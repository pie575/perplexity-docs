Las buenas prácticas comunes de prompting se encuentran en la [Guía de prompts de la Agent API](/es/docs/agent-api/prompt-guide) y se aplican a Sonar sin modificaciones: sé específico, limita el número de resultados, no pidas URL dentro del texto, evita el contenido few-shot y usa parámetros en lugar de texto para aplicar filtros.

Esta página aborda la única diferencia estructural que cambia la forma de escribir prompts para Sonar: el prompt del sistema no influye en la búsqueda.

<div id="shape-search-through-the-user-message">
  ## Moldea la búsqueda a través del mensaje del usuario
</div>

Sonar ejecuta una búsqueda web antes de generar su respuesta, y solo el mensaje del usuario sirve para orientar esa búsqueda. El prompt del sistema no es visible para la búsqueda: llega al modelo únicamente en el momento de responder, cuando ya se cuenta con los resultados. Usa el prompt del sistema para el tono, el estilo y las reglas de fundamentación, pero trata el mensaje del usuario como la pregunta para el modelo y, a la vez, como la semilla de la búsqueda.

La consecuencia práctica es que la forma de redactar el mensaje del usuario influye directamente en qué fuentes aparecen. Una pregunta específica y descriptiva da mejores resultados que una vaga, y ni el prompt del sistema más pulido puede salvar un mensaje de usuario impreciso. Si la calidad de la recuperación importa, invierte primero ahí.

**Buen ejemplo**: «¿Qué directrices ha publicado la FDA sobre la IA en dispositivos médicos durante el último año y qué categorías de dispositivos abarcan?»

**Mal ejemplo**: «Cuéntame sobre las normas de IA de la FDA».

<Warning>
  No incluyas instrucciones de búsqueda en el prompt del sistema. Frases como «busca solo en Wikipedia» o «consulta los resultados más recientes» no tienen ningún efecto. Para restricciones estrictas como dominio, actualidad o región, usa los [parámetros de filtro de búsqueda](/es/docs/sonar/filters) específicos en el cuerpo de la solicitud, en lugar de intentar expresar la restricción en prosa.
</Warning>

<CodeGroup>
  ```python Python theme={null}
  from perplexity import Perplexity

  client = Perplexity()

  completion = client.chat.completions.create(
      model="sonar",
      messages=[
          {"role": "user", "content": "Summarize the FDA's regulatory framework for Software as a Medical Device (SaMD), including the Pre-Cert program."}
      ],
      search_domain_filter=["fda.gov"],
      search_recency_filter="month"
  )

  print(completion.choices[0].message.content)
  ```

Esto contrasta con la Agent API, donde las `instructions` se vuelven a leer en cada turno del bucle del agente y determinan tanto las llamadas a herramientas como la respuesta final. En Sonar, `instructions` no tiene equivalente: los mensajes de sistema solo influyen en la generación, nunca en la recuperación.

<div id="reduce-hallucinations">
  ## Reducir las alucinaciones
</div>

Los LLM están ajustados para resultar útiles, lo que a veces los lleva a dar una respuesta cuando los resultados de búsqueda son escasos o poco pertinentes, en lugar de advertir esa carencia. El prompt del sistema no influye en la fase de búsqueda en sí, pero sí determina cómo el modelo utiliza los resultados al redactar la respuesta final, y por eso es el lugar idóneo para fijar reglas de fundamentación. Dos añadidos breves cubren la mayoría de estos casos límite.

**Dale permiso al modelo para decir que no encontró nada.** Con una salida explícita en el prompt del sistema, es más probable que el modelo reconozca que los resultados son insuficientes en vez de recurrir a los datos de entrenamiento para llenar ese vacío.

```text System Prompt theme={null}
Responde únicamente a partir de los resultados de búsqueda proporcionados. Si los resultados no contienen la respuesta, indícalo de forma explícita en lugar de adivinar.
```

**Exige que se declaren las coincidencias parciales.** A veces la búsqueda devuelve resultados relacionados pero que no coinciden (un año distinto, una empresa matriz en lugar de una filial, un producto similar). Pedirle al modelo que señale la discrepancia desde el principio evita que esos casos se presenten como respuestas directas.

```text System Prompt theme={null}
Si los resultados de búsqueda están relacionados pero no coinciden con la pregunta (un año distinto, una empresa matriz o un producto similar), indica la discrepancia de forma explícita antes de responder.
```

<div id="what-carries-over-from-the-agent-api-guide">
  ## Qué se mantiene de la guía de la Agent API
</div>

Se aplican las mismas reglas fundamentales de prompting, sin cambios:

* **Sé específico y descriptivo** en el mensaje del usuario. Las consultas vagas generan resultados dispersos.
* **Limita la cantidad de resultados.** Si necesitas una lista, indica su extensión.
* **No uses contenido few-shot.** Pegar una respuesta de ejemplo ya redactada puede hacer que el paso de búsqueda se quede anclado al tema del ejemplo. Hacer few-shot de la *estructura* está bien; para garantizar el formato, usa `response_format`.
* **No pidas URLs en el texto de la respuesta.** Sonar siempre devuelve las fuentes en los campos de nivel superior `citations` y `search_results`. Tómalas de ahí.
* **Usa parámetros, no prosa, para los filtros.** El backend de búsqueda lee los parámetros; no lee el prompt del sistema.
