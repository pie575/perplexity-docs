Esta guía te guía paso a paso en la creación de un pipeline completo de generación aumentada por recuperación (RAG) con la Embeddings API y la Agent API de Perplexity.

Abarca la fragmentación de documentos, la generación de embeddings con modelos estándar y contextualizados, la creación de un índice vectorial en memoria, la consulta del contexto relevante y la generación de respuestas fundamentadas.

<Info>
  Esta guía se centra en el pipeline de extremo a extremo. Para consultar los detalles de referencia de la API sobre cada tipo de embedding, consulta [Embeddings estándar](/es/docs/embeddings/standard-embeddings) y [Embeddings contextualizados](/es/docs/embeddings/contextualized-embeddings).
</Info>

<div id="pipeline-overview">
  ## Descripción general del pipeline
</div>

Un pipeline de RAG recupera información relevante de tus propios documentos antes de generar una respuesta, de modo que las respuestas del modelo se fundamenten en tus datos en lugar de depender únicamente del conocimiento paramétrico.

<img src="https://mintcdn.com/perplexity/mJe6zlFqiKQDJxBJ/docs/assets/images/cookbook/articles/embeddings-rag-diagram.svg?fit=max&auto=format&n=mJe6zlFqiKQDJxBJ&q=85&s=586467bbbce4759a125dd4b49827259c" alt="Diagrama del pipeline de RAG" width="1200" className="block dark:hidden" data-path="docs/assets/images/cookbook/articles/embeddings-rag-diagram.svg" />

<img src="https://mintcdn.com/perplexity/mJe6zlFqiKQDJxBJ/docs/assets/images/cookbook/articles/embeddings-rag-diagram-dark.svg?fit=max&auto=format&n=mJe6zlFqiKQDJxBJ&q=85&s=87b6b2f5f5e8e797edb54cfd98d2152c" alt="Diagrama del pipeline de RAG" width="1200" className="hidden dark:block" data-path="docs/assets/images/cookbook/articles/embeddings-rag-diagram-dark.svg" />

Los pasos son:

1. **Divide** tus documentos de origen en fragmentos manejables con solapamiento.
2. **Genera embeddings** de cada fragmento con un modelo de embeddings de Perplexity.
3. **Indexa** los embeddings para la búsqueda por similitud.
4. **Consulta** generando el embedding de la pregunta del usuario con el mismo modelo.
5. **Recupera** los k fragmentos más similares.
6. **Genera** una respuesta pasando el contexto recuperado a la Agent API.

<div id="document-chunking">
  ## Fragmentación de documentos
</div>

Divide tus documentos en fragmentos lo suficientemente pequeños para la ventana de contexto del modelo, sin perder la coherencia semántica. Los fragmentos con solapamiento garantizan que no se pierda la información situada en los límites entre fragmentos.

<CodeGroup>
  ```python Python theme={null}
  def chunk_text(text: str, chunk_size: int = 500, overlap: int = 100) -> list[str]:
      """Divide el texto en fragmentos solapados según el número de caracteres."""
      chunks = []
      start = 0
      while start < len(text):
          end = start + chunk_size
          chunk = text[start:end].strip()
          if chunk:
              chunks.append(chunk)
          start += chunk_size - overlap
      return chunks

  document = """Retrieval-augmented generation (RAG) is a technique that combines
  information retrieval with text generation. Rather than relying solely on a
  language model's training data, RAG systems first search a knowledge base for
  relevant documents, then use those documents as context when generating a
  response. This reduces hallucinations and allows the system to provide answers
  grounded in specific, up-to-date sources."""

  chunks = chunk_text(document, chunk_size=300, overlap=50)
  for i, chunk in enumerate(chunks):
      print(f"Chunk {i} ({len(chunk)} chars): {chunk[:60]}...")
  ```

  ```typescript TypeScript theme={null}
  function chunkText(text: string, chunkSize: number = 500, overlap: number = 100): string[] {
      const chunks: string[] = [];
      let start = 0;
      while (start < text.length) {
          const end = start + chunkSize;
          const chunk = text.slice(start, end).trim();
          if (chunk) chunks.push(chunk);
          start += chunkSize - overlap;
      }
      return chunks;
  }

  const document = `Retrieval-augmented generation (RAG) is a technique that combines
  information retrieval with text generation. Rather than relying solely on a
  language model's training data, RAG systems first search a knowledge base for
  relevant documents, then use those documents as context when generating a
  response. This reduces hallucinations and allows the system to provide answers
  grounded in specific, up-to-date sources.`;

  const chunks = chunkText(document, 300, 50);
  chunks.forEach((chunk, i) => {
      console.log(`Chunk ${i} (${chunk.length} chars): ${chunk.slice(0, 60)}...`);
  });
  ```
</CodeGroup>

<Tip>
  Un tamaño de fragmento de 300-500 caracteres con un solapamiento de 50-100 caracteres funciona bien en la mayoría de los casos de uso. En documentos estructurados (markdown, HTML), conviene dividir por encabezados o por límites de párrafo en lugar de por recuento de caracteres.
</Tip>

<div id="embedding-with-the-standard-model">
  ## Generación de embeddings con el modelo estándar
</div>

Los embeddings estándar procesan cada texto de forma independiente. Úsalos cuando los fragmentos sean autónomos y no dependan del contexto circundante.

<CodeGroup>
  ```python Python theme={null}
  import base64
  import numpy as np
  from perplexity import Perplexity

  client = Perplexity()

  def decode_embedding(b64_string: str) -> np.ndarray:
      """Decodifica un embedding int8 codificado en base64 a un array numpy de float32."""
      return np.frombuffer(base64.b64decode(b64_string), dtype=np.int8).astype(np.float32)

  chunks = [
      "RAG combines retrieval with generation to ground responses in real data.",
      "Document chunking splits text into overlapping segments for embedding.",
      "Cosine similarity measures the angle between two embedding vectors.",
  ]

  response = client.embeddings.create(input=chunks, model="pplx-embed-v1-4b")
  embeddings = [decode_embedding(emb.embedding) for emb in response.data]
  print(f"Embedded {len(embeddings)} chunks, each with {len(embeddings[0])} dimensions")
  ```

  ```typescript TypeScript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  function decodeEmbedding(b64String: string): Int8Array {
      const buffer = Buffer.from(b64String, 'base64');
      return new Int8Array(buffer.buffer, buffer.byteOffset, buffer.byteLength);
  }

  const chunks = [
      "RAG combines retrieval with generation to ground responses in real data.",
      "Document chunking splits text into overlapping segments for embedding.",
      "Cosine similarity measures the angle between two embedding vectors.",
  ];

  const response = await client.embeddings.create({
      input: chunks,
      model: "pplx-embed-v1-4b"
  });
  const embeddings = response.data.map(emb => decodeEmbedding(emb.embedding));
  console.log(`Embedded ${embeddings.length} chunks, each with ${embeddings[0].length} dimensions`);
  ```
</CodeGroup>

<div id="embedding-with-the-contextualized-model">
  ## Generación de embeddings con el modelo contextualizado
</div>

Los embeddings contextualizados reconocen que los fragmentos pertenecen a un mismo documento. El modelo aplica atención entre fragmentos, de modo que el embedding de cada fragmento incorpora información de los fragmentos vecinos. La diferencia clave en la API es la estructura de arreglos anidados: cada arreglo interno contiene los fragmentos de un solo documento.

<CodeGroup>
  ```python Python theme={null}
  from perplexity import Perplexity

  client = Perplexity()

  # Dos documentos de origen, cada uno dividido en fragmentos
  doc1_chunks = [
      "RAG combines retrieval with generation to produce grounded answers.",
      "The retrieval step searches a vector index for chunks similar to the query.",
      "The generation step uses retrieved context to produce a final response."
  ]
  doc2_chunks = [
      "Embedding models convert text into dense vector representations.",
      "Cosine similarity is the standard metric for comparing embeddings."
  ]

  # Se pasan como arreglos anidados (un arreglo interno por documento)
  response = client.contextualized_embeddings.create(
      input=[doc1_chunks, doc2_chunks],
      model="pplx-embed-context-v1-4b"
  )

  # Respuesta anidada: response.data[doc_idx].data[chunk_idx]
  for doc in response.data:
      for chunk in doc.data:
          print(f"Doc {doc.index}, Chunk {chunk.index}: {chunk.embedding[:20]}...")
  ```

  ```typescript TypeScript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  const doc1Chunks = [
      "RAG combines retrieval with generation to produce grounded answers.",
      "The retrieval step searches a vector index for chunks similar to the query.",
      "The generation step uses retrieved context to produce a final response."
  ];
  const doc2Chunks = [
      "Embedding models convert text into dense vector representations.",
      "Cosine similarity is the standard metric for comparing embeddings."
  ];

  // Se pasan como arreglos anidados (un arreglo interno por documento)
  const response = await client.contextualizedEmbeddings.create({
      input: [doc1Chunks, doc2Chunks],
      model: "pplx-embed-context-v1-4b"
  });

  // Respuesta anidada: response.data[docIdx].data[chunkIdx]
  for (const doc of response.data) {
      for (const chunk of doc.data) {
          console.log(`Doc ${doc.index}, Chunk ${chunk.index}: ${chunk.embedding.slice(0, 20)}...`);
      }
  }
  ```
</CodeGroup>

<Warning>
  **El orden de los fragmentos importa.** Los fragmentos de cada documento deben pasarse en su orden secuencial original. El modelo contextualizado se apoya en el contexto posicional para relacionar fragmentos vecinos, por lo que desordenarlos degradará la calidad de los embeddings.
</Warning>

<div id="querying-a-contextualized-index">
  ## Consultar un índice contextualizado
</div>

Al usar embeddings contextualizados, envuelve cada consulta en una lista interna de un solo elemento (por ejemplo, `[[query]]`) para que la API la trate como un documento de un único fragmento:

<CodeGroup>
  ```python Python theme={null}
  from perplexity import Perplexity
  import base64, numpy as np

  client = Perplexity()

  def decode_embedding(b64: str) -> np.ndarray:
      return np.frombuffer(base64.b64decode(b64), dtype=np.int8).astype(np.float32)

  def cosine_similarity(a: np.ndarray, b: np.ndarray) -> float:
      return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

  # Indexar con el modelo contextualizado (los fragmentos comparten atención entre sí)
  doc_chunks = [
      "RAG combines retrieval with generation to produce grounded answers.",
      "The retrieval step finds chunks similar to the user query.",
      "The generation step uses retrieved context to produce a final response.",
  ]
  ctx_response = client.contextualized_embeddings.create(
      input=[doc_chunks],  # arreglo anidado: una lista interna por documento
      model="pplx-embed-context-v1-4b"
  )
  index = [
      {"embedding": decode_embedding(chunk.embedding), "text": doc_chunks[chunk.index]}
      for chunk in ctx_response.data[0].data
  ]

  # Consultar el índice
  query = "How does retrieval work in RAG?"
  q_response = client.contextualized_embeddings.create(
      input=[[query]], model="pplx-embed-context-v1-4b"
  )
  q_emb = decode_embedding(q_response.data[0].data[0].embedding)
  results = sorted(index, key=lambda x: cosine_similarity(q_emb, x["embedding"]), reverse=True)
  print(f"Top result: {results[0]['text']}")
  ```

  ```typescript TypeScript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  function decodeEmbedding(b64: string): Int8Array {
      const buffer = Buffer.from(b64, 'base64');
      return new Int8Array(buffer.buffer, buffer.byteOffset, buffer.byteLength);
  }

  function cosineSimilarity(a: Int8Array, b: Int8Array): number {
      let dot = 0, normA = 0, normB = 0;
      for (let i = 0; i < a.length; i++) {
          dot += a[i] * b[i]; normA += a[i] ** 2; normB += b[i] ** 2;
      }
      return dot / (Math.sqrt(normA) * Math.sqrt(normB));
  }

  // Indexar con el modelo contextualizado
  const docChunks = [
      "RAG combines retrieval with generation to produce grounded answers.",
      "The retrieval step finds chunks similar to the user query.",
      "The generation step uses retrieved context to produce a final response.",
  ];
  const ctxResponse = await client.contextualizedEmbeddings.create({
      input: [docChunks],  // arreglo anidado: un arreglo interno por documento
      model: "pplx-embed-context-v1-4b"
  });
  const index = ctxResponse.data[0].data.map(chunk => ({
      embedding: decodeEmbedding(chunk.embedding),
      text: docChunks[chunk.index],
  }));

  // Consultar el índice
  const query = "How does retrieval work in RAG?";
  const qResponse = await client.contextualizedEmbeddings.create({
      input: [[query]], model: "pplx-embed-context-v1-4b"
  });
  const qEmb = decodeEmbedding(qResponse.data[0].data[0].embedding);
  const results = [...index].sort((a, b) => cosineSimilarity(qEmb, b.embedding) - cosineSimilarity(qEmb, a.embedding));
  console.log(`Top result: ${results[0].text}`);
  ```
</CodeGroup>

<div id="building-a-vector-index">
  ## Construcción de un índice vectorial
</div>

Este ejemplo usa numpy para calcular la similitud coseno con un índice sencillo en memoria. Para sistemas en producción con millones de vectores, utilice una base de datos vectorial dedicada (Pinecone, Weaviate, Qdrant, etc.).

<CodeGroup>
  ```python Python theme={null}
  import base64
  import numpy as np
  from perplexity import Perplexity

  client = Perplexity()

  def decode_embedding(b64_string: str) -> np.ndarray:
      return np.frombuffer(base64.b64decode(b64_string), dtype=np.int8).astype(np.float32)

  def cosine_similarity(a: np.ndarray, b: np.ndarray) -> float:
      return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

  # Documentos a indexar
  documents = {
      "RAG Overview": [
          "Retrieval-augmented generation grounds LLM responses in external data.",
          "RAG reduces hallucinations by providing factual context to the model.",
          "A typical RAG pipeline has three stages: indexing, retrieval, and generation."
      ],
      "Embedding Models": [
          "Embedding models map text to dense vector representations.",
          "Similar texts produce vectors that are close in the embedding space.",
          "Perplexity offers both standard and contextualized embedding models."
      ]
  }

  # Construir el índice: lista de tuplas (embedding, texto, título del documento)
  index = []
  for title, chunks in documents.items():
      response = client.embeddings.create(input=chunks, model="pplx-embed-v1-4b")
      for emb_obj in response.data:
          index.append({
              "embedding": decode_embedding(emb_obj.embedding),
              "text": chunks[emb_obj.index],
              "doc_title": title
          })

  print(f"Indexed {len(index)} chunks")
  ```

  ```typescript TypeScript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  function decodeEmbedding(b64String: string): Int8Array {
      const buffer = Buffer.from(b64String, 'base64');
      return new Int8Array(buffer.buffer, buffer.byteOffset, buffer.byteLength);
  }

  function cosineSimilarity(a: Int8Array, b: Int8Array): number {
      let dot = 0, normA = 0, normB = 0;
      for (let i = 0; i < a.length; i++) {
          dot += a[i] * b[i];
          normA += a[i] * a[i];
          normB += b[i] * b[i];
      }
      return dot / (Math.sqrt(normA) * Math.sqrt(normB));
  }

  const documents: Record<string, string[]> = {
      "RAG Overview": [
          "Retrieval-augmented generation grounds LLM responses in external data.",
          "RAG reduces hallucinations by providing factual context to the model.",
          "A typical RAG pipeline has three stages: indexing, retrieval, and generation."
      ],
      "Embedding Models": [
          "Embedding models map text to dense vector representations.",
          "Similar texts produce vectors that are close in the embedding space.",
          "Perplexity offers both standard and contextualized embedding models."
      ]
  };

  // Construir el índice
  const index: { embedding: Int8Array; text: string; docTitle: string }[] = [];
  for (const [title, chunks] of Object.entries(documents)) {
      const response = await client.embeddings.create({
          input: chunks,
          model: "pplx-embed-v1-4b"
      });
      for (const embObj of response.data) {
          index.push({
              embedding: decodeEmbedding(embObj.embedding),
              text: chunks[embObj.index],
              docTitle: title
          });
      }
  }

  console.log(`Indexed ${index.length} chunks`);
  ```
</CodeGroup>

<div id="query-pipeline">
  ## Pipeline de consultas
</div>

El pipeline de consultas completo genera embeddings de la pregunta del usuario, recupera los k fragmentos más similares y los pasa como contexto a la Agent API para generar la respuesta.

<CodeGroup>
  ```python Python theme={null}
  def rag_query(question: str, index: list[dict], top_k: int = 3, min_score: float = 0.3) -> str:
      """Generar embeddings de la pregunta -> recuperar fragmentos similares -> generar respuesta."""
      # Paso 1: Generar embeddings de la pregunta
      query_response = client.embeddings.create(input=[question], model="pplx-embed-v1-4b")
      query_emb = decode_embedding(query_response.data[0].embedding)

      # Paso 2: Recuperar los k fragmentos principales que superen el umbral mínimo de similitud
      scored = sorted(
          [{"score": cosine_similarity(query_emb, item["embedding"]), **item} for item in index],
          key=lambda x: x["score"], reverse=True
      )[:top_k]
      scored = [item for item in scored if item["score"] >= min_score]

      if not scored:
          return "No relevant context found for this question."

      # Incluir la atribución de la fuente junto a cada fragmento
      context = "\n\n".join(
          f"[Source: {item['doc_title']}]\n{item['text']}" for item in scored
      )

      # Paso 3: Generar la respuesta mediante la Agent API
      response = client.responses.create(
          model="openai/gpt-5.4",
          input=question,
          instructions=(
              "Answer based only on the provided context. "
              "Cite sources by name when referencing specific information. "
              "If the context does not contain enough information, say so.\n\n"
              f"Context:\n{context}"
          )
      )
      return response.output_text

  answer = rag_query("What are the stages of a RAG pipeline?", index)
  print(answer)
  ```

  ```typescript TypeScript theme={null}
  async function ragQuery(question: string, idx: typeof index, topK: number = 3, minScore: number = 0.3): Promise<string> {
      // Paso 1: Generar embeddings de la pregunta
      const qResponse = await client.embeddings.create({
          input: [question], model: "pplx-embed-v1-4b"
      });
      const qEmb = decodeEmbedding(qResponse.data[0].embedding);

      // Paso 2: Recuperar los k fragmentos principales que superen el umbral mínimo de similitud
      const scored = idx
          .map(item => ({ ...item, score: cosineSimilarity(qEmb, item.embedding) }))
          .sort((a, b) => b.score - a.score)
          .slice(0, topK)
          .filter(item => item.score >= minScore);

      if (scored.length === 0) {
          return "No relevant context found for this question.";
      }

      // Incluir la atribución de la fuente junto a cada fragmento
      const context = scored
          .map(item => `[Source: ${item.docTitle}]\n${item.text}`)
          .join("\n\n");

      // Paso 3: Generar la respuesta mediante la Agent API
      const response = await client.responses.create({
          model: "openai/gpt-5.4",
          input: question,
          instructions: `Answer based only on the provided context. Cite sources by name when referencing specific information. If the context does not contain enough information, say so.\n\nContext:\n${context}`
      });
      return response.output_text;
  }

  const answer = await ragQuery("What are the stages of a RAG pipeline?", index);
  console.log(answer);
  ```
</CodeGroup>

<Tip>
  Empieza con `top_k=3` y `min_score=0.3` en la mayoría de los casos de uso. Sube `top_k` a 5–7 para preguntas amplias o fragmentos cortos. Sube `min_score` a 0.5–0.7 si los fragmentos recuperados contienen información irrelevante. Bájalo hasta cerca de 0.2 para consultas diversas o ambiguas.
</Tip>

<div id="standard-vs-contextualized-comparison">
  ## Comparación entre estándar y contextualizado
</div>

| Aspecto                     | Estándar (`pplx-embed-v1-4b`)                                              | Contextualizado (`pplx-embed-context-v1-4b`)                        |
| --------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| **Formato de entrada**      | Lista plana de textos                                                      | Arreglos anidados agrupados por documento                           |
| **Percepción del contexto** | Cada texto se embede de forma independiente                                | Los fragmentos comparten contexto entre sí dentro de cada documento |
| **Ideal para**              | Entradas de preguntas frecuentes, textos independientes, documentos cortos | Párrafos de documentos, secciones de artículos                      |
| **Orden de los fragmentos** | El orden no importa                                                        | Debe respetar el orden original del documento                       |
| **Embedding de consultas**  | `client.embeddings.create(input=[query])`                                  | `client.contextualized_embeddings.create(input=[[query]])`          |
| **Precio (modelo 4b)**      | $0.03 / 1M tokens                                                          | $0.05 / 1M tokens                                                   |

<div id="when-to-use-standard-embeddings">
  ### Cuándo usar embeddings estándar
</div>

* Los fragmentos son autónomos y no dependen del contexto circundante.
* Tu contenido consiste en pares de preguntas frecuentes, descripciones de productos o entradas breves e independientes.
* Necesitas el menor costo por token.

<div id="when-to-use-contextualized-embeddings">
  ### Cuándo usar embeddings contextualizados
</div>

* Los fragmentos provienen de documentos extensos en los que el significado depende del texto circundante.
* Un fragmento como «Este enfoque mejora el rendimiento un 20 %» solo cobra sentido con el contexto que lo rodea.
* Estás generando embeddings de párrafos de artículos, informes o documentación técnica.
* Buscas mayor precisión en la recuperación a cambio de un incremento moderado del costo.

<div id="matryoshka-dimensions">
  ## Dimensiones Matryoshka
</div>

Los modelos de embeddings de Perplexity admiten Matryoshka Representation Learning (MRL), que concentra la información más importante en las primeras N dimensiones. Puedes solicitar dimensiones reducidas directamente a través de la API para obtener búsquedas más rápidas y ocupar menos almacenamiento.

<CodeGroup>
  ```python Python theme={null}
  import base64
  import numpy as np
  from perplexity import Perplexity

  client = Perplexity()

  texts = ["Matryoshka embeddings allow dimension reduction without re-embedding."]

  def decode_embedding(b64: str) -> np.ndarray:
      return np.frombuffer(base64.b64decode(b64), dtype=np.int8)

  # Dimensiones completas (2560 para el modelo 4b)
  full = client.embeddings.create(input=texts, model="pplx-embed-v1-4b")

  # Reducidas a 512 dimensiones a través de la API
  reduced = client.embeddings.create(input=texts, model="pplx-embed-v1-4b", dimensions=512)

  print(f"Full: {len(decode_embedding(full.data[0].embedding))} dimensions")
  print(f"Reduced: {len(decode_embedding(reduced.data[0].embedding))} dimensions")
  ```

  ```typescript TypeScript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  const texts = ["Matryoshka embeddings allow dimension reduction without re-embedding."];

  function decodeEmbedding(b64: string): Int8Array {
      const buffer = Buffer.from(b64, 'base64');
      return new Int8Array(buffer.buffer, buffer.byteOffset, buffer.byteLength);
  }

  // Dimensiones completas (2560 para el modelo 4b)
  const full = await client.embeddings.create({ input: texts, model: "pplx-embed-v1-4b" });

  // Reducidas a 512 dimensiones a través de la API
  const reduced = await client.embeddings.create({
      input: texts, model: "pplx-embed-v1-4b", dimensions: 512
  });

  console.log(`Full: ${decodeEmbedding(full.data[0].embedding).length} dimensions`);
  console.log(`Reduced: ${decodeEmbedding(reduced.data[0].embedding).length} dimensions`);
  ```
</CodeGroup>

Contrapartidas de la reducción de dimensiones para el modelo `pplx-embed-v1-4b`:

|   Dimensiones   | Almacenamiento por vector | Calidad relativa | Caso de uso                                     |
| :-------------: | :-----------------------: | :--------------: | ----------------------------------------------- |
| 2560 (completa) |           2,5 KB          |    La más alta   | Máxima precisión, conjuntos de datos pequeños   |
|       1024      |            1 KB           |     Muy alta     | Buen equilibrio para la mayoría de aplicaciones |
|       512       |           512 B           |       Alta       | Recuperación a gran escala, búsqueda rápida     |
|       256       |           256 B           |     Moderada     | Conjuntos de datos enormes, filtrado grueso     |
|       128       |           128 B           |     Más baja     | Filtrado inicial de candidatos                  |

<Tip>
  Usa el parámetro `dimensions` en la llamada a la API en lugar de truncar los vectores manualmente. La API aplica la normalización adecuada para el número de dimensiones solicitado. Empieza con las dimensiones completas y redúcelas solo cuando el almacenamiento o la latencia se conviertan en un cuello de botella.
</Tip>

<div id="batch-processing">
  ## Procesamiento por lotes
</div>

Al generar embeddings de colecciones grandes de documentos, procésalas por lotes para no superar los límites de tasa de la API. La API estándar acepta hasta 512 textos por solicitud, con un límite combinado de 120.000 tokens.

<CodeGroup>
  ```python Python theme={null}
  import asyncio
  import base64
  import numpy as np
  from perplexity import AsyncPerplexity

  def decode_embedding(b64_string: str) -> np.ndarray:
      return np.frombuffer(base64.b64decode(b64_string), dtype=np.int8).astype(np.float32)

  async def batch_embed(texts: list[str], batch_size: int = 100) -> list[np.ndarray]:
      """Genera embeddings de textos por lotes con control de tasa."""
      async with AsyncPerplexity() as client:
          all_embeddings = []
          for i in range(0, len(texts), batch_size):
              batch = texts[i:i + batch_size]
              response = await client.embeddings.create(
                  input=batch, model="pplx-embed-v1-4b"
              )
              all_embeddings.extend(decode_embedding(e.embedding) for e in response.data)
              print(f"Embedded {min(i + batch_size, len(texts))}/{len(texts)}")
              if i + batch_size < len(texts):
                  await asyncio.sleep(0.1)  # Breve pausa entre lotes
          return all_embeddings

  # Uso
  texts = [f"Document chunk number {i} with content." for i in range(500)]
  embeddings = asyncio.run(batch_embed(texts, batch_size=100))
  print(f"Total: {len(embeddings)} embeddings")
  ```

  ```typescript TypeScript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  function decodeEmbedding(b64String: string): Int8Array {
      const buffer = Buffer.from(b64String, 'base64');
      return new Int8Array(buffer.buffer, buffer.byteOffset, buffer.byteLength);
  }

  async function batchEmbed(texts: string[], batchSize: number = 100): Promise<Int8Array[]> {
      const allEmbeddings: Int8Array[] = [];
      for (let i = 0; i < texts.length; i += batchSize) {
          const batch = texts.slice(i, i + batchSize);
          const response = await client.embeddings.create({
              input: batch, model: "pplx-embed-v1-4b"
          });
          allEmbeddings.push(...response.data.map(e => decodeEmbedding(e.embedding)));
          console.log(`Embedded ${Math.min(i + batchSize, texts.length)}/${texts.length}`);
          if (i + batchSize < texts.length) {
              await new Promise(r => setTimeout(r, 100)); // Breve pausa entre lotes
          }
      }
      return allEmbeddings;
  }

  // Uso
  const texts = Array.from({ length: 500 }, (_, i) => `Document chunk number ${i} with content.`);
  const embeddings = await batchEmbed(texts, 100);
  console.log(`Total: ${embeddings.length} embeddings`);
  ```
</CodeGroup>

<Info>
  Para los embeddings contextualizados, arma los lotes a nivel de documento usando `client.contextualized_embeddings.create(input=batch_of_doc_arrays)` con el mismo patrón. La API contextualizada acepta hasta 512 documentos con 16.000 fragmentos en total por solicitud.
</Info>

<Warning>
  **Límites de tasa:** mantén los tamaños de lote holgadamente por debajo de los límites de la API (512 textos / 120.000 tokens en la estándar; 512 documentos / 16.000 fragmentos en la contextualizada) y añade pequeñas pausas entre solicitudes para evitar el throttling.
</Warning>

<div id="complete-example">
  ## Ejemplo completo
</div>

Un pipeline autónomo que indexa dos documentos con embeddings contextualizados y responde preguntas sobre el contenido indexado.

<CodeGroup>
  ```python Python theme={null}
  import base64
  import numpy as np
  from perplexity import Perplexity

  client = Perplexity()

  # --- Funciones auxiliares ---

  def chunk_text(text: str, chunk_size: int = 400, overlap: int = 80) -> list[str]:
      chunks, start = [], 0
      while start < len(text):
          chunk = text[start:start + chunk_size].strip()
          if chunk:
              chunks.append(chunk)
          start += chunk_size - overlap
      return chunks

  def decode_embedding(b64: str) -> np.ndarray:
      return np.frombuffer(base64.b64decode(b64), dtype=np.int8).astype(np.float32)

  def cosine_similarity(a: np.ndarray, b: np.ndarray) -> float:
      return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

  # --- Documentos de origen ---

  DOCUMENTS = {
      "Quantum Computing": (
          "Quantum computers use qubits that can exist in superposition, representing "
          "0 and 1 simultaneously. Unlike classical bits, qubits leverage quantum "
          "interference to perform calculations. Quantum entanglement allows qubits to "
          "be correlated, enabling parallel processing at scale. Current quantum computers "
          "from IBM, Google, and others have dozens to hundreds of physical qubits."
      ),
      "Machine Learning": (
          "Machine learning enables computers to learn from data without explicit "
          "programming. Supervised learning uses labeled examples to train models for "
          "classification and regression. Neural networks with many layers (deep learning) "
          "excel at image recognition and language tasks. Training requires large datasets "
          "and significant compute, often using GPUs or TPUs."
      ),
  }

  # --- Paso 1: Indexar con el modelo ---

  def build_index(documents: dict[str, str]) -> list[dict]:
      index = []
      for title, text in documents.items():
          chunks = chunk_text(text)
          response = client.contextualized_embeddings.create(
              input=[chunks],
              model="pplx-embed-context-v1-4b"
          )
          for chunk_obj in response.data[0].data:
              index.append({
                  "embedding": decode_embedding(chunk_obj.embedding),
                  "text": chunks[chunk_obj.index],
                  "doc_title": title,
              })
      print(f"Indexed {len(index)} chunks from {len(documents)} documents")
      return index

  # --- Paso 2: Consultar el índice, recuperar y generar ---

  def rag_query(question: str, index: list[dict], top_k: int = 3, min_score: float = 0.3) -> str:
      q_resp = client.contextualized_embeddings.create(
          input=[[question]], model="pplx-embed-context-v1-4b"
      )
      q_emb = decode_embedding(q_resp.data[0].data[0].embedding)

      results = sorted(
          [{"score": cosine_similarity(q_emb, item["embedding"]), **item} for item in index],
          key=lambda x: x["score"], reverse=True
      )[:top_k]
      results = [r for r in results if r["score"] >= min_score]

      if not results:
          return "No relevant context found for this question."

      context = "\n\n".join(f"[{r['doc_title']}]\n{r['text']}" for r in results)

      response = client.responses.create(
          model="openai/gpt-5.4",
          input=question,
          instructions=(
              "Answer based only on the provided context. "
              "Cite the source name in brackets when referencing information. "
              "If the context is insufficient, say so.\n\n"
              f"Context:\n{context}"
          )
      )
      return response.output_text

  # --- Ejecución ---

  if __name__ == "__main__":
      index = build_index(DOCUMENTS)

      questions = [
          "What makes qubits different from classical bits?",
          "What hardware is used to train machine learning models?",
      ]
      for q in questions:
          print(f"\nQ: {q}")
          print(f"A: {rag_query(q, index)}")
  ```

  ```typescript TypeScript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  // --- Funciones auxiliares ---

  function chunkText(text: string, chunkSize = 400, overlap = 80): string[] {
      const chunks: string[] = [];
      let start = 0;
      while (start < text.length) {
          const chunk = text.slice(start, start + chunkSize).trim();
          if (chunk) chunks.push(chunk);
          start += chunkSize - overlap;
      }
      return chunks;
  }

  function decodeEmbedding(b64: string): Int8Array {
      const buffer = Buffer.from(b64, 'base64');
      return new Int8Array(buffer.buffer, buffer.byteOffset, buffer.byteLength);
  }

  function cosineSimilarity(a: Int8Array, b: Int8Array): number {
      let dot = 0, normA = 0, normB = 0;
      for (let i = 0; i < a.length; i++) {
          dot += a[i] * b[i]; normA += a[i] ** 2; normB += b[i] ** 2;
      }
      return dot / (Math.sqrt(normA) * Math.sqrt(normB));
  }

  // --- Documentos de origen ---

  const DOCUMENTS: Record<string, string> = {
      "Quantum Computing": "Quantum computers use qubits that can exist in superposition, representing 0 and 1 simultaneously. Unlike classical bits, qubits leverage quantum interference to perform calculations. Quantum entanglement allows qubits to be correlated, enabling parallel processing at scale. Current quantum computers from IBM, Google, and others have dozens to hundreds of physical qubits.",
      "Machine Learning": "Machine learning enables computers to learn from data without explicit programming. Supervised learning uses labeled examples to train models for classification and regression. Neural networks with many layers (deep learning) excel at image recognition and language tasks. Training requires large datasets and significant compute, often using GPUs or TPUs.",
  };

  type IndexEntry = { embedding: Int8Array; text: string; docTitle: string };

  // --- Paso 1: indexar con el modelo ---

  async function buildIndex(documents: Record<string, string>): Promise<IndexEntry[]> {
      const index: IndexEntry[] = [];
      for (const [title, text] of Object.entries(documents)) {
          const chunks = chunkText(text);
          const response = await client.contextualizedEmbeddings.create({
              input: [chunks],
              model: "pplx-embed-context-v1-4b"
          });
          for (const chunkObj of response.data[0].data) {
              index.push({
                  embedding: decodeEmbedding(chunkObj.embedding),
                  text: chunks[chunkObj.index],
                  docTitle: title,
              });
          }
      }
      console.log(`Indexed ${index.length} chunks from ${Object.keys(documents).length} documents`);
      return index;
  }

  // --- Paso 2: consultar el índice, recuperar y generar ---

  async function ragQuery(
      question: string,
      index: IndexEntry[],
      topK = 3,
      minScore = 0.3
  ): Promise<string> {
      const qResp = await client.contextualizedEmbeddings.create({
          input: [[question]], model: "pplx-embed-context-v1-4b"
      });
      const qEmb = decodeEmbedding(qResp.data[0].data[0].embedding);

      const results = index
          .map(item => ({ ...item, score: cosineSimilarity(qEmb, item.embedding) }))
          .sort((a, b) => b.score - a.score)
          .slice(0, topK)
          .filter(r => r.score >= minScore);

      if (results.length === 0) return "No relevant context found for this question.";

      const context = results.map(r => `[${r.docTitle}]\n${r.text}`).join("\n\n");

      const response = await client.responses.create({
          model: "openai/gpt-5.4",
          input: question,
          instructions: `Answer based only on the provided context. Cite the source name in brackets when referencing information. If the context is insufficient, say so.\n\nContext:\n${context}`,
      });
      return response.output_text;
  }

  // --- Ejecutar ---

  const index = await buildIndex(DOCUMENTS);

  const questions = [
      "What makes qubits different from classical bits?",
      "What hardware is used to train machine learning models?",
  ];
  for (const q of questions) {
      console.log(`\nQ: ${q}`);
      console.log(`A: ${await ragQuery(q, index)}`);
  }
  ```
