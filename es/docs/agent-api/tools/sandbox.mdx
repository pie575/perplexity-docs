<div id="overview">
  ## Descripción general
</div>

La herramienta `sandbox` permite que el modelo ejecute código durante una solicitud a la Agent API. El agente puede ejecutar código en un contenedor aislado, inspeccionar la salida y usar el resultado en su respuesta final.

Tú no proporcionas el código: habilitas la herramienta y el modelo escribe y ejecuta el código por sí mismo a partir de tu prompt y tus instrucciones; luego lee su propio `stdout`/`stderr` y lo utiliza en la respuesta. El código exacto que ejecutó el modelo se te devuelve en la respuesta (consulta [Estructura de la respuesta](#response-shape)), de modo que puedes verificar qué se ejecutó.

Habilita la herramienta agregándola al arreglo `tools`. El modelo decide cuándo invocarla según tu prompt y tus instrucciones.

<CodeGroup>
  ```python Python theme={null}
  from perplexity import Perplexity

  client = Perplexity()


  def get_output_text(response) -> str:
      return "".join(
          content.text
          for item in response.output or []
          if getattr(item, "type", None) == "message"
          for content in getattr(item, "content", None) or []
          if getattr(content, "type", None) == "output_text"
      )


  response = client.responses.create(
      model="openai/gpt-5.6-sol",
      input="For 230+ qualifying high-severity CVEs (CVE-YYYY-NNNNN published 2023–2025, CVSS ≥ 7.0), find the canonical vendor security advisory URL per CVE and name the affected product and the advisory's stated fix version.",
      tools=[{"type": "sandbox"}, {"type": "web_search"}],
      instructions="Use the sandbox and web search to gather and verify the advisories before answering.",
  )

  print(get_output_text(response))
  ```

  ```typescript Typescript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  const response = await client.responses.create({
    model: 'openai/gpt-5.6-sol',
    input: "For 230+ qualifying high-severity CVEs (CVE-YYYY-NNNNN published 2023–2025, CVSS ≥ 7.0), find the canonical vendor security advisory URL per CVE and name the affected product and the advisory's stated fix version.",
    tools: [{ type: 'sandbox' as const }, { type: 'web_search' as const }],
    instructions: 'Use the sandbox and web search to gather and verify the advisories before answering.',
  });

  console.log(response.output_text);
  ```

  ```bash cURL theme={null}
  curl https://api.perplexity.ai/v1/agent \
    -H "Authorization: Bearer $PERPLEXITY_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "model": "openai/gpt-5.6-sol",
      "input": "For 230+ qualifying high-severity CVEs (CVE-YYYY-NNNNN published 2023–2025, CVSS ≥ 7.0), find the canonical vendor security advisory URL per CVE and name the affected product and the advisory'\''s stated fix version.",
      "tools": [
        {
          "type": "sandbox"
        },
        {
          "type": "web_search"
        }
      ],
      "instructions": "Use the sandbox and web search to gather and verify the advisories before answering."
    }' | jq
  ```
</CodeGroup>

<div id="use-cases">
  ## Casos de uso
</div>

* Búsqueda web
* Cálculos numéricos y análisis estadístico
* Limpieza, parseo y transformación de datos
* Ejecución de código para verificar la lógica o reproducir un error
* Generación de artefactos estructurados, como CSV, JSON o informes
* Flujos de trabajo de varios pasos que requieren archivos intermedios o estado calculado

<div id="how-the-container-works">
  ## Cómo funciona el contenedor
</div>

El sandbox es un contenedor Linux aislado. Saber qué puede y qué no puede hacer te ayuda a anticipar cuándo el modelo recurrirá a él y qué esperar de vuelta.

| Propiedad                          | Comportamiento                                                                                                                                                                                                                                                                                                  |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Lenguajes**                      | El modelo ejecuta **Python** para los cálculos y **bash** para los comandos de shell. Cada ejecución indica su `language` en la respuesta.                                                                                                                                                                       |
| **Acceso a internet**              | El contenedor tiene acceso a la red, por lo que el código del modelo puede instalar los paquetes que necesite en tiempo de ejecución y comunicarse con endpoints externos.                                                                                                                                       |
| **Estado dentro de una respuesta** | Varias ejecuciones dentro de una misma respuesta comparten el mismo contenedor: los archivos escritos y los paquetes instalados en un paso anterior siguen ahí para un paso posterior. Esto es lo que hace posible los flujos de trabajo de varios pasos y los archivos intermedios.                            |
| **Captura de salida**              | `stdout` y `stderr` se capturan en cada ejecución. Las salidas muy grandes se truncan (del orden de ~1 MiB por flujo), así que conviene que el modelo escriba los resultados grandes en un archivo y lo devuelva (consulta [Recuperar archivos generados](#retrieving-generated-files)) en lugar de imprimirlos. |
| **Límite de tiempo de ejecución**  | Cada ejecución tiene un tope de tiempo de ejecución. Si se supera, el `status` de esa ejecución es `timed_out` (consulta [Manejo de errores](#error-handling)). Para trabajos largos, usa el [modo en segundo plano](#running-in-the-background).                                                              |

<div id="calling-other-tools-from-inside-the-sandbox">
  ### Llamar a otras herramientas desde dentro del sandbox
</div>

El contenedor incluye el SDK de Perplexity preinstalado, por lo que el código que el modelo ejecuta dentro del sandbox puede llamar directamente a [Web Search](/es/docs/agent-api/tools/web-search), [Fetch URL Content](/es/docs/agent-api/tools/fetch-url-content) y [People Search](/es/docs/agent-api/tools/people-search) —sin que tengas que añadir esas herramientas a la solicitud— y luego operar con lo que devuelvan. Cada una de estas llamadas se factura a su tarifa estándar por invocación (consulta [Precios](#pricing)).

<div id="github-connector">
  ### Conector de GitHub
</div>

El [conector de GitHub](/es/docs/agent-api/tools/connectors#use-connectors-in-the-sandbox) permite que el modelo use tus credenciales de GitHub conectadas en los comandos del sandbox.
Habilita tanto `sandbox` como el conector de GitHub en la solicitud.
De esta forma, el modelo puede usar `git` y `gh` para clonar repositorios privados, modificar código, confirmar cambios y crear o actualizar pull requests.
Solo puede acceder a los repositorios y realizar las acciones que permita tu cuenta de GitHub conectada.

Para conocer la estructura de la solicitud y ver un ejemplo con GitHub, consulta [Conectores](/es/docs/agent-api/tools/connectors).

<div id="running-in-the-background">
  ## Ejecución en segundo plano
</div>

Para llamadas al sandbox de larga duración, envía la solicitud con `background: true` y sondea la respuesta por ID hasta que se complete.

<CodeGroup>
  ```python Python theme={null}
  import time
  from perplexity import Perplexity

  client = Perplexity()


  def get_output_text(response) -> str:
      return "".join(
          content.text
          for item in response.output or []
          if getattr(item, "type", None) == "message"
          for content in getattr(item, "content", None) or []
          if getattr(content, "type", None) == "output_text"
      )


  response = client.responses.create(
      model="openai/gpt-5.6-sol",
      input="Create a CSV with the first 10 Fibonacci numbers and their squares.",
      tools=[{"type": "sandbox"}],
      background=True,
  )

  while response.status in ("queued", "in_progress"):
      time.sleep(2)
      response = client.responses.retrieve(response.id)

  print(get_output_text(response))
  ```

  ```typescript Typescript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  let response = await client.responses.create({
    model: 'openai/gpt-5.6-sol',
    input: 'Create a CSV with the first 10 Fibonacci numbers and their squares.',
    tools: [{ type: 'sandbox' as const }],
    background: true,
  });

  while (response.status === 'queued' || response.status === 'in_progress') {
    await new Promise((r) => setTimeout(r, 2000));
    response = await client.responses.retrieve(response.id);
  }

  console.log(response.output_text);
  ```

  ```bash cURL theme={null}
  # 1. Enviar con background: true
  curl https://api.perplexity.ai/v1/agent \
    -H "Authorization: Bearer $PERPLEXITY_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "model": "openai/gpt-5.6-sol",
      "input": "Create a CSV with the first 10 Fibonacci numbers and their squares.",
      "tools": [{ "type": "sandbox" }],
      "background": true
    }'

  # 2. Sondear la respuesta por ID hasta que el estado sea completed, failed, cancelled o incomplete
  curl https://api.perplexity.ai/v1/agent/$RESPONSE_ID \
    -H "Authorization: Bearer $PERPLEXITY_API_KEY"
  ```
</CodeGroup>

<div id="error-handling">
  ## Manejo de errores
</div>

Los errores del sandbox se devuelven a través de la respuesta habitual de la Agent API.

| Caso                         | Qué se observa                                                                                                                                                                                                                                  |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Tiempo de espera agotado** | El `status` de la entrada afectada en `results[]` (y del elemento `sandbox_results` que la contiene) es `timed_out`. Si la solicitud no puede completarse, el estado de la respuesta de nivel superior es `failed` e incluye un objeto `error`. |
| **Error de ejecución**       | La entrada correspondiente en `results[]` incluye un `exit_code` distinto de cero y la salida de error en `stderr`. La respuesta de la Agent API puede completarse igualmente si el contenedor se ejecutó correctamente.                        |
| **Cuota o límite**           | La respuesta falla y devuelve un objeto `error` que describe el límite. Los límites de tasa de la Agent API siguen vigentes.                                                                                                                    |

<div id="limits-and-quotas">
  ## Límites y cuotas
</div>

sandbox se ejecuta dentro de las solicitudes a la Agent API y está sujeto a los límites de tasa de la Agent API. Consulta [Límites de tasa y niveles de uso](/es/docs/admin/rate-limits-usage-tiers#agent-api-rate-limits) para conocer los límites de solicitudes según el nivel.

<div id="response-shape">
  ## Estructura de la respuesta
</div>

Cuando el modelo llama a la herramienta sandbox, la respuesta de la Agent API incluye un elemento `sandbox_results` en su array `output`, junto con los elementos `message` que haya. Una misma respuesta puede contener varios elementos `sandbox_results` si el modelo realiza más de una llamada al sandbox.

Cada elemento `sandbox_results` describe una invocación del sandbox y anida la salida de cada ejecución dentro de un array `results`.

| Campo          | Tipo     | Descripción                                                                               |
| -------------- | -------- | ----------------------------------------------------------------------------------------- |
| `type`         | `string` | Siempre `sandbox_results`.                                                                |
| `call_id`      | `string` | Identificador de esta llamada a la herramienta sandbox.                                   |
| `container_id` | `string` | Identificador del contenedor aislado que ejecutó el código.                               |
| `language`     | `string` | Lenguaje en el que el sandbox ejecutó el código (por ejemplo, `python`).                  |
| `code`         | `string` | El código que se ejecutó dentro del sandbox.                                              |
| `status`       | `string` | Estado general de la llamada al sandbox. Uno de `completed`, `timed_out`, `failed`.       |
| `results`      | `array`  | Una entrada por cada ejecución dentro del contenedor. Consulta los campos a continuación. |

Cada entrada de `results` tiene los siguientes campos:

| Campo         | Tipo      | Descripción                                                                                     |
| ------------- | --------- | ----------------------------------------------------------------------------------------------- |
| `stdout`      | `string`  | Salida estándar capturada de la ejecución.                                                      |
| `stderr`      | `string`  | Error estándar capturado de la ejecución.                                                       |
| `exit_code`   | `integer` | Código de salida del proceso. Un valor distinto de cero indica un error en tiempo de ejecución. |
| `duration_ms` | `integer` | Duración real de la ejecución, en milisegundos.                                                 |
| `status`      | `string`  | Estado de cada ejecución. Uno de `completed`, `timed_out`, `failed`.                            |

Ejemplo:

```json theme={null}
{
  "type": "sandbox_results",
  "call_id": "call_Y1Lo4H6cGFgNVsn4mwC0oSgc",
  "code": "vals = [(i, i*i) for i in range(1, 11)]\nprint('\\n'.join(f'{a},{b}' for a, b in vals))",
  "container_id": "i6dr97ven2qfm0sdtvfzc",
  "language": "python",
  "results": [
    {
      "duration_ms": 9011,
      "exit_code": 0,
      "status": "completed",
      "stderr": "",
      "stdout": "1,1\n2,4\n3,9\n4,16\n5,25\n6,36\n7,49\n8,64\n9,81\n10,100\n"
    }
  ],
  "status": "completed"
}
```

Para ver el esquema completo de la solicitud y la respuesta, consulta la [referencia de la Agent API](/es/api-reference/agent-post).

<div id="retrieving-generated-files">
  ## Recuperar archivos generados
</div>

Cuando el código del sandbox escribe un archivo y lo entrega mediante la herramienta `share_file`, el array `output` de la respuesta incluye un elemento `share_file`. El contenido del archivo no se devuelve en línea: debes recuperarlo con los endpoints de archivos de respuestas, usando el `id` de la respuesta.

Lista los archivos que generó una respuesta:

<CodeGroup>
  ```python Python theme={null}
  from perplexity import Perplexity

  client = Perplexity()

  files = client.responses.files.list("resp_abc123")

  for file in files.data:
      print(file.id, file.filename, file.bytes)
  ```

  ```bash cURL theme={null}
  curl https://api.perplexity.ai/v1/agent/$RESPONSE_ID/files \
    -H "Authorization: Bearer $PERPLEXITY_API_KEY" | jq
  ```
</CodeGroup>

```json theme={null}
{
  "data": [
    {
      "bytes": 8002,
      "created_at": 1780923289,
      "filename": "anthropic_news.csv",
      "id": "9198548a-490b-4119-858f-fd3676b60319",
      "object": "file"
    }
  ],
  "object": "list"
}
```

Cada entrada tiene los siguientes campos:

| Campo        | Tipo      | Descripción                                                                                         |
| ------------ | --------- | --------------------------------------------------------------------------------------------------- |
| `id`         | `string`  | Identificador del archivo, empleado para descargar el contenido. Distinto del `id` de la respuesta. |
| `filename`   | `string`  | Nombre que el sandbox asignó al archivo.                                                            |
| `bytes`      | `integer` | Tamaño del archivo en bytes.                                                                        |
| `created_at` | `integer` | Marca de tiempo Unix de la creación del archivo.                                                    |
| `object`     | `string`  | Siempre `file`.                                                                                     |

Descarga el contenido de un archivo a partir de su `id`. El endpoint devuelve los bytes sin procesar del archivo (no JSON), con un `Content-Type` acorde al archivo y una cabecera `Content-Disposition: attachment` que incluye el nombre original.

<CodeGroup>
  ```python Python theme={null}
  from perplexity import Perplexity

  client = Perplexity()

  content = client.responses.files.content(
      file_id="9198548a-490b-4119-858f-fd3676b60319",
      response_id="resp_abc123",
  )
  content.write_to_file("anthropic_news.csv")
  ```

  ```bash cURL theme={null}
  curl https://api.perplexity.ai/v1/agent/$RESPONSE_ID/files/$FILE_ID/content \
    -H "Authorization: Bearer $PERPLEXITY_API_KEY" \
    -o anthropic_news.csv
  ```
</CodeGroup>

<div id="pricing">
  ## Precios
</div>

`sandbox` se factura según tres ejes:

| Eje                     | Precio               | Notas                                                                                                                                                                                                                                                                                                     |
| ----------------------- | -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Tokens**              | Según el modelo       | El uso de tokens del modelo se factura por separado según los precios de tokens de la Agent API. Consulta [Modelos](/es/docs/agent-api/models) para ver las tarifas de cada modelo.                                                                                                                            |
| **Sesión de sandbox**   | $0,03 por sesión     | Se factura una sola vez por cada contenedor de sandbox. Una sesión es el ciclo de vida de un único contenedor aislado y cubre hasta 20 minutos de uso activo a efectos de facturación: es la ventana de facturación, no un límite de ejecución.                                                           |
| **Herramientas usadas** | Según la herramienta | El código que se ejecuta dentro del sandbox puede llamar a las herramientas [Web Search](/es/docs/agent-api/tools/web-search), [Fetch URL Content](/es/docs/agent-api/tools/fetch-url-content) y [People Search](/es/docs/agent-api/tools/people-search). Cada una se factura a su tarifa estándar por invocación. |

Las invocaciones de sandbox se contabilizan en `usage.tool_calls_details.sandbox.invocation`.

Consulta [Precios](/es/docs/getting-started/pricing#tool-pricing) para ver la tabla completa de precios de las herramientas de la Agent API.
