<div id="overview">
  ## Descripción general
</div>

La herramienta `web_search` permite al modelo buscar en la web durante una solicitud a la Agent API. Úsala para obtener información actualizada, noticias recientes, investigación respaldada por fuentes y responder preguntas que requieren información más allá de los datos de entrenamiento del modelo.

Habilita la herramienta agregándola al arreglo `tools`. El modelo decide cuándo invocarla en función de tu prompt y de las instrucciones.

<CodeGroup>
  ```python Python theme={null}
  from perplexity import Perplexity

  client = Perplexity()

  response = client.responses.create(
      model="openai/gpt-5.6-sol",
      input="Explain the architecture of NVIDIA's CUDA programming model: threads, blocks, grids, warps, and memory hierarchy, and how they enable GPU parallelism.",
      tools=[
          {
              "type": "web_search",
              "search_context_size": "medium"
          }
      ],
      instructions="Search for current, source-grounded information before answering.",
  )

  print(response.output_text)
  ```

  ```typescript Typescript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  const response = await client.responses.create({

    tools: [
      {
        type: 'web_search' as const,
        search_context_size: 'medium',
      },
    ],
    instructions: 'Search for current, source-grounded information before answering.',
  });

  console.log(response.output_text);
  ```

<div id="using-recommended-token-budgets">
  ### Uso de los presupuestos de tokens recomendados
</div>

Empieza con `low`, `medium` o `high` para dimensionar el contexto de búsqueda mediante `search_context_size`. Cada tamaño con nombre se asigna a un par recomendado de presupuestos `max_tokens` y `max_tokens_per_page`, y es la opción predeterminada recomendada para la mayoría de las aplicaciones.

| `search_context_size` | `max_tokens` | `max_tokens_per_page` | Ideal para                                             |
| --------------------- | ------------ | --------------------- | ------------------------------------------------------ |
| `low`                 | 300          | 300                   | Datos sencillos y consultas ligeras                    |
| `medium`              | 1000         | 1000                  | Investigación general y comparación de productos       |
| `high`                | 4000         | 4000                  | Respuestas con muchas fuentes e investigación compleja |

<Note>
  Estas correspondencias de presupuestos de tokens reflejan los valores predeterminados que Perplexity recomienda actualmente y pueden cambiar a medida que publiquemos configuraciones actualizadas según los resultados de evaluación más recientes. Al invocar un tamaño con nombre, siempre se aplica el presupuesto recomendado vigente.
</Note>

<div id="advanced-token-budget-configuration">
  ### Configuración avanzada del presupuesto de tokens
</div>

Usa el presupuesto explícito de tokens cuando necesites fijar presupuestos exactos para controlar costes, controlar la latencia o realizar evaluaciones. Establece `max_tokens` para limitar el contexto de búsqueda total de todos los resultados y `max_tokens_per_page` para limitar el contenido extraído de cada página de resultados. Los presupuestos explícitos prevalecen sobre cualquier valor de `search_context_size` enviado en la misma solicitud, y se te cobra por el número exacto de tokens de contexto de búsqueda consumidos, no por el presupuesto solicitado.

<div id="filters">
  ## Filtros
</div>

Usa filtros para restringir las fuentes, las fechas y el contexto de ubicación que utiliza `web_search`.

| Filtro                       | Tipo             | Descripción                                                                                   |
| ---------------------------- | ---------------- | --------------------------------------------------------------------------------------------- |
| `search_domain_filter`       | array de cadenas | Incluye o excluye hasta 20 dominios o URL. Antepón `-` a las entradas para excluirlas.        |
| `search_recency_filter`      | cadena           | Limita los resultados a `"hour"`, `"day"`, `"week"`, `"month"` o `"year"`.                    |
| `search_after_date_filter`   | cadena           | Incluye resultados publicados después de una fecha en formato MM/DD/YYYY.                     |
| `search_before_date_filter`  | cadena           | Incluye resultados publicados antes de una fecha en formato MM/DD/YYYY.                       |
| `last_updated_after_filter`  | cadena           | Incluye resultados cuya última actualización sea posterior a una fecha en formato MM/DD/YYYY. |
| `last_updated_before_filter` | cadena           | Incluye resultados cuya última actualización sea anterior a una fecha en formato MM/DD/YYYY.  |
| `user_location`              | objeto           | Personaliza la búsqueda por país, región, ciudad, latitud y longitud.                         |

<div id="domain-filter">
  ### Filtro de dominios
</div>

<Warning>
  Usa `search_domain_filter` en modo de lista de permitidos o en modo de lista de bloqueados, pero no en ambos. El filtro de dominios admite hasta 20 dominios o URL. Por ejemplo, `["nasa.gov", "wikipedia.org"]` incluye únicamente esos dominios, mientras que `["-reddit.com", "-pinterest.com"]` los excluye.
</Warning>

Las entradas pueden definirse a nivel de dominio (por ejemplo, `wikipedia.org`) o a nivel de URL (por ejemplo, `https://en.wikipedia.org/wiki/Chess`) para lograr un control más granular.

<div id="recency-filter">
  ### Filtro de actualidad
</div>

`search_recency_filter` asigna a cada valor una ventana relativa:

| Valor   | Ventana                                                                                         |
| ------- | ----------------------------------------------------------------------------------------------- |
| `hour`  | Última hora: úsalo para datos en tiempo real, como noticias de última hora o eventos en directo |
| `day`   | Últimas 24 horas                                                                                |
| `week`  | Últimos 7 días                                                                                  |
| `month` | Últimos 30 días                                                                                 |
| `year`  | Últimos 365 días                                                                                |

Para rangos exactos, usa `search_after_date_filter` / `search_before_date_filter` (fecha de publicación) o `last_updated_after_filter` / `last_updated_before_filter` (última actualización). Los valores de los filtros de fecha deben tener el formato `MM/DD/YYYY` (por ejemplo, `"03/01/2026"`).

<div id="location-filter">
  ### Filtro de ubicación
</div>

`user_location` acepta cualquier combinación de los siguientes campos:

* `country` — Código de dos letras [ISO 3166-1 alpha-2](https://en.wikipedia.org/wiki/ISO_3166-1_alpha-2) (por ejemplo, `"US"`, `"FR"`).
* `region` — Nombre de la región o del estado (por ejemplo, `"California"`).
* `city` — Nombre de la ciudad (por ejemplo, `"San Francisco"`).
* `latitude` y `longitude` — Coordenadas para una localización precisa.

<Tip>
  `city` y `region` mejoran notablemente la precisión de la ubicación. Inclúyelos junto con `country` siempre que sea posible.
</Tip>

<Warning>
  `latitude` y `longitude` deben proporcionarse junto con `country`. No se pueden enviar por separado.
</Warning>

<div id="filter-usage-cheatsheet">
  ### Guía rápida de uso de filtros
</div>

Copia cualquiera de estos fragmentos en un objeto de herramienta `web_search`. `user_location` va al mismo nivel que `filters`, mientras que los demás controles se colocan dentro de `filters`.

| Filtro                        | Ejemplo                                                                                                          |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Lista de dominios permitidos  | `filters: { search_domain_filter: ["docs.perplexity.ai", "developer.mozilla.org"] }`                             |
| Lista de dominios bloqueados  | `filters: { search_domain_filter: ["-reddit.com", "-pinterest.com"] }`                                           |
| Actualidad                    | `filters: { search_recency_filter: "week" }`                                                                     |
| Rango de fecha de publicación | `filters: { search_after_date_filter: "01/01/2026", search_before_date_filter: "05/01/2026" }`                   |
| Rango de última actualización | `filters: { last_updated_after_filter: "01/01/2026", last_updated_before_filter: "05/01/2026" }`                 |
| Ubicación del usuario         | `user_location: { country: "US", region: "CA", city: "San Francisco", latitude: 37.7749, longitude: -122.4194 }` |

<Tip>
  Los filtros se combinan sin restricciones. Puedes usar juntos los filtros de fuente, fecha, actualidad y ubicación anteriores en un mismo objeto de herramienta `web_search`: no hay límite por solicitud en cuanto a combinaciones de filtros.
</Tip>

<div id="response-shape">
  ## Estructura de la respuesta
</div>

Cuando se ejecuta `web_search`, la respuesta puede incluir un elemento de salida `search_results` antes del mensaje final del asistente. El objeto `usage` final incluye el recuento de tokens, los detalles de costos y `tool_calls_details.search_web.invocation` cuando se reporta el uso de llamadas a herramientas.

```json theme={null}
{
  "output": [
    {
      "type": "search_results",
      "queries": ["AI infrastructure announcements"],
      "results": [
        {
          "id": 1,
          "url": "https://example.com/news",
          "title": "Example AI infrastructure announcement",
          "snippet": "A short snippet from the search result.",
          "date": "2026-05-01",
          "last_updated": "2026-05-01",
          "source": "web"
        }
      ]
    },
    {
      "type": "message",
      "role": "assistant",
      "content": [
        {
          "type": "output_text",
          "text": "The answer generated from the search results."
        }
      ]
    }
  ],
  "usage": {
    "input_tokens": 1200,
    "output_tokens": 300,
    "total_tokens": 1500,
    "tool_calls_details": {
      "search_web": {
        "invocation": 1
      }
    }
  }
}
```

Cada entrada de `results` incluye los siguientes campos:

| Campo          | Tipo   | Descripción                                                             |
| -------------- | ------ | ----------------------------------------------------------------------- |
| `id`           | entero | Índice estable que se usa para referenciar el resultado en las citas.   |
| `url`          | cadena | URL canónica de la página de origen.                                    |
| `title`        | cadena | Título de la página tal como lo devuelve la fuente.                     |
| `snippet`      | cadena | Fragmento de texto extraído de la página durante la búsqueda.           |
| `date`         | cadena | Fecha de publicación original de la página, en formato `YYYY-MM-DD`.    |
| `last_updated` | cadena | Fecha de la última actualización de la página, en formato `YYYY-MM-DD`. |
| `source`       | cadena | Origen del resultado (por ejemplo, `"web"`).                            |

<Tip>
  **¿Quieres citas en línea?** Que el model añada marcadores a la respuesta depende del prompt, así que pídelos de forma explícita: por ejemplo, agrega a tu prompt: *&quot;Cita tus fuentes en línea con marcadores entre corchetes, una fuente por corchete, como `[1][2]`.&quot;* Cada número corresponde entonces al `id` de un resultado. Haya marcadores o no, toma los campos `id` y `url` de cada entrada de `search_results` como la fuente de verdad para las citas.
</Tip>

<div id="pricing">
  ## Precios
</div>

`web_search` se cobra a **$2,50 por cada 1.000 invocaciones**. El uso de tokens del modelo se factura por separado según los precios por token de la Agent API.

<Note>
  Los precios siguen el mismo esquema que el resto de llamadas a herramientas: se paga por las invocaciones de la herramienta más los tokens del modelo. Consulta [Precios](/es/docs/getting-started/pricing).
</Note>

<div id="limits-quotas">
  ## Límites / Cuotas
</div>

`web_search` se ejecuta dentro de las solicitudes de la Agent API y se rige por los límites de tasa de solicitudes de la Agent API. Consulta [Límites de tasa y niveles de uso](/es/docs/admin/rate-limits-usage-tiers#agent-api-rate-limits) para conocer los límites actuales de la Agent API según el nivel.

| Límite                                 | Se aplica a                                                | Recomendación                                                                                                                                                               |
| -------------------------------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Límites de tasa                        | Solicitudes de la Agent API que incluyen `web_search`      | A la solicitud se le aplican los límites del nivel de la Agent API. Implementa reintentos y retroceso exponencial para el tráfico en producción.                            |
| Entradas de dominio                    | `search_domain_filter`                                     | Hasta 20 dominios o URL por solicitud. Usa el modo de lista de permitidos o de bloqueados, tal como se describe en la advertencia de [Filtros](#filters).                   |
| Presupuesto de contexto de búsqueda    | `search_context_size`, `max_tokens`, `max_tokens_per_page` | Los presets de `search_context_size` gestionan el contexto automáticamente. Usa límites explícitos de tokens cuando necesites un control más estricto de costos o latencia. |
| Facturación de llamadas a herramientas | Invocaciones de `web_search`                               | Cada invocación de búsqueda computa en el uso y el precio de las llamadas a herramientas, de forma independiente del uso de tokens del modelo.                              |
