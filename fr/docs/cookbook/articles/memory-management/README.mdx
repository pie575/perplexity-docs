<div id="memory-management-with-llamaindex-and-perplexity-sonar-api">
  # Gestion de la mémoire avec LlamaIndex et la Sonar API de Perplexity
</div>

<div id="overview">
  ## Vue d&#39;ensemble
</div>

Cet article explore des solutions avancées pour préserver la mémoire conversationnelle dans les applications reposant sur de grands modèles de langage (LLM). L&#39;objectif est de permettre des conversations cohérentes sur plusieurs tours en conservant le contexte d&#39;une interaction à l&#39;autre, même lorsque la limite de tokens du modèle impose ses contraintes.

<div id="problem-statement">
  ## Énoncé du problème
</div>

Les LLM disposent d&#39;une fenêtre de contexte limitée, ce qui complique le maintien d&#39;une mémoire conversationnelle à long terme. Sans gestion adéquate de la mémoire, les questions de suivi peuvent perdre en pertinence ou donner lieu à des réponses hallucinées, sans rapport avec le sujet.

<div id="approaches">
  ## Approches
</div>

Avec LlamaIndex, nous avons implémenté deux stratégies distinctes pour résoudre ce problème :

<div id="1-chat-summary-memory-buffer">
  ### 1. **Chat Summary Memory Buffer**
</div>

* **Objectif** : résumer les messages les plus anciens pour rester dans la limite de tokens tout en conservant le contexte essentiel.
* **Approche** :
  * Utilise le `ChatSummaryMemoryBuffer` de LlamaIndex pour tronquer et résumer dynamiquement l&#39;historique de la conversation.
  * Garantit que les détails clés des échanges précédents sont conservés sous une forme condensée.
* **Cas d&#39;usage** : idéal pour les conversations de courte durée, où l&#39;efficacité mémoire est déterminante.
* **Implémentation** : [Consulter le guide complet →](/fr/docs/cookbook/articles/memory-management/chat-summary-memory-buffer/README)

<div id="2-persistent-memory-with-lancedb">
  ### 2. **Mémoire persistante avec LanceDB**
</div>

* **Objectif** : assurer la persistance de la mémoire à long terme d&#39;une session à l&#39;autre.
* **Approche** :
  * Stocke l&#39;historique des conversations sous forme d&#39;embeddings vectoriels dans LanceDB.
  * Récupère le contexte historique pertinent via la recherche sémantique et des filtres sur les métadonnées.
  * Intègre la Sonar API de Perplexity pour générer des réponses à partir du contexte récupéré.
* **Cas d&#39;usage** : adapté aux applications nécessitant une mémoire à long terme et un rappel contextuel.
* **Implémentation** : [Consulter le guide complet →](/fr/docs/cookbook/articles/memory-management/chat-with-persistence/README)
