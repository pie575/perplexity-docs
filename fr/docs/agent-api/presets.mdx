<div id="overview">
  ## Vue d&#39;ensemble
</div>

Les presets sont des configurations prédéfinies optimisées pour des cas d&#39;usage spécifiques. Chaque preset regroupe un model, une configuration de recherche, des étapes de raisonnement, un system prompt et un ensemble d&#39;outils disponibles.

<Info>
  Les presets de l&#39;Agent API utilisent désormais des noms basés sur des niveaux : fast-search → fast, pro-search → low, deep-research → medium, advanced-deep-research → high et ultra → xhigh.
</Info>

Les presets peuvent être utilisés de deux manières :

* **Preset dynamique (recommandé)** — appelez un preset par son nom (par exemple, `preset="low"`) pour bénéficier de la configuration optimisée par Perplexity la plus récente. Perplexity met à jour la configuration sous-jacente dès que les évaluations montrent des améliorations, et votre application en profite automatiquement, sans modification de code.
* **Preset/configuration figé** — copiez les valeurs actuelles d&#39;un preset (model, outils, system prompt, paramètres) dans votre requête et omettez le paramètre `preset`. Vous figez ainsi la configuration exacte qu&#39;utilise le preset aujourd&#39;hui. Choisissez cette approche si vous souhaitez mettre votre application à l&#39;abri des futures mises à jour de presets ou fixer précisément le model et les outils sous-jacents.

Vous pouvez combiner les deux : appelez le preset dynamique dans la plupart des environnements et utilisez une configuration figée là où la stabilité est indispensable.

<Note>
  Un preset est géré par Perplexity.
  Pour enregistrer et versionner votre propre configuration — par exemple en partant des [valeurs actuelles](#current-preset-values) d&#39;un preset —, utilisez un [profile](/fr/docs/agent-api/profiles), l&#39;équivalent d&#39;un preset détenu par l&#39;organisation.
  Une requête ne peut pas définir à la fois `preset` et `profile`.
</Note>

Les presets dynamiques utilisent automatiquement une `prompt_cache_key` stable pour leur préfixe de prompt partagé (system prompt et définitions d&#39;outils). Cela améliore la réutilisation du cache de prompts entre des requêtes indépendantes qui utilisent le même preset. Vous n&#39;avez pas besoin de définir la clé vous-même ; une `prompt_cache_key` explicite au niveau de la requête prévaut sur la valeur par défaut du preset.

<Info>
  Les presets fournissent des valeurs par défaut pertinentes, optimisées pour leur cas d&#39;usage. Vous pouvez remplacer n&#39;importe quel paramètre (comme `model`, `max_steps` ou `tools`) en transmettant des paramètres supplémentaires. Consultez [Personnaliser les presets](#customizing-presets) pour des exemples de code.
</Info>

<Note>
  **Aucun versionnement explicite.** Les presets ne sont pas rattachés à une version spécifique. Appeler un preset par son nom renvoie toujours la configuration la plus récente recommandée par Perplexity. Lorsque nous déployons une configuration nettement meilleure, nous la proposons sous forme de preset amélioré — le nom reste identique. Si vous devez fixer une configuration spécifique, créez plutôt une configuration figée en copiant les [valeurs actuelles du preset](#current-preset-values) directement dans votre requête.
</Note>

<div id="what-changes-when-a-preset-is-updated">
  ### Ce qui change lorsqu&#39;un preset est mis à jour
</div>

Lorsque Perplexity met à jour un preset, nous veillons à ce que les changements restent dans le même profil attendu, afin que votre application bénéficie d&#39;un gain de qualité sans mauvaise surprise :

* **Profil de coût** — les mises à jour de preset visent la même tranche de coût. Le model sous-jacent peut changer, mais les mises à jour sont calibrées pour rester au plus près du coût par requête existant.
* **Profil de latence** — les mises à jour de preset visent la même tranche de latence. Le nombre d&#39;étapes, la configuration de recherche et le budget d&#39;outils restent proches des valeurs actuelles.
* **Qualité** — c&#39;est la dimension que les mises à jour de preset cherchent à optimiser. Les nouvelles configurations sont déployées lorsque les évaluations font état d&#39;améliorations significatives.

Si vous devez figer une configuration précise plutôt que de suivre ces mises à jour, créez une configuration figée en copiant les [valeurs actuelles du preset](#current-preset-values) directement dans votre requête.

<div id="choosing-a-preset">
  ## Choisir un preset
</div>

Chaque preset établit un compromis entre profondeur de recherche, couverture des sources et latence. Utilisez le tableau ci-dessous pour choisir celui qui convient à votre requête.

| Preset            | Points forts                                                                                                                                                        | À utiliser quand                                                                                                                                                                                                                                                           |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **fast**          | Recherche d&#39;un fait précis, définitions et résumés rapides avec citations en ligne.                                                                             | La réponse tient en un fait ou un court résumé, la latence prime et aucune recherche en plusieurs étapes n&#39;est nécessaire.                                                                                                                                             |
| **low**           | Questions de recherche courantes, recherches légères en plusieurs étapes avec des informations à jour et des citations en ligne.                                    | Une requête nécessite des informations à jour, avec un recours limité à la recherche et aux outils.                                                                                                                                                                        |
| **medium**        | Navigation multi-étapes et agrégation large de nombreuses sources, avec citations en ligne pour les affirmations étayées par des sources.                           | Une question exige de recouper des éléments de preuve issus de nombreuses sources sur plusieurs cycles de recherche et de raisonnement.                                                                                                                                    |
| **high**          | Raisonnement de niveau expert et couverture exhaustive des sources, avec citations en ligne pour les affirmations étayées par des sources.                          | Vous avez besoin de la couverture la plus large et du raisonnement le plus poussé — une analyse de qualité institutionnelle où l&#39;exhaustivité compte plus que la latence.                                                                                              |
| **xhigh**         | Travaux ouverts et agentiques : exécution de code dans un sandbox, longues boucles d&#39;utilisation d&#39;outils et collecte simultanée sur de nombreuses sources. | La tâche est ouverte plutôt qu&#39;une simple question — elle exécute du code, orchestre de nombreux cycles d&#39;utilisation d&#39;outils ou construit un résultat étape par étape. C&#39;est le preset le plus puissant, idéal lorsque la capacité prime sur la vitesse. |
| **wide-research** | Constitution de vastes collections étayées par des preuves, avec découverte large et recherche menée sur chaque élément.                                            | Vous devez identifier de nombreux éléments répondant aux critères, étayer chaque résultat par des sources et produire une sortie structurée exploitable en aval. Voir le [guide Wide Research](/fr/docs/agent-api/wide-research).                                             |

<Info>
  La configuration complète actuelle de chaque preset — model, outils, paramètres et system prompt — figure dans la section [Valeurs actuelles des presets](#current-preset-values) ci-dessous.
</Info>

<div id="using-a-preset">
  ## Utiliser un preset
</div>

Appelez un preset par son nom avec le paramètre `preset` — Perplexity gère la configuration sous-jacente, ce qui vous permet de bénéficier des améliorations à venir sans modifier votre code.

<CodeGroup>
  ```python Python theme={null}
  from perplexity import Perplexity

  client = Perplexity()

  response = client.responses.create(
      preset="low",
      input="Summarize the core findings of the original 'Attention Is All You Need' transformer paper and explain why it changed NLP.",
  )

  print(response.output_text)
  ```

  ```typescript Typescript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  const response = await client.responses.create({
      preset: "low",
      input: "Summarize the core findings of the original 'Attention Is All You Need' transformer paper and explain why it changed NLP.",
  });

  console.log(response.output_text);
  ```

  ```bash cURL theme={null}
  curl https://api.perplexity.ai/v1/agent \
    -H "Authorization: Bearer $PERPLEXITY_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "preset": "low",
      "input": "Summarize the core findings of the Attention Is All You Need transformer paper and explain why it changed NLP."
    }'
  ```
</CodeGroup>

Remplacez `preset="low"` par n&#39;importe quel nom de preset du [tableau ci-dessus](#choosing-a-preset). Pour redéfinir une valeur par défaut d&#39;un preset, consultez [Personnaliser les presets](#customizing-presets).

<div id="customizing-presets">
  ## Personnaliser les presets
</div>

Les presets fournissent des valeurs par défaut pertinentes. Tout champ que vous transmettez avec le preset remplace la valeur par défaut correspondante. Tout ce que vous ne définissez pas conserve la valeur par défaut du preset.

Les `tools` font seuls exception : ils sont fusionnés outil par outil plutôt que remplacés dans leur ensemble. Déclarer un outil ne remplace que les options de cet outil et laisse les autres outils du preset activés.

<Note>
  Pour ajuster la profondeur de recherche avec un preset, définissez `max_tokens` et `max_tokens_per_page` sur `web_search`. Voir [Configurer la recherche](/fr/docs/agent-api/tools/web-search#configuring-search).
</Note>

<div id="current-preset-values">
  ## Valeurs actuelles des presets
</div>

Les valeurs actuelles d&#39;un preset correspondent au model, au system prompt, aux outils et aux paramètres concrets qui sous-tendent chaque preset, exprimés sous forme de champs d&#39;API publics. Copiez ces valeurs dans votre requête et omettez le paramètre `preset` pour créer une configuration figée : une configuration épinglée qui reproduit le comportement actuel du preset.

Chaque preset ci-dessous présente l&#39;intégralité de ses valeurs actuelles, de façon autonome — copiez un seul bloc pour figer le comportement du preset concerné.

<Note>
  Les configurations figées sont épinglées. Elles ne bénéficieront **pas** des améliorations futures des presets — appelez le preset par son nom (un [preset dynamique](#using-a-preset)) si vous souhaitez des mises à jour automatiques.
</Note>

<Note>
  L&#39;onglet cURL peut afficher une configuration plus complète que les onglets SDK : certains paramètres ne sont pas encore exposés par le SDK.
</Note>

Les exemples figés ci-dessous calculent localement la date UTC du jour avant d&#39;envoyer la requête. L&#39;API remplace `{{current_date}}` uniquement dans les instructions par défaut d&#39;un preset ; les espaces réservés présents dans les `instructions` fournies dans la requête sont transmis tels quels.

  <Accordion title="rapide — valeurs actuelles du préréglage">
    Recherches factuelles rapides, avec une latence minimale et des citations en ligne pour les affirmations issues de la recherche web.

    * **Modèle :** `openai/gpt-5.6-luna`

    * **Effort de raisonnement :** `minimal`
    * **Niveau de service :** `priority`
    * **Nombre maximal de tokens en sortie :** 8192
    * **Outils :** `web_search`
    * **Résultats de recherche :** `max_results: 10` (requête cURL)

          reasoning={"effort": "minimal"},
          instructions=r"""
      ## Role
      <role>
      You are Perplexity, a helpful search assistant built by Perplexity AI. Your task is to deliver accurate, well-cited answers by leveraging web search results. You prioritize speed and precision, providing direct answers that respect the user's time while maintaining factual accuracy.

      Given a user's query, generate an expert, useful, and contextually relevant response. Answer only the current query using its provided search results and relevant conversation history. Do not repeat information from previous answers.
      </role>

      ## Tools Workflow
      <tools_workflow>
      You must call the web search tool before answering. Do not rely on internal knowledge when search results can provide current, verifiable information.

      - Decompose complex queries into discrete, parallel search calls for accuracy
      - Use short, keyword-based queries (2-5 words optimal, 8 words maximum)
      - Do not generate redundant or overlapping queries
      - Match the language of the user's query
      - If search results are empty or unhelpful, answer using existing knowledge and state this limitation

      <tool_call_limit>Make at most one tool call before concluding.</tool_call_limit>
      </tools_workflow>

      ## Citation Instructions
      <citations>
      Your response must include citations. Add a citation to every sentence that includes information derived from search results.

      <formatting>
      - Use brackets with the source index immediately after the relevant statement: [1], [2], etc.
      - Do not leave a space between the last word and the citation
      - When multiple sources support a claim, use separate brackets: [1][2][3]
      - Cite up to three relevant sources per sentence, choosing the most pertinent results
      - Never use formats with spaces, commas, or dashes inside brackets
      - Citations must appear inline, never in a separate References section
      </formatting>

      <examples>
      Correct: "The Eiffel Tower is located in Paris[1][2]."
      Incorrect: "The Eiffel Tower is located in Paris [1, 2]."
      Incorrect: "The Eiffel Tower is located in Paris[1-2]."
      </examples>

      If you did not perform a search, do not include citations.
      </citations>

      ## Response Guidelines
      <response_guidelines>

      <structure>
      - Begin with a direct 1-2 sentence answer to the core question
      - Never start with a header or meta-commentary about your process
      - Use Level 2 headers (##) for sections only when organizing substantial content
      - Use bolded text (**text**) sparingly for emphasis on key terms
      - Keep responses concise; users should not need to scroll extensively
      </structure>

      <formatting>
      - Lists: Use flat lists only (no nesting). Numbers for sequential items, bullets (-) otherwise. One item per line with no indentation.
      - Tables: Use markdown tables for comparisons. Ensure headers are properly defined. Include citations within cells directly after relevant data.
      - Code: Use markdown code blocks with language identifiers for syntax highlighting.
      - Math: Use LaTeX with \( \) for inline and \[ \] for block formulas. Never use $ or unicode for math.
      - Quotes: Use markdown blockquotes for relevant supporting quotes.
      </formatting>

      <tone>
      - Write with precision and clarity using plain language
      - Use active voice and vary sentence structure naturally
      - Avoid hedging phrases ("It is important to...", "It is subjective...")
      - Do not use first-person pronouns or self-referential phrases
      - Ensure smooth transitions between sentences
      </tone>

      </response_guidelines>

      ## Query Type Adaptations
      <query_types>
      Adapt your response structure based on query type while following all general guidelines.

      <academic>
      Provide detailed, well-structured answers formatted as scientific write-ups with paragraphs and sections using markdown headers.
      </academic>

      <news>
      Summarize recent events concisely, grouping by topic. Use lists with bolded news titles at the start of each item. Prioritize diverse perspectives from trustworthy sources. Combine overlapping coverage with multiple citations. Prioritize recency. Never start with a header.
      </news>

      <weather>
      Provide only the weather forecast in a brief format. If search results lack relevant weather data, state this clearly.
      </weather>

      <people>
      Write a concise, comprehensive biography. If results reference multiple people with the same name, describe each separately without mixing information. Never start with the person's name as a header.
      </people>

      <coding>
      Use markdown code blocks with appropriate language identifiers. Present code first, then explain it.
      </coding>

      <recipes>
      Provide step-by-step instructions with clear ingredient amounts and precise directions for each step.
      </recipes>

      <translation>
      Provide the translation directly without citations or search references.
      </translation>

      <creative_writing>
      Follow user instructions precisely. Search results and citations are not required. Focus on delivering exactly what the user needs.
      </creative_writing>

      <math_and_science>
      For simple calculations, answer with the final result only. Use LaTeX for all formulas (\( \) inline, \[ \] block). Add citations after formulas: \[ \sin(x) \] [1][2]. Never use $ or unicode for math expressions.
      </math_and_science>

      <url_lookup>
      When the query includes a URL, rely solely on information from that source. Always cite [1] for the URL content. If the query is only a URL without instructions, summarize its content.
      </url_lookup>

      </query_types>

      ## Prohibited Content
      <prohibited>
      Never include in your responses:
      - Meta-commentary about your search or research process
      - Phrases like "Based on my search results...", "According to my research...", "Let me provide..."

      - Verbatim song lyrics or copyrighted content
      - A header at the beginning of your response
      - References or bibliography sections
      </prohibited>

      <copyright>
      - Never reproduce copyrighted content verbatim (text, lyrics, etc.)
      - Public domain content (expired copyrights, traditional works) may be shared
      - When copyright status is uncertain, treat as copyrighted
      - Keep summaries brief (under 30 words) and original
      - Brief factual statements (names, dates, facts) are always acceptable
      </copyright>""",
          tools=[
              {"type": "web_search"},
          ],
      )

      print(response.output_text)
