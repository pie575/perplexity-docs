<div id="overview">
  ## Vue d&#39;ensemble
</div>

L&#39;outil `fetch_url` récupère et extrait le contenu d&#39;URL spécifiques au cours d&#39;une requête à l&#39;Agent API. Utilisez-le lorsque votre application sait déjà quelle page, quel article, quel document ou quel rapport le modèle doit examiner.

Utilisez `fetch_url` lorsque vous avez besoin du contenu intégral de pages dont vous connaissez déjà les URL. Utilisez [`web_search`](/fr/docs/agent-api/tools/web-search) lorsque le modèle doit d&#39;abord identifier les pages pertinentes.

<CodeGroup>
  ```python Python theme={null}
  from perplexity import Perplexity

  client = Perplexity()

  response = client.responses.create(
      model="openai/gpt-5.6-sol",
      input="Explain Bayesian inference: how prior beliefs are updated to posterior beliefs given new evidence, with a concrete medical-test example.",
      tools=[
          {
              "type": "fetch_url"
          }
      ],
      instructions="Fetch the URL before summarizing it.",
  )

  print(response.output_text)
  ```

  ```typescript Typescript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  const response = await client.responses.create({

      {
        type: 'fetch_url' as const,
      },
    ],
    instructions: 'Fetch the URL before summarizing it.',
  });

  console.log(response.output_text);
  ```

<div id="when-to-use">
  ## Quand l&#39;utiliser
</div>

| Utilisez `fetch_url` quand...                       | Utilisez `web_search` quand...                             |
| --------------------------------------------------- | ---------------------------------------------------------- |
| Vous disposez déjà d&#39;une URL                    | Vous devez trouver des pages pertinentes                   |
| Vous avez besoin du contenu complet d&#39;une page  | Vous avez besoin d&#39;extraits issus de plusieurs sources |
| Vous résumez un article ou un document précis       | Vous explorez un sujet large                               |
| Vous voulez que le modèle examine une source connue | Vous voulez que le modèle trouve des sources récentes      |

<Tip>
  Combinez `web_search` et `fetch_url` pour une recherche en plusieurs étapes : recherchez les pages pertinentes, puis récupérez les URL les plus importantes afin d&#39;obtenir un contexte plus complet.
</Tip>

  ## Gestion des erreurs
</div>

`fetch_url` fonctionne au mieux des possibilités. Lorsqu&#39;une URL ne peut pas être entièrement récupérée ou extraite, l&#39;API peut tout de même renvoyer une réponse Agent API aboutie, dont le message final de l&#39;assistant précise quel contenu était disponible. Vérifiez chaque élément de `fetch_url_results.contents` : les éléments réussis contiennent le texte extrait de la page, tandis que les éléments en échec contiennent un marqueur explicite dans `snippet` pour l&#39;URL demandée.

Les marqueurs d&#39;échec indiquent la raison connue : erreur client HTTP, blocage par la politique robots ou limitation de débit, par exemple. Si la récupération en amont ne renvoie aucun élément pour une URL demandée, l&#39;API ajoute un élément dont le snippet inclut `no_result_returned`. Considérez ces marqueurs comme un contenu indisponible, et non comme du texte de page.

| Cas                                        | Comportement de la réponse                                                                                                                                                                                                                                      |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Contenus payants et pages de connexion** | `fetch_url` ne contourne pas les contrôles d&#39;accès. L&#39;élément de contenu correspondant contient un marqueur d&#39;échec précisant que le site d&#39;origine a rejeté la requête et qu&#39;il peut exiger des identifiants ou une méthode autre que GET. |
| **Redirections**                           | Les redirections HTTP sont suivies lorsque la destination peut être récupérée. Dans l&#39;élément `fetch_url_results` renvoyé, le champ `url` correspond à l&#39;URL que vous avez demandée, et non à la destination finale de la redirection.                  |
| **Contenu non HTML**                       | `fetch_url` extrait le contenu textuel que le serveur renvoie à l&#39;URL. Les PDF, les téléchargements binaires et les URL qui renvoient des pages de vérification anti-robot peuvent produire un contenu extrait limité ou sans rapport.                      |
| **Délais dépassés et URL inaccessibles**   | L&#39;élément de contenu correspondant contient un marqueur d&#39;échec accompagné de la raison disponible. Si aucun résultat en amont n&#39;est renvoyé, le marqueur inclut `no_result_returned`.                                                              |

<div id="limits-quotas">
  ## Limites / Quotas
</div>

Utilisez `max_urls` pour limiter les récupérations et les rendre prévisibles. Un nombre réduit d&#39;URL réduit généralement la latence et laisse davantage de contexte au raisonnement du modèle et à sa réponse finale.

| Limite                                             | Valeur                                                                                                                                                                                                         |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Nombre maximal d&#39;URL par appel d&#39;outil** | `max_urls` peut être défini de 1 à 10.                                                                                                                                                                         |
| **Schémas d&#39;URL pris en charge**               | Utilisez des URL absolues en `http://` ou `https://`. Les autres schémas (`file:`, `data:`, `ftp:`, URL d&#39;extensions de navigateur) ne sont pas pris en charge et ne produisent aucun contenu exploitable. |
| **Taille du contenu**                              | Le contenu récupéré est extrait sous forme d&#39;extraits destinés au contexte du modèle et peut être tronqué dans le cas des pages longues.                                                                   |
