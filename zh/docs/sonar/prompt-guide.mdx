本页介绍唯一一处会改变 Sonar 提示方式的结构性差异：系统提示词不会影响搜索。

<div id="shape-search-through-the-user-message">
  ## 通过用户消息来塑造搜索
</div>

Sonar 会在生成答案前先执行一次网络搜索，而驱动这次搜索的只有用户消息。系统提示词对搜索是不可见的，它只在生成答案时才会传给 model，此时搜索结果已经拿到手了。系统提示词适合用来设定语气、风格和事实依据规则，而用户消息则要同时当作提给 model 的问题和搜索的种子。

由此带来的实际影响是：用户消息的措辞会直接决定检索到哪些来源。具体、描述清晰的问题效果远好于含糊的提问，而再精心打磨的系统提示词也救不回一句含糊的用户消息。如果检索质量很关键，请优先在这里投入精力。

**好的示例**：&quot;What guidance has the FDA issued on AI in medical devices in the past year, and which device categories does it cover?&quot;

**不佳的示例**：&quot;Tell me about FDA AI rules.&quot;

<Warning>
  不要把搜索指令写进系统提示词。诸如&quot;只在 Wikipedia 上搜索&quot;或&quot;查找最新结果&quot;这类说法不会有任何效果。对于域名、时效性或地区这类硬性约束，请在请求体中使用专门的[搜索筛选参数](/zh/docs/sonar/filters)，而不要试图用自然语言把约束描述出来。
</Warning>

  ```python Python theme={null}
  from perplexity import Perplexity

  client = Perplexity()

  completion = client.chat.completions.create(
      model="sonar",
      messages=[
          {"role": "user", "content": "Summarize the FDA's regulatory framework for Software as a Medical Device (SaMD), including the Pre-Cert program."}
      ],
      search_domain_filter=["fda.gov"],
      search_recency_filter="month"
  )

  print(completion.choices[0].message.content)
  ```

这与 Agent API 形成对比：在 Agent API 中，`instructions` 会在智能体循环的每一轮被重新读取，既影响工具调用，也影响最终答案。而在 Sonar 中，没有与 `instructions` 对应的机制——系统消息只影响生成，永远不会影响检索。

<div id="reduce-hallucinations">
  ## 减少幻觉
</div>

大语言模型经过调优后总是倾向于“帮上忙”，因此当搜索结果稀少或不相关时，它们有时会硬给出一个答案，而不是指出信息缺口。系统提示词本身并不会影响搜索环节，但它决定了模型在撰写最终回复时如何使用搜索结果，因此这里正是设定事实依据规则的合适位置。只需补充两句简短的说明，就能覆盖大多数此类边缘情况。

**允许模型直接说自己没找到相关信息。** 在系统提示词中明确给出这样的“退路”后，模型就更有可能承认结果不足，而不是靠训练数据来填补缺口。

```text System Prompt theme={null}
仅使用所提供的搜索结果作答。如果搜索结果中没有答案，请明确说明，不要猜测。
```

**要求披露&quot;近似匹配&quot;结果。** 搜索有时会返回相关但并不匹配的结果 (年份不同、返回母公司而非子公司、产品相似但不是同一个) 。让 model 主动说明这类不匹配之处，可以避免它们被当作直接答案呈现。

```text System Prompt theme={null}
如果搜索结果与问题相关但并不匹配（例如年份不同、是母公司而非该公司、或是类似产品），请在作答前明确指出这一不匹配之处。
```

<div id="what-carries-over-from-the-agent-api-guide">
  ## 哪些内容沿用自 Agent API 指南
</div>

以下核心提示词规则完全适用，无需改动：

* **在用户消息中写得具体、描述清晰。** 含糊的查询只会得到零散的结果。
* **限定结果数量。** 如果需要列表，请说明列表长度。
* **不要用少样本示例提供内容。** 粘贴一段写好的示例答案，可能导致搜索环节紧盯示例中的主题。用少样本示例来约束*结构*没有问题；若需要保证输出形态，请使用 `response_format`。
* **不要在响应正文中索要 URL。** Sonar 始终会在顶层的 `citations` 和 `search_results` 字段中返回来源，请从这些字段读取。
* **筛选要用参数，而不是文字描述。** 搜索后端读取的是参数，而不是系统提示词。
