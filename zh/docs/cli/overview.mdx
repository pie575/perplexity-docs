---

`pplx` CLI 会返回来自 Perplexity Search API 的结构化 JSON，因此非常适合 shell 管道、交互式终端操作，以及需要获取最新网页结果或查询相关页面片段的编程智能体。

<div id="install">
  ## 安装
</div>

在你的项目中打开 agent，并向它发送以下内容：

```text wrap theme={null}
阅读 https://github.com/perplexityai/api-platform-developers/blob/main/skills/pplx-cli/SKILL.md 并安装该 skill，然后用它在我的终端中进行网页搜索。
```

若不使用 agent，可自行运行安装程序：

```bash theme={null}
curl -fsSL https://github.com/perplexityai/perplexity-cli/releases/latest/download/install.sh | sh
```

<div id="authenticate">
  ## 认证
</div>

每条命令都需要 [Perplexity API key](https://console.perplexity.ai/project/keys)。
请选择一种认证方式：

<Tabs>
  <Tab title="环境变量">
    ```bash theme={null}
    export PERPLEXITY_API_KEY="your_api_key_here"
    ```
  </Tab>

  <Tab title="交互式登录">
    ```bash theme={null}
    pplx auth login
    ```
  </Tab>
</Tabs>

<div id="filter-results">
  ### 过滤结果
</div>

这些标志用于限定搜索范围。
它们与 Search API 的过滤器完全相同，行为和限制也一致——详见[域名过滤器](/zh/docs/search/filters/domain-filter)和[日期与时间过滤器](/zh/docs/search/filters/date-time-filters)。

```bash theme={null}
pplx search web "AI inference hardware" \
  --domains arxiv.org,nvidia.com \
  --published-after-date 07/01/2026 \
  -n 5
```

| 参数                        | 格式                                 | 说明                | 示例                                        |
| ------------------------- | ---------------------------------- | ----------------- | ----------------------------------------- |
| `--domains`               | 逗号分隔的主机名                           | 仅返回来自这些域名的结果      | `--domains arxiv.org,nvidia.com`          |
| `--excluded-domains`      | 逗号分隔的主机名                           | 排除来自这些域名的结果       | `--excluded-domains reddit.com,quora.com` |
| `--published-after-date`  | `MM/DD/YYYY`                       | 发布日期在该日期当天或之后     | `--published-after-date 07/01/2026`       |
| `--published-before-date` | `MM/DD/YYYY`                       | 发布日期在该日期当天或之前     | `--published-before-date 07/31/2026`      |
| `--updated-after-date`    | `MM/DD/YYYY`                       | 最后修改时间在该日期当天或之后   | `--updated-after-date 07/01/2026`         |
| `--updated-before-date`   | `MM/DD/YYYY`                       | 最后修改时间在该日期当天或之前   | `--updated-before-date 07/31/2026`        |
| `--recency-filter`        | `hour`、`day`、`week`、`month`、`year` | 使用相对时间窗口，而非指定具体日期 | `--recency-filter week`                   |
| `--country`               | ISO 3166-1 alpha-2 代码              | 搜索面向的地区，默认为 `US`  | `--country DE`                            |

<Note>
  `--recency-filter` 不能与 `--published-after-date` 或 `--published-before-date` 同时使用。
  此类请求会返回 `BAD_REQUEST` 错误。
</Note>

<div id="ask-the-same-question-several-ways">
  ### 用多种方式提出同一个问题
</div>

额外的位置参数查询是同一个问题的不同表述，而非多次独立搜索。
CLI 仍然只返回一组排序后的结果，但换几种方式表述问题，能挖出那些只匹配你一开始没想到的措辞的页面：

```bash theme={null}
pplx search web \
  "kubernetes pod OOMKilled causes" \
  "why does k8s keep killing my pod with OOMKilled"
```

<div id="save-full-results">
  ### 保存完整结果
</div>

在保持 stdout 输出精简的同时保存完整结果：

```bash theme={null}
pplx search web "kubernetes pod OOMKilled causes" \
  --output-dir out \
  --stdout-preview=200
```

完整响应会写入 `out/web/`，标准输出中的 `saved_to` 字段包含其路径。
仅当你同时设置了 `--output-dir` 或 `PPLX_OUTPUT_DIR` 时，`--stdout-preview` 才会截断标准输出。
被截断的字符串以 `...<truncated>` 结尾，且响应中会新增顶层字段 `"truncated": true`。

<div id="search-errors">
  ### 搜索错误
</div>

搜索要么成功，要么直接失败：失败时 stdout 不会有任何输出，JSON 错误对象会写入 stderr。
搜索特有的错误码是 `BAD_REQUEST`，当各项过滤器相互矛盾时服务会返回该错误，例如同时使用 `--recency-filter` 和发布日期范围限制。
此处可能遇到的其他错误均属于[常见错误](#handle-errors)。

<div id="generate-query-relevant-snippets">
  ## 生成与查询相关的片段
</div>

只提取页面中与查询相关的段落，而不是抓取整个页面：

```bash theme={null}
pplx content snippets "how does a bloom filter decide set membership" \
  https://en.wikipedia.org/wiki/Bloom_filter
```

<Accordion title="响应">
  ```json wrap theme={null}
  {
    "results": [
      {
        "url": "https://en.wikipedia.org/wiki/Bloom_filter",
        "text": "In computing, a **Bloom filter** is a space-efficient probabilistic data structure, conceived by Burton Howard Bloom in 1970, that is used to test whether an element is a member of a set. False positive matches are possible, but false negatives are not ...",
        "tokens_count": 1047
      }
    ]
  }
  ```
</Accordion>

`text` 仅保留页面中与查询相关的段落，中间省略的部分用 `…` 字符标记。

<Info>
  `content snippets` 需要 CLI v0.2.3 或更高版本。
  若使用的是旧版二进制文件，请先运行 `pplx update`。
</Info>

<Note>
  `pplx content fetch` 已弃用，后续将停止可用，请改用 `content snippets`。
</Note>

<div id="cover-several-pages-in-one-call">
  ### 在一次调用中覆盖多个页面
</div>

多余的位置参数 URL 代表的是更多页面，而不是对问题的改写：与 `pplx search web` 不同 (在那里，额外的位置参数是对同一个问题的不同表述) ，这里每个 URL 都会针对同一查询独立截取片段。
单次调用最多支持 50 个 URL：

```bash theme={null}
pplx content snippets "bloom filter false positive rate" \
  https://en.wikipedia.org/wiki/Bloom_filter \
  https://systemdesign.one/bloom-filters-explained/ \
  --max-tokens-per-page 256
```

<Accordion title="响应">
  ```json wrap theme={null}
  {
    "results": [
      {
        "url": "https://en.wikipedia.org/wiki/Bloom_filter",
        "text": "More generally, fewer than 10 bits per element are required for a 1% false positive probability, independent of the size or number of elements in the set.\n\n…\n\nIf all are 1, then either the element is in the set, *or* the bits have by chance been set to 1 during the insertion of other elements, resulting in a false positive. ...",
        "tokens_count": 261
      },
      {
        "url": "https://systemdesign.one/bloom-filters-explained/",
        "text": "### Bloom filter false positive\n\nIn Figure 5, the bloom filter is queried to check the membership of item *green*, which is not a member of the bloom filter. ...",
        "tokens_count": 262
      }
    ]
  }
  ```
</Accordion>

<div id="budget-the-tokens">
  ### 规划 token 预算
</div>

有两个参数可以限制返回的文本量。

| 参数                      | 取值范围        | 默认值                     | 说明                                    |
| ----------------------- | ----------- | ----------------------- | ------------------------------------- |
| `--max-tokens`          | `1`–`16384` | `4096`                  | 所有片段合计的最大 token 数                     |
| `--max-tokens-per-page` | `1`–`4096`  | `min(1024, max_tokens)` | 单个页面片段的最大 token 数；不得超过 `--max-tokens` |

预算只是大致值：如上面的 `tokens_count` 所示，片段可能会略微超出上限。

<div id="snippet-errors">
  ### 片段错误
</div>

`pplx content snippets` 以 URL 为单位报告失败，而非以命令为单位。
某个页面无法提取片段并不会导致整次运行失败：命令仍以 `0` 退出，只是该 URL 的结果中会包含 `error` 消息，且没有 `text`。

```bash theme={null}
pplx content snippets "example domain reserved documentation" \
  https://www.iana.org/help/example-domains \
  https://www.example.com/nonexistent/
```

<Accordion title="响应">
  ```json wrap theme={null}
  {
    "results": [
      {
        "url": "https://www.iana.org/help/example-domains",
        "text": "1. Instructions and Guides\n\n# Example Domains\n\nAs described in RFC 2606 and RFC 6761, a number of domains such as example.com and example.org are maintained for documentation purposes. ...",
        "tokens_count": 152
      },
      {
        "url": "https://www.example.com/nonexistent/",
        "error": "no snippet could be generated under the requested token budget"
      }
    ]
  }
  ```
</Accordion>

在采信某个结果的 `text` 之前，请先检查每个结果中是否存在 `error`，因为调用成功并不代表每个页面都成功生成了摘要片段。

<div id="keep-large-responses-out-of-stdout">
  ### 避免将大体量响应输出到 stdout
</div>

即使只是片段，跨多个 URL 累加起来也相当可观。
`--output-dir` 会将完整响应写入 `<dir>/snippets/`，而 `--stdout-preview` 会截断输出到 stdout 的长字符串：

```bash theme={null}
pplx content snippets "how does a bloom filter decide set membership" \
  https://en.wikipedia.org/wiki/Bloom_filter \
  --output-dir out \
  --stdout-preview=200
```

<Accordion title="响应">
  ```json wrap theme={null}
  {
    "results": [
      {
        "url": "https://en.wikipedia.org/wiki/Bloom_filter",
        "text": "In computing, a **Bloom filter** is a space-efficient probabilistic data structure, conceived by Burton Howard Bloom in 1970, that is used to test whether an element is a member of a set. False positi...<truncated>",
        "tokens_count": 1047
      }
    ],
    "saved_to": "out/snippets/c6989ad7.json",
    "truncated": true
  }
  ```
</Accordion>

标准输出只会带上 `saved_to` 中的保存路径以及 `"truncated": true`，因此终端输出始终清爽易读，而完整文本则保存在磁盘上。

<div id="handle-errors">
  ## 处理错误
</div>

以下是所有 `pplx` 命令都可能遇到的常见错误。
命令失败时，会向 stderr 写入一个 JSON 错误对象：

```json theme={null}
{
  "error": {
    "code": "AUTHENTICATION",
    "message": "...",
    "command": "search.web",
    "hint": "Set the PERPLEXITY_API_KEY environment variable"
  }
}
```

根据 `error.code` 进行分支处理。

<Accordion title="错误码">
  | 错误码                                         | 触发场景                                     |
  | ------------------------------------------- | ---------------------------------------- |
  | `AUTHENTICATION`                            | 未配置密钥，或密钥无效                              |
  | `FORBIDDEN`                                 | 该密钥无权访问你请求的内容                            |
  | `RATE_LIMIT`                                | 已超出速率限制                                  |
  | `BAD_REQUEST`                               | 服务拒绝了该请求，例如 `--recency-filter` 与日期范围同时使用 |
  | `VALIDATION`                                | 服务拒绝了某个字段值                               |
  | `NOT_FOUND`                                 | 请求的资源不存在                                 |
  | `TIMEOUT`                                   | 请求耗时过长                                   |
  | `CONNECT`                                   | CLI 无法连接到 API                            |
  | `INTERNAL_SERVER`                           | 服务发生故障                                   |
  | `UNKNOWN_ARGUMENT`                          | 该命令没有此标志                                 |
  | `INVALID_VALUE`、`VALUE_VALIDATION`          | 标志值格式错误或超出范围                             |
  | `MISSING_REQUIRED_ARGUMENT`、`MISSING_QUERY` | 缺少必需参数或查询内容                              |
  | `ARGUMENT_ERROR`                            | 其他参数解析失败                                 |
</Accordion>

在假定某个标志存在之前，请先运行 `pplx <command> --help`；CLI 输出本身即为 JSON，因此无需 `--json` 标志。
