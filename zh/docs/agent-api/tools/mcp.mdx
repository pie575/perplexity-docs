<div id="overview">
  ## 概览
</div>

除了你自行定义的 `function` 工具之外，你还可以将 model 连接到远程 [Model Context Protocol](https://modelcontextprotocol.io) (MCP) 服务器，从而为其赋予新的能力。当 model 需要借助外部服务来回答提示词时，它会调用该服务器的工具来访问并控制这些服务。

`mcp` 工具可将用户提供的远程 MCP 服务器接入 Agent API 请求。请求开始时，Agent API 会发现该服务器的工具，并在运行过程中像调用原生工具一样调用它们，因此你无需为每个工具单独编写自定义的 `function` 工具。

<Note>
  无需在每次请求中都传入 MCP 服务器的 URL 和身份验证信息，[Connectors](/zh/docs/agent-api/tools/connectors) 可由 Perplexity 替你管理连接与认证：在 API Portal 中完成一次集成连接，之后通过 ID 引用即可——既不需要 `server_url`，也不需要为每次请求提供 token。Connectors 还能做到 `mcp` 工具无法做到的一点：与 [Sandbox](/zh/docs/agent-api/tools/sandbox) 共享凭据。借助 GitHub connector，model 可以在 sandbox 中运行 `git` 和 `gh` 来审查代码、修改代码并发起拉取请求。

  **预览版：** Connectors 目前处于预览阶段，支持的服务与行为可能会发生变化。
</Note>

下面的示例连接到公开的 [DeepWiki](https://deepwiki.com) MCP 服务器 (无需身份验证) ，并要求 model 使用该服务器的工具回答一个关于某个 GitHub 仓库的问题。

<Tip>
  如需查看将 MCP 服务器与 model 自带网络搜索相结合的更完整、可运行示例，请参阅 [Model Picker](/zh/docs/cookbook/examples/model-picker/README) cookbook 教程。
</Tip>

  ```python Python theme={null}
      ],

  print(response.output_text)
  ```

<div id="defer-tool-definitions">
  ## 延迟加载工具定义
</div>

默认情况下，请求中暴露的每个 MCP 工具定义都会进入模型的初始上下文。如果某个服务器工具数量很多、schema 很大，或者你同时连接了多个服务器，可将 `defer_loading` 设为 `true`。这样模型就能先检索工具目录，只加载需要的 schema。该字段按服务器单独生效，因此需要在每个希望延迟加载的服务器上分别设置。省略该字段或将其设为 `false`，则维持默认的即时加载行为。

延迟加载会在首次工具调用前额外消耗几个模型轮次。请将 [`max_steps`](/zh/docs/agent-api/building-agents/define-the-run#customize-the-loop-max-steps) 设得足够大，让模型既能检索目录，又能调用检索到的工具；否则，运行可能在检索结束后直接给出回答并终止，始终没有真正调用任何工具。

在下面的示例中，DeepWiki 的三个工具定义都不会出现在模型的初始上下文中。模型会先检索目录，只加载检索匹配到的内容，再调用找到的工具。

<CodeGroup>
  ```python Python theme={null}
  from perplexity import Perplexity

  client = Perplexity()

  response = client.responses.create(
      model="openai/gpt-5.6-sol",
      input="Ask DeepWiki this exact question: which license does fastapi/fastapi use?",
      max_steps=6,
      tools=[
          {
              "type": "mcp",
              "server_label": "deepwiki",
              "server_url": "https://mcp.deepwiki.com/mcp",
              "defer_loading": True,
          }
      ],
  )

  print(response.output_text)
  ```

<Tip>
  如果某个大量使用 MCP 的请求接近或超出模型的上下文窗口，请先启用 `defer_loading`，再考虑缩短提示词或移除有用的工具。这样可以避免将所有符合条件的 MCP schema 一次性塞入初始上下文，同时仍让模型能够使用这些工具。
</Tip>

每个 `tool_search_output` 项对应一次对延迟加载目录的搜索。搜索范围可以覆盖所有延迟加载的服务器，也可以只针对其中一个，且只返回匹配到的工具——即上文 DeepWiki 三个工具中的某一个。搜索也可能没有任何匹配结果，此时模型可以再次搜索，因此一次运行中可能包含多个这样的项。调用仍以 `mcp_call` 形式出现。请求开始时，Agent API 仍会发现每个服务器的工具，因此延迟加载既不会省去发现耗时，也不会改变[发现失败时的行为](#error-handling)。

三个小工具只能算规模不大的目录，因此额外的搜索步骤在这里收益有限。目录越大，延迟加载的价值才越明显：服务器更多、工具更多、schema 更大，或者上下文窗口本来会被撑爆。

<div id="authentication">
  ## 身份验证
</div>

与上面的 DeepWiki 服务器不同，大多数 MCP 服务器都需要身份验证。最常见的方式是使用 OAuth 访问令牌，将其传入 `mcp` 工具的 `authorization` 字段即可：

<CodeGroup>
  ```python Python theme={null}
  import os
  from perplexity import Perplexity

  client = Perplexity()

  response = client.responses.create(
      model="openai/gpt-5.6-sol",
      input="Use GitHub to find open issues about authentication in perplexityai/perplexity-py.",
      tools=[
          {
              "type": "mcp",
              "server_label": "github",
              "server_url": "https://api.githubcopilot.com/mcp/",
              "authorization": os.environ["GITHUB_MCP_TOKEN"],
              "allowed_tools": ["search_repositories", "list_issues", "issue_read"],
          }
      ],
  )

  print(response.output_text)
  ```

  ```typescript Typescript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  const response = await client.responses.create({
    model: 'openai/gpt-5.6-sol',

    tools: [
      {
        type: 'mcp',
        server_label: 'github',
        server_url: 'https://api.githubcopilot.com/mcp/',
        authorization: process.env.GITHUB_MCP_TOKEN,
        allowed_tools: ['search_repositories', 'list_issues', 'issue_read'],
      },
    ],
  });

  console.log(response.output_text);
  ```


<Info>
  本示例使用 [GitHub MCP 服务器](https://github.com/github/github-mcp-server)。请创建一个 [GitHub 个人访问令牌](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)，为其授予你希望 model 查看的仓库的访问权限，并将其导出为 `GITHUB_MCP_TOKEN`。
</Info>

<div id="parameters">
  ## 参数
</div>

| 参数              | 类型      | 是否必填 | 说明                                                                     |
| --------------- | ------- | ---- | ---------------------------------------------------------------------- |
| `type`          | string  | 是    | 必须为 `"mcp"`。                                                           |
| `server_label`  | string  | 是    | 在单个请求内唯一，需匹配 `^[a-zA-Z0-9_-]{1,64}$`。用于为该服务器的工具划分命名空间。                 |
| `server_url`    | string  | 是    | 远程 MCP 服务器的 HTTPS URL。必须是 Streamable HTTP MCP 端点；不支持旧版 SSE 传输。         |
| `authorization` | string  | 否    | 传递给远程 MCP 服务器用于身份验证的访问令牌。请填写原始令牌值。该值不会被记录或回显。                          |
| `headers`       | object  | 否    | 发送给 MCP 服务器的额外请求头 (取值为字符串) 。                                           |
| `allowed_tools` | array   | 否    | 向 model 开放的工具名称白名单。省略或留空则开放所有已发现的工具。                                   |
| `defer_loading` | boolean | 否    | 设为 `true` 时，已发现的工具定义不会进入初始 model 上下文，model 可按需加载相关 schema。默认为 `false`。 |

<div id="response-shape">
  ## 响应结构
</div>

使用 `mcp` 工具时，响应的 `output` 数组中除了最终的 `message` 项，还可能包含两种 MCP 专用的项类型：

* `mcp_list_tools` — 每个服务器发出一次，列出请求开始时发现的工具。
* `mcp_call` — model 在该服务器上每调用一个工具就发出一次。

若设置 `defer_loading: true`，当 model 在延迟加载的工具目录中执行搜索时，数组中还可能包含 `tool_search_output` 项。工具调用仍以 `mcp_call` 项的形式出现。

<div id="mcp_list_tools">
  ### `mcp_list_tools`
</div>

| 字段             | 类型     | 说明                        |
| -------------- | ------ | ------------------------- |
| `type`         | string | 始终为 `mcp_list_tools`。     |
| `id`           | string | 此输出项的标识符。                 |
| `server_label` | string | 你为该服务器指定的 `server_label`。 |
| `tools`        | array  | 在该服务器上发现的工具。              |
| `error`        | string | 成功列出服务器工具时不会出现该字段。        |

`tools` 中的每一项包含以下字段：

| 字段             | 类型     | 说明                             |
| -------------- | ------ | ------------------------------ |
| `name`         | string | 服务器对外暴露的工具名称。                  |
| `description`  | string | 来自服务器的工具描述。                    |
| `input_schema` | object | 服务器为该工具输入定义的 JSON Schema，原样透传。 |

<div id="mcp_call">
  ### `mcp_call`
</div>

| 字段             | 类型            | 说明                                               |
| -------------- | ------------- | ------------------------------------------------ |
| `type`         | string        | 始终为 `mcp_call`。                                  |
| `id`           | string        | 此输出项的标识符。                                        |
| `server_label` | string        | 运行该工具的服务器的 `server_label`。                       |
| `name`         | string        | 被调用工具的名称。                                        |
| `arguments`    | string        | model 传入的 JSON 编码参数。                             |
| `output`       | string        | 工具输出文本。调用失败时为空。                                  |
| `error`        | string | null | 成功时为 `null`。调用失败时存放失败信息字符串，该字符串同时也会在带内返回给 model。 |

<div id="tool_search_output">
  ### `tool_search_output`
</div>

仅在 `defer_loading: true` 时发出；model 每对延迟加载的目录执行一次搜索，就发出一条。

| 字段          | 类型     | 说明                                                        |                    |
| ----------- | ------ | --------------------------------------------------------- | ------------------ |
| `type`      | string | 始终为 `tool_search_output`。                                 |                    |
| `id`        | string | 该输出项的标识符。                                                 |                    |
| `call_id`   | string | null                                                      | 托管目录搜索时始终为 `null`。 |
| `execution` | string | 搜索的执行位置。目前始终为 `server` —— 请兼容其他取值。                        |                    |
| `status`    | string | 搜索状态，例如 `completed`。                                      |                    |
| `arguments` | string | model 生成的不透明搜索文本，也可能不存在。请将其视为非结构化内容，不要解析 —— 其格式不属于契约的一部分。 |                    |
| `tools`     | array  | 匹配到的工具，按服务器分组。未匹配到任何结果时为空。                                |                    |

`tools` 中的每一项对应一个服务器的命名空间：

| 字段            | 类型     | 说明                                                                                        |
| ------------- | ------ | ----------------------------------------------------------------------------------------- |
| `type`        | string | 始终为 `namespace`。                                                                          |
| `name`        | string | 这些工具所属服务器的 `server_label`。                                                                |

| `tools`       | array  | 匹配到的工具，每项包含 `type` (`function`) 、`name`、`description` 和 `parameters` (服务器的 JSON Schema) 。 |

<div id="error-handling">
  ## 错误处理
</div>

| 情况         | 你会看到什么                                                                                                                                                                                        |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **发现失败**   | 请求失败并返回 `external_connector_error` (HTTP `424 Failed Dependency`) ——无法列出该服务器的工具，因此本次运行根本不会开始，也不会返回 `output` 数组。错误体中的 `message` 会指明具体是哪个服务器，例如 `MCP server "github" could not be initialized`。 |
| **工具调用失败** | 对应 `mcp_call` 项的 `output` 为空，并带有 `error` 字符串。该失败还会以带内方式返回给 model，使其可以自行恢复，或在最终回答中加以说明。                                                                                                        |

如果服务器无法访问，或在运行开始时列举其工具时返回了不可用的响应，就会出现发现失败。由于发现过程先于 model 执行，整个请求会以 `external_connector_error` 失败，并且不返回 `output` 数组。

运行期间的工具调用失败不会导致请求失败。如上所述，错误会通过 `mcp_call` 项以带内方式返回给 model，因此 model 可以自行恢复，或在最终回答中加以说明。

<div id="risks-and-safety">
  ## 风险与安全
</div>

`mcp` 工具让你能够将 model 连接到外部服务——这是一项强大的能力，但也伴随着风险。远程 MCP 服务器属于第三方服务，未经 Perplexity 验证。它们可以让 model 读取、发送和接收数据，并在所连接的服务中执行操作，且每个服务器都受其自身的条款和条件约束。请仅连接你信任的服务器。

<Warning>
  Agent API **暂不**支持 MCP 审批。每一次 MCP 工具调用都会自动执行，因此请只连接你信任的 MCP 服务器，并只开放那些无需审批即可放心运行的工具。
</Warning>

使用 `allowed_tools` 限制 model 可调用哪些服务器工具。对于包含写入或管理操作的服务器，建议使用只读服务器模式、只读 token，或一份范围很小的只读工具允许列表。

<div id="limitations">
  ## 限制
</div>

`mcp` 工具向后兼容 OpenAI 的 Responses MCP API。以下 OpenAI MCP 功能暂不支持：

| 功能或字段                                            | 行为                                       |
| ------------------------------------------------ | ---------------------------------------- |
| `require_approval`                               | 忽略。每次 MCP 工具调用都会自动执行。                    |
| `mcp_approval_request` / `mcp_approval_response` | 既不发出也不接受。审批的暂停/继续流程暂不可用。                 |
| `connector_id` 及托管连接器目录                          | 忽略。仅支持自带的 `server_url`。                  |
| 连接器 OAuth 流程                                     | 不支持。请通过 `authorization` 将凭证传递给你自己的远程服务器。 |
| MCP 资源、提示词与采样                                    | 暂不支持；工具是目前唯一受支持的 MCP 能力。                 |
| MCP 输出项上的 `approval_request_id` 与 `status`       | MCP 输出项结构中不包含这些字段。                       |

<div id="pricing">
  ## 定价
</div>

MCP 工具调用免费——Agent API 不会因调用远程 MCP 服务器而收取按次调用费。模型 token 用量仍按 Agent API 的 token 定价单独计费 (各模型费率见 [Models](/zh/docs/agent-api/models)) ；远程 MCP 服务器由你自行运营，因此其产生的任何费用均不属于 Agent API 的计费范围。
