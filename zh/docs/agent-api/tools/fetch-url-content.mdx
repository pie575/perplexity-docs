<div id="overview">
  ## 概览
</div>

`fetch_url` 工具可在 Agent API 请求过程中抓取并提取指定 URL 的内容。如果你的应用已经明确知道模型该查看哪个页面、文章、文档或报告，就可以使用该工具。

需要从已知 URL 获取完整页面内容时，使用 `fetch_url`；需要让模型先找到相关页面时，则使用 [`web_search`](/zh/docs/agent-api/tools/web-search)。

<CodeGroup>
  ```python Python theme={null}
  from perplexity import Perplexity

  client = Perplexity()

  response = client.responses.create(
      model="openai/gpt-5.6-sol",
      input="Explain Bayesian inference: how prior beliefs are updated to posterior beliefs given new evidence, with a concrete medical-test example.",
      tools=[
          {
              "type": "fetch_url"
          }
      ],
      instructions="Fetch the URL before summarizing it.",
  )

  print(response.output_text)
  ```

  ```typescript Typescript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  const response = await client.responses.create({
    model: 'openai/gpt-5.6-sol',
    input: 'Explain Bayesian inference: how prior beliefs are updated to posterior beliefs given new evidence, with a concrete medical-test example.',
    tools: [
      {
        type: 'fetch_url' as const,
      },
    ],
    instructions: 'Fetch the URL before summarizing it.',
  });

  console.log(response.output_text);
  ```

  ```bash cURL theme={null}
  curl https://api.perplexity.ai/v1/agent \
    -H "Authorization: Bearer $PERPLEXITY_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "model": "openai/gpt-5.6-sol",
      "input": "Explain Bayesian inference: how prior beliefs are updated to posterior beliefs given new evidence, with a concrete medical-test example.",
      "tools": [
        {
          "type": "fetch_url"
        }
      ],
      "instructions": "Fetch the URL before summarizing it."
    }' | jq
  ```
</CodeGroup>

<div id="when-to-use">
  ## 使用场景
</div>

| 何时使用 `fetch_url`… | 何时使用 `web_search`… |
| ----------------- | ------------------ |
| 你已经有了 URL         | 你需要找到相关页面          |
| 你需要更完整的页面内容       | 你需要多个来源的摘要片段       |
| 你要总结某篇特定的文章或文档    | 你在研究某个宽泛的主题        |
| 你希望模型查看某个已知来源     | 你希望模型查找最新来源        |

<Tip>
  将 `web_search` 与 `fetch_url` 结合用于多步研究：先搜索找到相关页面，再抓取其中最重要的 URL 以获取更完整的上下文。
</Tip>

  ## 错误处理
</div>

`fetch_url` 采用尽力而为的策略。当某个 URL 无法完整抓取或提取时,API 仍可返回一个已完成的 Agent API 响应,并在最终的助手消息中说明实际获取到了哪些内容。请逐项检查 `fetch_url_results.contents`:成功的条目包含提取到的页面文本,失败的条目则会在所请求 URL 的 `snippet` 中给出明确的标记。

失败标记会说明已知原因,例如 HTTP 客户端错误、robots 策略拦截或速率限制。如果上游抓取未针对某个请求的 URL 返回任何条目,API 会补充一个 snippet 中包含 `no_result_returned` 的条目。请将这些标记视为内容不可用,而不要当作页面文本处理。

| 情况               | 响应行为                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------- |
| **付费墙与登录墙**      | `fetch_url` 不会绕过访问控制。对应的内容项会包含失败标记,说明源站拒绝了该请求,可能需要凭据或非 GET 方法。                        |
| **重定向**          | 当目标地址可以抓取时,会跟随 HTTP 重定向。在返回的 `fetch_url_results` 条目中,`url` 字段反映的是你请求的 URL,而非最终的重定向目标。  |
| **非 HTML 内容**    | `fetch_url` 会提取服务器在该 URL 上返回的任何文本内容。对于 PDF、二进制下载,以及返回反爬虫验证页面的 URL,提取到的内容可能很有限,甚至与预期无关。 |
| **超时与无法访问的 URL** | 对应的内容项会包含失败标记,并附上已知原因。如果上游未返回任何结果,该标记会包含 `no_result_returned`。                        |

<div id="limits-quotas">
  ## 限制 / 配额
</div>

使用 `max_urls` 可将抓取数量控制在可控、可预期的范围内。URL 越少，延迟通常越低，也能为 model 的推理和最终回答留出更多上下文空间。

| 限制                  | 值                                                                                          |
| ------------------- | ------------------------------------------------------------------------------------------ |
| **每次工具调用的最大 URL 数** | `max_urls` 可设置为 1 到 10。                                                                    |
| **支持的 URL 协议**      | 请使用绝对路径的 `http://` 或 `https://` URL。其他协议 (`file:`、`data:`、`ftp:`、浏览器扩展 URL) 不受支持，无法获得可用内容。 |
| **内容大小**            | 抓取到的内容会被提取为摘要片段供 model 用作上下文，较长的页面可能会被截断。                                                    |

  ## 定价

</Note>
