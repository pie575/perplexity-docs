<div id="overview">
  ## 概述
</div>

`web_search` 工具可让模型在 Agent API 请求过程中搜索网络。当你需要最新信息、近期新闻、有来源支撑的研究，或问题超出模型训练数据范围时，都可以使用该工具。

只需将该工具添加到 `tools` 数组即可启用。模型会根据你的提示词和指令自行决定何时调用它。

<CodeGroup>
  ```python Python theme={null}
  from perplexity import Perplexity

  client = Perplexity()

  response = client.responses.create(
      model="openai/gpt-5.6-sol",
      input="Explain the architecture of NVIDIA's CUDA programming model: threads, blocks, grids, warps, and memory hierarchy, and how they enable GPU parallelism.",
      tools=[
          {
              "type": "web_search",
              "search_context_size": "medium"
          }
      ],
      instructions="Search for current, source-grounded information before answering.",
  )

  print(response.output_text)
  ```

  ```typescript Typescript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  const response = await client.responses.create({
    model: 'openai/gpt-5.6-sol',
    input: 'Explain the architecture of NVIDIA\'s CUDA programming model: threads, blocks, grids, warps, and memory hierarchy, and how they enable GPU parallelism.',
    tools: [
      {
        type: 'web_search' as const,
        search_context_size: 'medium',
      },
    ],
    instructions: 'Search for current, source-grounded information before answering.',
  });

  console.log(response.output_text);
  ```

      "model": "openai/gpt-5.6-sol",

      "tools": [
        {
          "type": "web_search",
          "search_context_size": "medium"
        }
      ],
      "instructions": "Search for current, source-grounded information before answering."
    }' | jq

<div id="using-recommended-token-budgets">
  ### 使用推荐的 token 预算
</div>

通过 `search_context_size` 设置搜索上下文规模时，建议先从 `low`、`medium` 或 `high` 入手。每个命名规模都对应一组推荐的 `max_tokens` 与 `max_tokens_per_page` 预算，适合作为大多数应用的默认配置。

| `search_context_size` | `max_tokens` | `max_tokens_per_page` | 适用场景            |
| --------------------- | ------------ | --------------------- | --------------- |
| `low`                 | 300          | 300                   | 简单事实与轻量查询       |
| `medium`              | 1,000        | 1,000                 | 常规调研与产品对比       |
| `high`                | 4,000        | 4,000                 | 需大量引用来源的回答与复杂调研 |

<Note>
  这些 token 预算映射反映的是 Perplexity 当前推荐的默认值；随着我们根据最新评测结果发布新的配置，这些值可能会发生变化。指定某个命名规模时，始终会解析为当前推荐的预算。
</Note>

<div id="advanced-token-budget-configuration">
  ### 高级 token 预算配置
</div>

当你需要为成本控制、延迟控制或评估设定精确的预算上限时，请使用显式的 token 预算配置。通过 `max_tokens` 限制所有结果的搜索上下文总量，通过 `max_tokens_per_page` 限制从每个结果页面中提取的内容量。显式预算会覆盖同一请求中传入的 `search_context_size` 值；计费按实际消耗的搜索上下文 token 数计算，而非按请求的预算值计算。

</Note>

<div id="filters">
  ## 过滤器
</div>

使用过滤器可以限定 `web_search` 所使用的来源、日期和位置上下文。

| 过滤器                          | 类型    | 说明                                                     |
| ---------------------------- | ----- | ------------------------------------------------------ |
| `search_domain_filter`       | 字符串数组 | 包含或排除最多 20 个域名或 URL。条目前加 `-` 表示排除。                     |
| `search_recency_filter`      | 字符串   | 将结果限制为 `"hour"`、`"day"`、`"week"`、`"month"` 或 `"year"`。 |
| `search_after_date_filter`   | 字符串   | 仅包含在指定日期之后发布的结果，日期格式为 MM/DD/YYYY。                      |
| `search_before_date_filter`  | 字符串   | 仅包含在指定日期之前发布的结果，日期格式为 MM/DD/YYYY。                      |
| `last_updated_after_filter`  | 字符串   | 仅包含在指定日期之后最后更新的结果，日期格式为 MM/DD/YYYY。                    |
| `last_updated_before_filter` | 字符串   | 仅包含在指定日期之前最后更新的结果，日期格式为 MM/DD/YYYY。                    |
| `user_location`              | 对象    | 按国家、地区、城市、纬度和经度个性化搜索结果。                                |

<div id="domain-filter">
  ### 域名过滤器
</div>

<Warning>
  使用 `search_domain_filter` 时，只能选择允许列表模式或拒绝列表模式，不可同时使用。域名过滤器最多支持 20 个域名或 URL。例如，`["nasa.gov", "wikipedia.org"]` 表示仅包含这些域名，而 `["-reddit.com", "-pinterest.com"]` 则表示排除这些域名。
</Warning>

条目可以是域名级别 (例如 `wikipedia.org`) ，也可以是 URL 级别 (例如 `https://en.wikipedia.org/wiki/Chess`) ，以实现更精细的控制。

<div id="recency-filter">
  ### 时效性过滤器
</div>

`search_recency_filter` 会将每个取值映射为一个相对时间窗口：

| 取值      | 时间窗口                         |
| ------- | ---------------------------- |
| `hour`  | 过去 1 小时 —— 适用于突发新闻、现场活动等实时数据 |
| `day`   | 过去 24 小时                     |
| `week`  | 过去 7 天                       |
| `month` | 过去 30 天                      |
| `year`  | 过去 365 天                     |

如需精确的时间范围，请使用 `search_after_date_filter` / `search_before_date_filter` (发布日期) 或 `last_updated_after_filter` / `last_updated_before_filter` (最后更新时间) 。日期过滤器的取值必须采用 `MM/DD/YYYY` 格式 (例如 `"03/01/2026"`) 。

<div id="location-filter">
  ### 位置过滤器
</div>

`user_location` 接受以下字段的任意组合：

* `country` —— 两位字母的 [ISO 3166-1 alpha-2](https://en.wikipedia.org/wiki/ISO_3166-1_alpha-2) 国家代码 (例如 `"US"`、`"FR"`) 。
* `region` —— 地区或州名 (例如 `"California"`) 。
* `city` —— 城市名 (例如 `"San Francisco"`) 。
* `latitude` 和 `longitude` —— 用于精确定位的坐标。

<Tip>
  `city` 和 `region` 能显著提升定位精度，请尽可能与 `country` 一同提供。
</Tip>

<Warning>
  `latitude` 和 `longitude` 必须与 `country` 一起提供，不能单独使用。
</Warning>

<div id="filter-usage-cheatsheet">
  ### 过滤器使用速查表
</div>

将以下任意代码片段复制到 `web_search` 工具对象中。`user_location` 与 `filters` 平级，其余控制项则位于 `filters` 内部。

| 过滤器      | 示例                                                                                                               |
| -------- | ---------------------------------------------------------------------------------------------------------------- |
| 域名允许列表   | `filters: { search_domain_filter: ["docs.perplexity.ai", "developer.mozilla.org"] }`                             |
| 域名拒绝列表   | `filters: { search_domain_filter: ["-reddit.com", "-pinterest.com"] }`                                           |
| 时效性      | `filters: { search_recency_filter: "week" }`                                                                     |
| 发布日期范围   | `filters: { search_after_date_filter: "01/01/2026", search_before_date_filter: "05/01/2026" }`                   |
| 最后更新时间范围 | `filters: { last_updated_after_filter: "01/01/2026", last_updated_before_filter: "05/01/2026" }`                 |
| 用户位置     | `user_location: { country: "US", region: "CA", city: "San Francisco", latitude: 37.7749, longitude: -122.4194 }` |

<Tip>
  过滤器可自由组合。你可以在同一个 `web_search` 工具对象中同时使用上述来源、日期、时效性和位置过滤器——单次请求的过滤器组合数量不受限制。
</Tip>

<div id="response-shape">
  ## 响应结构
</div>

`web_search` 运行时，响应可能会在最终的 assistant 消息之前包含一个 `search_results` 输出项。最终的 `usage` 对象包含 token 计数、费用明细；若报告了工具调用用量，还会包含 `tool_calls_details.search_web.invocation`。

```json theme={null}
{
  "output": [
    {
      "type": "search_results",
      "queries": ["AI infrastructure announcements"],
      "results": [
        {
          "id": 1,
          "url": "https://example.com/news",
          "title": "Example AI infrastructure announcement",
          "snippet": "A short snippet from the search result.",
          "date": "2026-05-01",
          "last_updated": "2026-05-01",
          "source": "web"
        }
      ]
    },
    {
      "type": "message",
      "role": "assistant",
      "content": [
        {
          "type": "output_text",
          "text": "The answer generated from the search results."
        }
      ]
    }
  ],
  "usage": {
    "input_tokens": 1200,
    "output_tokens": 300,
    "total_tokens": 1500,
    "tool_calls_details": {
      "search_web": {
        "invocation": 1
      }
    }
  }
}
```

`results` 中的每一项都包含以下字段：

| 字段             | 类型      | 说明                          |
| -------------- | ------- | --------------------------- |
| `id`           | integer | 稳定索引，用于在引用中指向该结果。           |
| `url`          | string  | 来源页面的规范 URL。                |
| `title`        | string  | 来源返回的页面标题。                  |
| `snippet`      | string  | 搜索时从页面中提取的摘录文本。             |
| `date`         | string  | 页面首次发布的日期，格式为 `YYYY-MM-DD`。 |
| `last_updated` | string  | 页面最近更新的日期，格式为 `YYYY-MM-DD`。 |
| `source`       | string  | 结果的来源 (例如 `"web"`) 。        |

<Tip>
  **需要行内引用？** model 是否会在回答中添加引用标记取决于提示词，因此请明确提出要求——例如在提示词末尾追加：*&quot;使用方括号标记进行行内引用，每个方括号只放一个来源，形如 `[1][2]`。&quot;* 其中每个数字对应某个结果的 `id`。无论是否带有标记，都应以每个 `search_results` 条目的 `id` 和 `url` 字段作为引用的权威依据。
</Tip>

<div id="pricing">
  ## 定价
</div>

`web_search` 的计费标准为 **每 1,000 次调用 $2.50**。模型 token 用量则按 Agent API 的 token 定价单独计费。

<Note>
  其定价方式与其他工具调用一致：既要支付工具调用费用，也要支付模型 token 费用。参见[定价](/zh/docs/getting-started/pricing)。
</Note>

<div id="limits-quotas">
  ## 限制 / 配额
</div>

`web_search` 在 Agent API 请求内部运行，受 Agent API 请求速率限制的约束。有关当前基于层级的 Agent API 限制，请参阅[速率限制与使用层级](/zh/docs/admin/rate-limits-usage-tiers#agent-api-rate-limits)。

| 限制      | 适用对象                                                     | 说明                                                                  |
| ------- | -------------------------------------------------------- | ------------------------------------------------------------------- |
| 速率限制    | 包含 `web_search` 的 Agent API 请求                           | 该请求适用 Agent API 层级限制。生产流量请添加重试与退避处理。                                |
| 域名条目    | `search_domain_filter`                                   | 每次请求最多 20 个域名或 URL。请按[过滤器](#filters)一节警告中的说明，选择允许列表或拒绝列表模式之一。       |
| 搜索上下文预算 | `search_context_size`、`max_tokens`、`max_tokens_per_page` | `search_context_size` 预设会自动管理上下文。如需更严格地控制成本或延迟，请显式设置 token 上限。 |
| 工具调用计费  | `web_search` 调用                                          | 每次搜索调用都计入工具调用用量与费用，与模型 token 用量分开计算。                                |
