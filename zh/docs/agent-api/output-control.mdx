<div id="streaming-responses">
  ## 流式响应
</div>

借助流式传输，你可以在 Perplexity API 生成内容的同时逐步接收部分响应，而不必等待完整响应返回。这对实时用户体验、长响应以及交互式应用尤为有用。

<Info>
  Agent API 中可用的所有模型均支持流式传输。
</Info>

要启用流式传输，请在创建响应时设置 `stream=True` (Python) 或 `stream: true` (TypeScript) ：

<CodeGroup>
  ```python Python SDK theme={null}
  from perplexity import Perplexity

  client = Perplexity()

  # 创建流式响应
  stream = client.responses.create(
      preset="fast",
      input="Explain what a model card is in the context of large language models: the typical sections (intended use, training data, limitations, evaluation).",
      stream=True
  )

  # 处理流式响应
  for event in stream:
      if event.type == "response.output_text.delta":
          print(event.delta, end="")
      elif event.type == "response.completed":
          print(f"\n\nCompleted: {event.response.usage}")
  ```

  ```typescript TypeScript SDK theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  // 创建流式响应
  const stream = await client.responses.create({
    preset: "fast",
    input: "Explain what a model card is in the context of large language models: the typical sections (intended use, training data, limitations, evaluation).",
    stream: true
  });

  // 处理流式响应
  for await (const chunk of stream) {
    if (chunk.type === "response.output_text.delta") {
      process.stdout.write((chunk as any).delta);
    }
  }
  ```

  ```bash cURL theme={null}
  curl -X POST "https://api.perplexity.ai/v1/agent" \
    -H "Authorization: Bearer $PERPLEXITY_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "preset": "fast",
      "input": "Explain what a model card is in the context of large language models: the typical sections (intended use, training data, limitations, evaluation).",
      "stream": true
    }'
  ```
</CodeGroup>

  ```bash cURL theme={null}
  curl https://api.perplexity.ai/v1/agent/$RESPONSE_ID \
    -H "Authorization: Bearer $PERPLEXITY_API_KEY"
  ```
</CodeGroup>

后台运行具有持久性，因此你也可以实时流式接收，并在断线后重新连接。请求 `GET /v1/agent/{id}?stream=true&starting_after=N`，即可从序号 `N` 之后的事件继续接收。重连仅在该响应的重连窗口内有效；窗口过期后，该端点会返回 `400`，此时可改用普通的 `GET /v1/agent/{id}` 获取最终快照。详见 [Agent API 参考](/zh/api-reference/agent-post)。

<div id="structured-outputs">
  ## 结构化输出
</div>

结构化输出让你能够强制 Perplexity 的模型按指定格式返回响应，从而获得一致且机器可读的数据，无需手动解析即可直接集成到你的应用中。

我们目前支持 **JSON Schema** 结构化输出。要启用结构化输出，请在请求中添加 `response_format` 字段：

```json theme={null}
{
  "response_format": {
    "type": "json_schema",
    "json_schema": {
      "name": "your_schema_name",
      "schema": { /* 你的 JSON Schema 对象 */ }
    }
  }
}
```

`name` 字段为必填项，且必须为 1 至 64 个字母数字字符。schema 应为有效的 JSON schema 对象。除非输出超出 `max_tokens`，否则 LLM 的响应将符合指定格式。

schema 的 `required` 数组中列出的属性在输出中必须出现。凡是已声明但未列入 `required` 的属性均为可选，其值可能为 JSON `null`。如果 `required` 被省略或为空，则所有已声明的属性都是可选的。在 `/v1/agent` 及其兼容别名 `/v1/responses` 上，流式与非流式请求的行为均是如此。

<Tip>
  **提升 schema 遵循度**：在提示词中对输出格式给出一些提示，有助于提高对结构化格式的遵循度。例如，加入“请以如下结构的 JSON 对象返回数据……”或“提取信息并按 schema 中指定的格式输出。”之类的表述。
</Tip>

<Info>
  使用新 JSON Schema 的首次请求预计会在首个 token 上出现延迟。准备新 schema 通常需要 10 到 30 秒，可能导致超时错误。schema 准备完成后，后续请求就不会再有此类延迟。
</Info>
