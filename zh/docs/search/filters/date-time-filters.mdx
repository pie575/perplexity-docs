title: "搜索日期与时间过滤器"
---

<Note>
  `search_after_date_filter` 和 `search_before_date_filter` 参数可将搜索结果限制在特定的发布日期范围内，只有发布日期落在这两个日期之间的结果才会返回。

  `last_updated_after_filter` 和 `last_updated_before_filter` 参数则按内容最后一次修改或更新的时间进行筛选，而非按最初发布的时间。

  `search_recency_filter` 参数提供了一种便捷方式，可按相对于当前日期的预定义时间段 (例如 &quot;hour&quot;、&quot;day&quot;、&quot;week&quot;、&quot;month&quot;、&quot;year&quot;) 筛选结果。
</Note>

<Info>
  具体日期过滤器必须使用 &quot;%m/%d/%Y&quot; 格式 (例如 &quot;3/1/2025&quot;) 。时效性过滤器使用 &quot;hour&quot;、&quot;day&quot;、&quot;week&quot;、&quot;month&quot; 或 &quot;year&quot; 等预定义值。所有过滤器均为可选——你可以根据需要提供具体日期或时效性过滤器。
</Info>

<div id="overview">
  ## 概览
</div>

Search API 的日期与时间过滤器可将搜索结果限定在特定时间范围内，从而控制返回哪些结果。共有三类日期与时间过滤器可用：

<div id="publication-date-filters">
  ### 发布日期过滤器
</div>

`search_after_date_filter` 和 `search_before_date_filter` 参数根据内容**最初创建或发布**的时间来筛选结果。它适用于以下场景：

* 查找在特定时间范围内发布的内容
* 排除过于陈旧或过于新近的内容
* 聚焦于某一特定发布时期的内容

<div id="last-updated-date-filters">
  ### 最后更新日期过滤器
</div>

`last_updated_after_filter` 和 `last_updated_before_filter` 参数用于按内容的**最后修改或更新**时间过滤结果。它适用于以下场景：

* 查找近期更新或持续维护的内容
* 排除长期未更新的陈旧内容
* 只关注在特定时间段内更新过的内容

<div id="search-recency-filter">
  ### 搜索时效性过滤器
</div>

`search_recency_filter` 参数提供了一种简单的方式，可按相对于当前日期的预定义时间段过滤结果。它适用于以下场景：

* 查找过去一小时、一天、一周、一个月或一年内的内容
* 无需指定具体日期即可获取最新结果
* 快速筛选出时效性强的信息

**可用取值：**

* `"hour"` —— 过去一小时内的内容。适用于突发新闻、实时事件等实时性数据。
* `"day"` —— 过去 24 小时内的内容
* `"week"` —— 过去 7 天内的内容
* `"month"` —— 过去 30 天内的内容
* `"year"` —— 过去 365 天内的内容

**重要提示：** 发布日期过滤器依据内容的原始创建/发布日期，最后更新过滤器依据修改日期，而时效性过滤器依据的是相对于当前日期的时间段。

按发布日期限定搜索结果：

```bash theme={null}
"search_after_date_filter": "3/1/2025",
"search_before_date_filter": "3/5/2025"
```

若要按最后更新日期筛选搜索结果：

```bash theme={null}
"last_updated_after_filter": "07/01/2025",
"last_updated_before_filter": "12/30/2025"
```

若要按时间范围限制搜索结果：

```bash theme={null}
"search_recency_filter": "week"
```

这些过滤器会在其他搜索参数的基础上叠加生效。

<div id="search_after_date_filter">
  ### `search_after_date_filter`
</div>

* **类型**：字符串
* **格式**：&quot;%m/%d/%Y&quot; (例如 &quot;3/1/2025&quot;) 
* **说明**：过滤搜索结果，仅返回在该日期之后发布的内容
* **是否可选**：是
* **示例**：`"search_after_date_filter": "1/1/2025"`

<div id="search_before_date_filter">
  ### `search_before_date_filter`
</div>

* **类型**：字符串
* **格式**：&quot;%m/%d/%Y&quot; (例如 &quot;3/1/2025&quot;) 
* **说明**：筛选搜索结果，仅返回在该日期之前发布的内容
* **可选**：是
* **示例**：`"search_before_date_filter": "12/31/2025"`

<div id="last_updated_after_filter">
  ### `last_updated_after_filter`
</div>

* **类型**：字符串
* **格式**：&quot;%m/%d/%Y&quot; (例如 &quot;07/01/2025&quot;) 
* **说明**：仅返回最后更新时间晚于该日期的搜索结果
* **可选**：是
* **示例**：`"last_updated_after_filter": "07/01/2025"`

<div id="last_updated_before_filter">
  ### `last_updated_before_filter`
</div>

* **类型**：字符串
* **格式**：&quot;%m/%d/%Y&quot; (例如 &quot;12/30/2025&quot;) 
* **说明**：筛选搜索结果，仅返回最后更新时间早于该日期的内容
* **可选**：是
* **示例**：`"last_updated_before_filter": "12/30/2025"`

<div id="search_recency_filter">
  ### `search_recency_filter`
</div>

* **类型**：字符串
* **允许的值**：&quot;hour&quot;、&quot;day&quot;、&quot;week&quot;、&quot;month&quot;、&quot;year&quot;
* **说明**：仅返回相对于当前日期的指定时间范围内的搜索结果
* **可选**：是
* **示例**：`"search_recency_filter": "week"`

<div id="best-practices">
  ## 最佳实践
</div>

**日期格式**

* 严格格式：日期必须完全符合 &quot;%m/%d/%Y&quot; 格式。例如 &quot;3/1/2025&quot; 或 &quot;03/01/2025&quot; 都可接受。
* 保持一致：根据搜索需求，统一使用其中一个或两个日期过滤器。两者结合可明确界定时间范围。

**过滤器选择**

* 选择合适的过滤器类型：如果关注内容最初的创建时间，使用发布日期过滤器 (`search_after_date_filter`/`search_before_date_filter`) ；如果需要近期维护过的内容，使用最后更新过滤器 (`last_updated_after_filter`/`last_updated_before_filter`) ；如需快速按相对时间过滤，使用时效性过滤器 (`search_recency_filter`) 。
* 时效性与精确日期：只想获取近期内容 (例如“过去一周”) 时，用 `search_recency_filter` 更为便捷；需要精确控制时间范围时，则使用具体的日期过滤器。
* 组合使用过滤器：可以同时使用发布日期过滤器和最后更新过滤器，查找同时满足两类条件的内容 (例如 2024 年发布但近期有更新) 。请注意，`search_recency_filter` 不能与具体日期过滤器 (`search_after_date_filter`/`search_before_date_filter` 或 `last_updated_after_filter`/`last_updated_before_filter`) 组合使用。

**客户端校验**

* 正则校验：在客户端使用如下正则表达式校验日期字符串：

<CodeGroup>
  ```bash theme={null}
  date_regex='^(0?[1-9]|1[0-2])/(0?[1-9]|[12][0-9]|3[01])/[0-9]{4}$'
  ```

  ```python theme={null}
  date_regex = r'^(0?[1-9]|1[0-2])/(0?[1-9]|[12]\d|3[01])/\d{4}$'
  ```
</CodeGroup>

这样可以确保在发送请求前日期符合所需格式。

**性能考量**

* 缩小搜索范围：使用日期范围过滤器通常会减少结果数量，从而有助于提升响应速度和结果相关性。
* 避免过度限制：确保日期范围既不过窄 (导致有用结果被排除) ，也不过宽 (使过滤失去意义) 。

<div id="advanced-usage-patterns">
  ## 高级用法模式
</div>

**查找突发新闻**

针对实时事件，可将 `search_recency_filter` 设为 `"hour"`；若要获取最新的突发新闻，则设为 `"day"`：

```python theme={null}
# 直播事件与实时数据
response = client.search(
    query="Apollo 11 moon landing mission overview",
    max_results=5,
    search_recency_filter="hour"

# 过去 24 小时内的突发新闻
response = client.search(

    search_recency_filter="day"
)
```

  ```python Python theme={null}
  from perplexity import Perplexity
  import re

  def validate_date_format(date_string):
      pattern = r'^(0?[1-9]|1[0-2])/(0?[1-9]|[12]\d|3[01])/\d{4}$'
      return bool(re.match(pattern, date_string))

  def search_with_date_filter(query, after_date=None, before_date=None):
      client = Perplexity()
      
      # 校验日期格式
      if after_date and not validate_date_format(after_date):
          raise ValueError(f"Invalid date format: {after_date}")
      if before_date and not validate_date_format(before_date):
          raise ValueError(f"Invalid date format: {before_date}")
      
      try:
          response = client.search(
              query=query,
              search_after_date_filter=after_date,
              search_before_date_filter=before_date
          )
          return response
      except Exception as e:
          print(f"Search failed: {e}")
          return None
  ```

  ```typescript Typescript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  function validateDateFormat(dateString: string): boolean {
    const pattern = /^(0?[1-9]|1[0-2])\/(0?[1-9]|[12]\d|3[01])\/\d{4}$/;
    return pattern.test(dateString);
  }

  async function searchWithDateFilter(
    query: string, 
    afterDate?: string, 
    beforeDate?: string
  ) {
    const client = new Perplexity();
    
    // 校验日期格式
    if (afterDate && !validateDateFormat(afterDate)) {
      throw new Error(`Invalid date format: ${afterDate}`);
    }
    if (beforeDate && !validateDateFormat(beforeDate)) {
      throw new Error(`Invalid date format: ${beforeDate}`);
    }
    
    try {
      const response = await client.search.create({
        query,
        search_after_date_filter: afterDate,
        search_before_date_filter: beforeDate
      });
      return response;
    } catch (error) {
      console.error('Search failed:', error);
      return null;
    }
  }
  ```
