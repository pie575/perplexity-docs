<div id="overview">
  ## 概要
</div>

Pro Search 分類器 は、クエリが Pro Search の高度な多段階のツール利用を必要とするのか、標準の Fast Search でも十分に回答できるのかを自動で判定するインテリジェントなシステムです。これにより、パフォーマンス要件とコスト効率のバランスを取りやすくなります。

<Info>
  `"pro"` と `"fast"` の検索タイプを手動で選択する代わりに、`"auto"` を指定すれば、クエリごとに分類器が最適な判断を行います。
</Info>

<div id="how-it-works">
  ## 仕組み
</div>

`search_type: "auto"` を設定すると、分類器が複数の観点からクエリを分析します。

<Steps>
  <Step title="クエリの複雑度分析">
    分類器は次の点を評価します。

    * サブクエリや論点の数
    * 比較分析が必要かどうか
    * 多段階の推論が必要かどうか
    * 求められる情報統合の複雑さ

    ```json theme={null}
    {
      "web_search_options": {
        "search_type": "auto"  // 分類器に判断を任せる
      }
    }
    ```
  </Step>

  <Step title="分類の判断">
    分析結果に基づき、分類器はクエリを次のいずれかにルーティングします。

    * **Pro Search**: 多段階のツール利用を要する複雑で多面的なクエリ向け
    * **Fast Search**: 単純な情報検索向け

    この判断はレスポンスのメタデータで確認できます。
  </Step>

  <Step title="実行">
    選択された検索モードがクエリを処理します。

    * **Pro Search**: 組み込みツール (web&#95;search、fetch&#95;url&#95;content) を自動的に使用します
    * **Fast Search**: 最適化されたシングルパスの検索と統合を実行します

    どちらのモードが使われた場合でも、同じ高品質なレスポンス形式が返されます。
  </Step>
</Steps>

<div id="classification-patterns">
  ## 分類パターン
</div>

<div id="queries-classified-as-pro-search">
  ### Pro Search に分類されるクエリ
</div>

多段階のツール利用が有効な複雑なクエリは、自動的に Pro Search にルーティングされます。

<AccordionGroup>
  <Accordion title="複数の要素を含む質問">
    **クエリ例:**
    「React、Vue、Angular の違いを、パフォーマンス、学習コスト、エコシステムの観点から教えてください。大規模なエンタープライズアプリケーションにはどれを選ぶべきですか?」

    **Pro Search になる理由:**

    * 3 つの異なるフレームワークに関する情報が必要
    * 複数の観点にまたがる比較分析が必要
    * 専門家の意見や推奨事項の収集を伴う
    * 多様な情報源の統合が有効

    **ツールの利用:**

    * 各フレームワークに対する複数回のウェブ検索
    * ベンチマークデータや公式ドキュメントの URL 取得
  </Accordion>

  <Accordion title="研究内容の統合">
    **クエリ例:**
    「減量と代謝の健康に対する間欠的断食の有効性について、最新の査読済み研究をまとめてください。サンプルサイズと研究の限界も含めてください。」

    **Pro Search になる理由:**

    * 複数の研究論文を探し出す必要がある
    * 要旨だけでなく論文全文へのアクセスが必要
    * 特定のデータ(サンプルサイズ、限界)の抽出を伴う
    * 複数の研究をまたいだ統合が必要

    **ツールの利用:**

    * 最近の査読済み論文のウェブ検索
    * 論文全文を読むための `fetch_url_content`
    * 情報の抽出と統合
  </Accordion>

  <Accordion title="速報性の高い複雑な分析">
    **クエリ例:**
    「連邦準備制度による直近の金利決定が株式市場に与えた影響を、セクターごとの影響と次四半期に関する専門家の予測を含めて分析してください。」

    **Pro Search になる理由:**

    * 非常に新しい情報が必要
    * 複数の情報源による検証が必要
    * セクターごとの分析を伴う
    * 専門家の意見の収集が有効

    **ツールの利用:**

    * 対象を絞った複数回のウェブ検索
    * 金融分析レポートの URL 取得
    * 多様な専門家の意見の統合
  </Accordion>
</AccordionGroup>

<div id="queries-classified-as-fast-search">
  ### Fast Search に分類されるクエリ
</div>

多段階の推論を必要としない単純なクエリは、Fast Search で効率的に処理されます。

<AccordionGroup>
  <Accordion title="単純な事実に関する質問">
    **クエリ例:**
    「フランスの首都はどこですか?」

    **Fast Search になる理由:**

    * 単一かつ確立された事実である
    * 計算や分析が不要
    * 検索スニペットからすぐに得られる情報

    **処理内容:**

    * ウェブ検索を1回実行
    * 検索結果から直接回答
    * 多段階の推論が不要
  </Accordion>

  <Accordion title="単純な情報の取得">
    **クエリ例:**
    「iPhone 15 Pro の主な機能は何ですか?」

    **Fast Search になる理由:**

    * 単一の製品に関する問い合わせ
    * 製品説明から得られる情報
    * 比較分析が不要
    * 計算が不要

    **処理内容:**

    * 製品仕様を検索
    * 機能を抽出して列挙
    * 検索結果をもとに情報を統合
  </Accordion>

  <Accordion title="単一トピックのクエリ">
    **クエリ例:**
    「機械学習とは何か説明してください。」

    **Fast Search になる理由:**

    * 単一の概念の定義
    * 複数の要素に分けた分析が不要
    * 標準的な情報がすぐに入手可能

    **処理内容:**

    * 機械学習の説明を検索
    * 明確な定義をまとめる
    * 信頼できる情報源から背景情報を提供
  </Accordion>

  <Accordion title="基本的な定義の問い合わせ">
    **クエリ例:**
    「API は何の略で、何に使われますか?」

    **Fast Search になる理由:**

    * 単純な定義の問い合わせ
    * 複雑な分析が不要
    * 情報がすぐに入手可能

    **処理内容:**

    * API の定義をすばやく検索
    * 略語と基本的な用途を説明
    * 明確で簡潔な回答を提供
  </Accordion>
</AccordionGroup>

<div id="pricing-comparison">
  ### 料金の比較
</div>

**Pro Search の料金:**

* 入力: 100万 token あたり $3
* 出力: 100万 token あたり $15
* リクエスト料金: 1,000 リクエストあたり $14〜$22 (コンテキストサイズに応じて変動)

**Fast Search の料金:**

* 入力: 100万 token あたり $3
* 出力: 100万 token あたり $15
* リクエスト料金: 1,000 リクエストあたり $6〜$14 (コンテキストサイズに応じて変動 - 標準の Sonar Pro と同じ)

<Tip>
  自動分類器は、Pro Search の高度な機能が本当に必要な場合にのみ Pro Search を使用することでコストを抑えつつ、複雑なクエリに対しては多段階のツール利用を確実に実行します。
</Tip>

  ### 自動分類の使用

<CodeGroup>
  ```python Python SDK theme={null}
  from perplexity import Perplexity

  client = Perplexity()
  # 分類器に判断を任せる
  response = client.chat.completions.create(
      model="sonar-pro",
      messages=[
          {
              "role": "user",
              "content": "Compare the energy efficiency (kWh/100mi and MPGe) of the Tesla Model 3, Chevrolet Bolt, and Nissan Leaf using EPA data."
          }
      ],
      stream=True,
      web_search_options={
          "search_type": "auto"  # 自動分類
      }
  )

  for chunk in response:
      if chunk.choices[0].delta.content:
          print(chunk.choices[0].delta.content, end="")
  ```

  ```typescript Typescript SDK theme={null}
  import { Perplexity } from '@perplexity-ai/sdk';

  const client = new Perplexity();

  // 分類器に判断を任せる
  const response = await client.chat.completions.create({
    model: 'sonar-pro',
    messages: [
      {
        role: 'user',
        content: 'Compare the energy efficiency (kWh/100mi and MPGe) of the Tesla Model 3, Chevrolet Bolt, and Nissan Leaf using EPA data.'
      }
    ],
    stream: true,
    web_search_options: {
      search_type: 'auto'  // 自動分類
    }
  });

  for await (const chunk of response) {
    if (chunk.choices[0]?.delta?.content) {
      process.stdout.write(chunk.choices[0].delta.content);
    }
  }
  ```

<div id="manual-override">
  ### 手動オーバーライド
</div>

必要な検索タイプが分かっている場合は、引き続き手動で指定できます。

<Tabs>
  <Tab title="Pro Search を強制する">
    多段階のツール利用が必要だと分かっている場合に使用します。

    ```python theme={null}
    response = client.chat.completions.create(
        model="sonar-pro",
        messages=[{"role": "user", "content": "Your complex query"}],
        stream=True,
        web_search_options={
            "search_type": "pro"  # Pro Search を強制
        }
    )
    ```

    **手動で Pro を指定するユースケース:**

    * クエリに多段階の推論が必要だと分かっている場合
    * 自動分類では Fast と判定されたが、より深い分析が必要な場合
    * 最大限の能力を発揮させたい重要なクエリ
  </Tab>

  <Tab title="Fast Search を強制する">
    速度とコストを最適化したい場合に使用します。

    ```python theme={null}
    response = client.chat.completions.create(
        model="sonar-pro",
        messages=[{"role": "user", "content": "Your simple query"}],
        stream=True,
        web_search_options={
            "search_type": "fast"  # Fast Search を強制（省略時も fast がデフォルト）
        }
    )
    ```

    **手動で Fast を指定するユースケース:**

    * Pro Search では過剰となる単純なクエリ
    * コストを重視するアプリケーション
    * 応答速度が最優先となる場合
  </Tab>
</Tabs>

<div id="best-practices">
  ## ベストプラクティス
</div>

<Steps>
  <Step title="自動分類をデフォルトにする">
    ほとんどのアプリケーションでは、`search_type: "auto"` を使用して分類器に最適化を任せてください。

    ```python theme={null}
    web_search_options={"search_type": "auto"}
    ```

    これにより、コストを抑えつつ、各クエリに適したツールが選択されます。
  </Step>

  <Step title="分類パターンを監視する">
    どのクエリが Pro と Fast のどちらに分類されるかを追跡し、利用パターンを把握しましょう。

    * 常に Pro Search が使われるクエリを確認する
    * 適切な場合に Fast Search で処理されるようクエリを言い換える余地を探る
    * どのようなユーザーの質問が高度な機能を必要とするかを把握する

    これにより、アプリケーションのクエリ設計を最適化できます。
  </Step>

  <Step title="手動オーバーライドは戦略的に使う">
    分類器をオーバーライドするのは、次の場合に限定してください。

    * 特定の性能要件がある場合
    * Pro と Fast の結果をテスト・比較する場合
    * 複雑さのレベルが既知の機能を構築する場合

    **例:**

    ```python theme={null}
    # 複雑な分析であることが分かっている場合 - Pro を強制する
    if query_requires_calculations(user_query):
        search_type = "pro"
    else:
        search_type = "auto"
    ```
  </Step>

  <Step title="効果的にクエリを設計する">
    分類器が最適な判断を下せるようにクエリを構成しましょう。

    **あまり最適でない例:**
    「電気自動車について教えて」

    **より良い例:**
    「電気自動車の平均航続距離はどれくらいですか?」(Fast Search が適切)

    **または:**
    「Tesla Model 3、Chevrolet Bolt、Nissan Leaf について、減価償却、電気代、メンテナンス費用を含めた5年間の総保有コストを比較してください」(Pro Search が適切)

    明確で具体的なクエリほど、分類の精度が高まります。
  </Step>
</Steps>

<div id="classification-transparency">
  ## 分類の透明性
</div>

分類の判断結果は、レスポンスのメタデータで確認できます。

```json theme={null}
{
  "id": "12345",
  "model": "sonar-pro",
  "search_metadata": {
    "search_type_used": "pro",  // または "fast"
    "classification_reason": "Multi-part comparative analysis with calculations"
  },
  "usage": {
    "prompt_tokens": 25,
    "completion_tokens": 150,
    "total_tokens": 175
  }
}
```

<Info>
  この透明性により、クエリがそのように分類された理由を把握し、今後のクエリを最適化できます。
</Info>

  ## 各モードの使い分け
</div>

<CardGroup cols={3}>
  <Card title="Auto（推奨）" icon="wand">
    **適した用途:** ほとんどのアプリケーション

    最適化は分類器に任せます。クエリの複雑さに応じて、コストと処理能力のバランスを自動的に調整します。
  </Card>

  <Card title="手動 Pro" icon="brain">
    **適した用途:** 複雑だと分かっているタスク

    計算、複数ソースの統合、詳細な分析など、多段階のツール利用が必要だと分かっている場合に使用します。
  </Card>

  <Card title="手動 Fast" icon="bolt">
    **適した用途:** 単純な情報取得

    単純な事実や定義の取得、または単純なクエリで速度とコストを重視したい場合に使用します。
  </Card>
</CardGroup>

<div id="common-questions">
  ## よくある質問
</div>

<AccordionGroup>
  <Accordion title="分類器の精度はどの程度ですか?">
    分類器は数千種類のクエリパターンで学習しており、非常に高い精度を備えています。判断が曖昧な場合は Pro Search を選ぶ側に寄せているため、機能が損なわれることはありません。

    ただし、誤分類が繰り返し発生する場合は、次の対応を検討してください。

    * クエリをより具体的に言い換える
    * 該当するクエリ種別では手動オーバーライドを使用する
    * ユースケース固有の要件を見直す
  </Accordion>

  <Accordion title="どのモードが使われたか確認できますか?">
    はい。レスポンスには次の情報を示すメタデータが含まれます。

    * 使用された検索タイプ
    * その分類が選ばれた理由(auto 使用時)
    * 検索タイプ別のコスト内訳

    これにより、利用パターンを把握し、最適化できます。
  </Accordion>

  <Accordion title="自動分類によって遅延は増えますか?">
    いいえ。分類はクエリ処理が始まる前にミリ秒単位で完了するため、応答時間への実質的な影響はありません。分類器はリアルタイムの判断に最適化されています。
  </Accordion>

  <Accordion title="分類結果に納得できない場合はどうすればよいですか?">
    手動オーバーライドはいつでも使用できます。

    ```python theme={null}
    web_search_options={"search_type": "pro"}  # 希望するモードを強制する
    ```

    分類結果に常に納得できない場合は、次の点を検討してください。

    * クエリをより具体的にする
    * 該当するクエリ種別では手動オーバーライドを使用する
    * ユースケースとして常に Pro または Fast モードが必要かどうかを見直す
  </Accordion>
</AccordionGroup>
