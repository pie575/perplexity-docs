プロンプト作成の共通のベストプラクティスは [Agent API プロンプトガイド](/ja/docs/agent-api/prompt-guide) にまとめられており、Sonar にもそのまま当てはまります。具体的に書く、結果件数に上限を設ける、本文中で URL を求めない、few-shot の内容を避ける、フィルターは文章ではなくパラメータで指定する、といった点です。

このページでは、Sonar でのプロンプトの与え方に影響する唯一の構造的な違い、すなわちシステムプロンプトが検索に影響しないという点を説明します。

<div id="shape-search-through-the-user-message">
  ## ユーザーメッセージで検索を制御する
</div>

Sonar は回答を生成する前に Web 検索を実行しますが、その検索を左右するのはユーザーメッセージだけです。システムプロンプトは検索からは参照されず、検索結果がすでに揃った回答生成の段階で初めてモデルに渡されます。システムプロンプトはトーン、スタイル、根拠づけのルールに使い、ユーザーメッセージはモデルへの質問であると同時に検索のきっかけとなるものとして扱ってください。

実際上の影響として、ユーザーメッセージの言い回しは、どの情報源が取得されるかに直接影響します。具体的で説明的な質問は曖昧な質問よりも良い結果につながり、どれだけ システムプロンプト を作り込んでも曖昧なユーザーメッセージを補うことはできません。検索品質が重要であれば、まずはそこに注力してください。

**良い例**: 「FDA は過去1年間に医療機器における AI についてどのようなガイダンスを発行しましたか。また、それはどの機器カテゴリーを対象としていますか。」

**悪い例**: 「FDA の AI ルールについて教えて。」

<Warning>
  検索の指示をシステムプロンプトに書かないでください。「Wikipedia のみを検索して」や「最新の結果を探して」といった表現は効果がありません。ドメイン、鮮度、地域などの厳格な制約は、文章で表現しようとするのではなく、リクエストボディの専用[検索フィルターパラメータ](/ja/docs/sonar/filters)を使用してください。
</Warning>

  ```python Python theme={null}
  from perplexity import Perplexity

  client = Perplexity()

  completion = client.chat.completions.create(
      model="sonar",
      messages=[
          {"role": "user", "content": "Summarize the FDA's regulatory framework for Software as a Medical Device (SaMD), including the Pre-Cert program."}
      ],
      search_domain_filter=["fda.gov"],
      search_recency_filter="month"
  )

  print(completion.choices[0].message.content)
  ```

これは Agent API とは対照的です。Agent API では、`instructions` はエージェントループのターンごとに読み直され、ツール呼び出しと最終的な回答の両方を方向づけます。Sonar には `instructions` に相当するものはありません。システムメッセージは生成にのみ影響し、検索 (リトリーバル) に影響することはありません。

<div id="reduce-hallucinations">
  ## ハルシネーションを減らす
</div>

LLMは「役に立とうとする」ように調整されているため、検索結果が乏しかったり的外れだったりしても、その不足を指摘せずに回答してしまうことがあります。システムプロンプトは検索ステップそのものを左右するわけではありませんが、最終的な応答を書く際にモデルが検索結果をどう使うかには影響します。そのため、根拠に基づかせるためのルールを記述する場所として最適です。短い指示を2つ加えるだけで、こうしたエッジケースの大半に対処できます。

**「何も見つからなかった」と言ってよい、とモデルに明示しましょう。** システムプロンプトで明示的な逃げ道を与えておくと、モデルは学習データで不足を埋めようとせず、結果が不十分であることを認めやすくなります。

```text System Prompt theme={null}
提供された検索結果のみに基づいて回答してください。検索結果に答えが含まれていない場合は、推測せず、その旨を明示的に述べてください。
```

**惜しい結果 (ニアミス) の明示を求める。** 検索では、関連はしているものの一致しない結果 (年が異なる、子会社ではなく親会社、類似した別製品など) が返ることがあります。不一致がある場合は最初に伝えるようモデルに指示しておけば、こうした結果がそのまま答えとして提示されるのを防げます。

```text System Prompt theme={null}
検索結果が質問に関連していても一致しない場合（年が異なる、親会社である、類似製品であるなど）は、回答の前にその不一致を明示的に述べてください。
```

<div id="what-carries-over-from-the-agent-api-guide">
  ## Agent API ガイドから引き継がれる内容
</div>

中核となるプロンプト設計のルールは、変更なしにそのまま適用されます。

* ユーザーメッセージでは**具体的かつ説明的に記述する**。曖昧なクエリは散漫な結果を招きます。
* **結果件数に上限を設ける。** リストが必要な場合は、その件数を明示してください。
* **コンテンツを few-shot で与えない。** 書き上げた回答例を貼り付けると、検索ステップがその例のトピックに引きずられることがあります。**構造**の few-shot は問題ありません。出力形式を確実に固定したい場合は `response_format` を使ってください。
* **応答テキスト内での URL の提示を求めない。** Sonar はソースを常にトップレベルの `citations` および `search_results` フィールドで返します。そこから読み取ってください。
* **フィルターには文章ではなくパラメーターを使う。** 検索バックエンドが読み取るのはパラメーターであり、システムプロンプト は読み取りません。
