---

<div id="overview">
  ## 概要
</div>

`fetch_url` ツールは、Agent API リクエストの実行中に、指定した URL からコンテンツを取得して抽出します。モデルに参照させたいページ、記事、ドキュメント、レポートがアプリケーション側であらかじめ分かっている場合に使用します。

既知の URL からページ全体のコンテンツを取得したい場合は `fetch_url` を使用してください。モデルがまず関連するページを探す必要がある場合は [`web_search`](/ja/docs/agent-api/tools/web-search) を使用してください。

<CodeGroup>
  ```python Python theme={null}
  from perplexity import Perplexity

  client = Perplexity()

  response = client.responses.create(
      model="openai/gpt-5.6-sol",
      input="Explain Bayesian inference: how prior beliefs are updated to posterior beliefs given new evidence, with a concrete medical-test example.",
      tools=[
          {
              "type": "fetch_url"
          }
      ],
      instructions="Fetch the URL before summarizing it.",
  )

  print(response.output_text)
  ```

  ```typescript Typescript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  const response = await client.responses.create({
    model: 'openai/gpt-5.6-sol',
    input: 'Explain Bayesian inference: how prior beliefs are updated to posterior beliefs given new evidence, with a concrete medical-test example.',
    tools: [
      {
        type: 'fetch_url' as const,
      },
    ],
    instructions: 'Fetch the URL before summarizing it.',
  });

  console.log(response.output_text);
  ```

  ```bash cURL theme={null}
  curl https://api.perplexity.ai/v1/agent \
    -H "Authorization: Bearer $PERPLEXITY_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "model": "openai/gpt-5.6-sol",
      "input": "Explain Bayesian inference: how prior beliefs are updated to posterior beliefs given new evidence, with a concrete medical-test example.",
      "tools": [
        {
          "type": "fetch_url"
        }
      ],
      "instructions": "Fetch the URL before summarizing it."
    }' | jq
  ```

<div id="when-to-use">
  ## 使い分け
</div>

| `fetch_url` を使う場面  | `web_search` を使う場面 |
| ------------------ | ------------------ |
| すでに URL がわかっている    | 関連するページを探し出したい     |
| ページ本文をより網羅的に取得したい  | 複数の情報源から抜粋を集めたい    |
| 特定の記事やドキュメントを要約したい | 幅広いトピックを調査したい      |
| 既知の情報源をモデルに精査させたい  | 最新の情報源をモデルに探させたい   |

<Tip>
  多段階のリサーチでは `web_search` と `fetch_url` を組み合わせましょう。まず検索で関連ページを見つけ、続いて重要な URL を取得すれば、より充実したコンテキストが得られます。
</Tip>

  ## パラメータ

```json theme={null}
  ],
  "usage": {
    "input_tokens": 900,
    "output_tokens": 250,
    "total_tokens": 1150,
    "tool_calls_details": {
      "fetch_url": {
        "invocation": 1
      }
    }
  }
}
```

<div id="error-handling">
  ## エラー処理
</div>

`fetch_url` はベストエフォートで動作します。URL を完全に取得・抽出できなかった場合でも、API は取得できた内容を説明する最終アシスタントメッセージを含めて、完了状態の Agent API レスポンスを返すことがあります。`fetch_url_results.contents` の各項目を確認してください。成功した項目には抽出されたページテキストが含まれ、失敗した項目には要求した URL に対する明示的なマーカーが `snippet` に含まれます。

失敗マーカーは、HTTP クライアントエラー、robots ポリシーによるブロック、レート制限など、判明している理由を示します。上流の取得処理が要求した URL に対して項目を返さなかった場合、API は snippet に `no_result_returned` を含む項目を追加します。これらのマーカーはページテキストではなく、コンテンツを取得できなかったことを示すものとして扱ってください。

| ケース                  | レスポンスの挙動                                                                                                                            |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| **ペイウォールとログインウォール**  | `fetch_url` はアクセス制御を回避しません。該当するコンテンツ項目には、オリジンがリクエストを拒否したこと、および認証情報や GET 以外のメソッドが必要な可能性があることを示す失敗マーカーが含まれます。                         |
| **リダイレクト**           | リダイレクト先を取得できる場合、HTTP リダイレクトは追跡されます。返される `fetch_url_results` 項目の `url` フィールドには、最終的なリダイレクト先ではなく、要求した URL が入ります。                       |
| **HTML 以外のコンテンツ**    | `fetch_url` は、サーバーがその URL で返すテキストコンテンツをそのまま抽出します。PDF、バイナリのダウンロード、ボット対策のチャレンジページを返す URL では、抽出されるコンテンツが限定的になったり、無関係なものになったりする場合があります。 |
| **タイムアウトと到達不能な URL** | 該当するコンテンツ項目には、判明している理由を伴う失敗マーカーが含まれます。上流から結果が返されない場合、マーカーには `no_result_returned` が含まれます。                                            |

<div id="limits-quotas">
  ## 上限 / クォータ
</div>

`max_urls` を使うと、取得件数を制限して挙動を予測しやすく保てます。URL が少ないほどレイテンシは低くなる傾向があり、モデル の推論と最終回答に使えるコンテキストをより多く残せます。

| 上限                      | 値                                                                                                                          |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **ツール呼び出しあたりの最大 URL 数** | `max_urls` は 1 から 10 まで設定できます。                                                                                             |
| **サポートされる URL スキーム**    | `http://` または `https://` の絶対 URL を使用してください。その他のスキーム (`file:`、`data:`、`ftp:`、ブラウザ拡張機能の URL) はサポートされておらず、利用可能なコンテンツは取得できません。 |
| **コンテンツサイズ**            | 取得したコンテンツは モデル のコンテキスト用にスニペットとして抽出され、ページが長い場合は切り詰められることがあります。                                                            |

  ## 料金
</div>

`fetch_url` は **呼び出し 1,000 回あたり $0.50** で課金されます。モデルの token 使用量は、Agent API の token 料金に従って別途課金されます。

<Note>
  料金体系は他のツール呼び出しと同じで、ツールの呼び出し回数分に加えてモデルの token 分が課金されます。詳細は[料金](/ja/docs/getting-started/pricing)を参照してください。
</Note>
