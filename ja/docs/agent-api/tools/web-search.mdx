<div id="overview">
  ## 概要
</div>

`web_search` ツールを使うと、Agent API リクエストの処理中にモデルがウェブを検索できます。最新情報、直近のニュース、出典に基づいた調査のほか、モデルの学習データだけでは答えられない質問に活用してください。

このツールを有効にするには、`tools` 配列に追加します。呼び出すタイミングは、プロンプトと instructions の内容に基づいてモデルが判断します。

<CodeGroup>
  ```python Python theme={null}
  from perplexity import Perplexity

  client = Perplexity()

  response = client.responses.create(
      model="openai/gpt-5.6-sol",
      input="Explain the architecture of NVIDIA's CUDA programming model: threads, blocks, grids, warps, and memory hierarchy, and how they enable GPU parallelism.",
      tools=[
          {
              "type": "web_search",
              "search_context_size": "medium"
          }
      ],
      instructions="Search for current, source-grounded information before answering.",
  )

  print(response.output_text)
  ```

  ```typescript Typescript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  const response = await client.responses.create({
    model: 'openai/gpt-5.6-sol',
    input: 'Explain the architecture of NVIDIA\'s CUDA programming model: threads, blocks, grids, warps, and memory hierarchy, and how they enable GPU parallelism.',
    tools: [
      {
        type: 'web_search' as const,
        search_context_size: 'medium',
      },
    ],
    instructions: 'Search for current, source-grounded information before answering.',
  });

  console.log(response.output_text);
  ```

  ```bash cURL theme={null}
  curl https://api.perplexity.ai/v1/agent \
    -H "Authorization: Bearer $PERPLEXITY_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "model": "openai/gpt-5.6-sol",
      "input": "Explain the architecture of NVIDIA\u0027s CUDA programming model: threads, blocks, grids, warps, and memory hierarchy, and how they enable GPU parallelism.",
      "tools": [
        {
          "type": "web_search",
          "search_context_size": "medium"
        }
      ],
      "instructions": "Search for current, source-grounded information before answering."
    }' | jq
  ```
</CodeGroup>

<div id="using-recommended-token-budgets">
  ### 推奨トークン予算の利用
</div>

検索コンテキストのサイズ設定は、まず `search_context_size` に `low`、`medium`、`high` のいずれかを指定するところから始めてください。名前付きの各サイズは、推奨される `max_tokens` と `max_tokens_per_page` の予算の組み合わせに対応しており、ほとんどのアプリケーションではこれをデフォルトとして使うことを推奨します。

| `search_context_size` | `max_tokens` | `max_tokens_per_page` | 適した用途            |
| --------------------- | ------------ | --------------------- | ---------------- |
| `low`                 | 300          | 300                   | 単純な事実確認や軽量な検索    |
| `medium`              | 1,000        | 1,000                 | 一般的な調査や製品比較      |
| `high`                | 4,000        | 4,000                 | 出典を多く要する回答や複雑な調査 |

<Note>
  これらのトークン予算の対応関係は、Perplexity の現在の推奨デフォルト値を反映したものであり、最新の評価結果に基づいて設定を更新した際に変更される場合があります。名前付きサイズを指定すると、常にその時点の推奨予算が適用されます。
</Note>

<div id="number-of-results">
  ### 結果の件数
</div>

`max_results` を設定すると、`web_search` 呼び出し 1 回あたりにツールが収集する結果の件数を制御できます。これは呼び出し全体の合計値で、クエリが複数に再構成された場合は、この上限がクエリごとに分割されます (おおよそ `ceil(max_results / number_of_queries)`) 。省略した場合は既定の値が適用されます。

<CodeGroup>
  ```python Python theme={null}
  tools = [
      {
          "type": "web_search",
          "search_context_size": "low",
          "max_results": 20
      }
  ]
  ```

  ```typescript Typescript theme={null}
  const tools = [
    {
      type: 'web_search' as const,
      search_context_size: 'low',
      max_results: 20,
    },
  ];
  ```

  ```bash cURL theme={null}
  "tools": [
    {
      "type": "web_search",
      "search_context_size": "low",
      "max_results": 20
    }
  ]
  ```
</CodeGroup>

<Note>
  `max_results` に指定できる範囲は [API リファレンス](/ja/api-reference/agent-post) を参照してください。範囲内であっても、バックエンドが要求より少ない件数を返す場合があります。`search_context_size` と組み合わせて、幅 (結果の件数) と深さ (結果ごとに抽出されるコンテンツ量) のバランスを調整してください。
</Note>

<div id="filters">
  ## フィルター
</div>

フィルターを使用して、`web_search` が参照するソース、日付、位置情報のコンテキストを絞り込みます。

| フィルター                        | 型      | 説明                                                          |
| ---------------------------- | ------ | ----------------------------------------------------------- |
| `search_domain_filter`       | 文字列の配列 | 最大20件のドメインまたはURLを対象に含める、または除外します。除外する場合は先頭に `-` を付けます。      |
| `search_recency_filter`      | 文字列    | 結果を `"hour"`、`"day"`、`"week"`、`"month"`、`"year"` の範囲に制限します。 |
| `search_after_date_filter`   | 文字列    | MM/DD/YYYY 形式で指定した日付より後に公開された結果を含めます。                       |
| `search_before_date_filter`  | 文字列    | MM/DD/YYYY 形式で指定した日付より前に公開された結果を含めます。                       |
| `last_updated_after_filter`  | 文字列    | MM/DD/YYYY 形式で指定した日付より後に最終更新された結果を含めます。                     |
| `last_updated_before_filter` | 文字列    | MM/DD/YYYY 形式で指定した日付より前に最終更新された結果を含めます。                     |
| `user_location`              | オブジェクト | 国、地域、都市、緯度、経度に基づいて検索をパーソナライズします。                            |

<div id="domain-filter">
  ### ドメインフィルター
</div>

<Warning>
  `search_domain_filter` は、許可リストモードまたは拒否リストモードのどちらか一方で使用してください (両方の併用は不可) 。ドメインフィルターに指定できるドメインまたはURLは最大20件です。たとえば `["nasa.gov", "wikipedia.org"]` は指定したドメインのみを対象とし、`["-reddit.com", "-pinterest.com"]` は指定したドメインを除外します。
</Warning>

エントリーはドメイン単位 (例: `wikipedia.org`) で指定できるほか、より細かく制御したい場合はURL単位 (例: `https://en.wikipedia.org/wiki/Chess`) でも指定できます。

<div id="recency-filter">
  ### 最新性フィルター
</div>

`search_recency_filter` は、各値を相対的な期間に対応付けます。

| 値       | 期間                                   |
| ------- | ------------------------------------ |
| `hour`  | 過去1時間 — 速報やライブイベントなど、リアルタイムデータに使用します |
| `day`   | 過去24時間                               |
| `week`  | 過去7日間                                |
| `month` | 過去30日間                               |
| `year`  | 過去365日間                              |

期間を厳密に指定するには、`search_after_date_filter` / `search_before_date_filter` (公開日) または `last_updated_after_filter` / `last_updated_before_filter` (最終更新日) を使用します。日付フィルターの値は `MM/DD/YYYY` 形式で指定する必要があります (例: `"03/01/2026"`) 。

<div id="location-filter">
  ### 位置情報フィルター
</div>

`user_location` には、以下のフィールドを任意に組み合わせて指定できます。

* `country` — 2文字の [ISO 3166-1 alpha-2](https://en.wikipedia.org/wiki/ISO_3166-1_alpha-2) コード (例: `"US"`、`"FR"`) 。
* `region` — 地域名または州名 (例: `"California"`) 。
* `city` — 都市名 (例: `"San Francisco"`) 。
* `latitude` と `longitude` — 位置を正確に指定するための座標。

<Tip>
  `city` と `region` を指定すると、位置情報の精度が大幅に向上します。可能な限り `country` と併せて指定してください。
</Tip>

<Warning>
  `latitude` と `longitude` は `country` と併せて指定する必要があります。単独では指定できません。
</Warning>

<div id="filter-usage-cheatsheet">
  ### フィルター利用早見表
</div>

以下のスニペットは、いずれも `web_search` ツールオブジェクトにコピーして使用できます。`user_location` は `filters` と並列に指定し、その他の設定は `filters` の内部に指定します。

| フィルター     | 例                                                                                                                |
| --------- | ---------------------------------------------------------------------------------------------------------------- |
| ドメイン許可リスト | `filters: { search_domain_filter: ["docs.perplexity.ai", "developer.mozilla.org"] }`                             |

  料金体系は他のツール呼び出しと同様で、ツールの呼び出し回数分に加えてモデルのトークン分が課金されます。詳細は [料金](/ja/docs/getting-started/pricing) を参照してください。
</Note>

<div id="limits-quotas">
  ## 制限 / クォータ
</div>

`web_search` は Agent API リクエスト内で実行されるため、Agent API のリクエストレート制限が適用されます。現行のティア別 Agent API 制限については、[レート制限と利用ティア](/ja/docs/admin/rate-limits-usage-tiers#agent-api-rate-limits) を参照してください。

| 制限          | 適用対象                                                     | ガイダンス                                                                                                |
| ----------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| レート制限       | `web_search` を含む Agent API リクエスト                         | リクエストには Agent API のティア制限が適用されます。本番トラフィックではリトライとバックオフの処理を実装してください。                                    |
| ドメインエントリ数   | `search_domain_filter`                                   | 1 リクエストあたり最大 20 件のドメインまたは URL。[フィルター](#filters) の警告に記載のとおり、許可リストまたは拒否リストのいずれかのモードを使用してください。          |
| 検索コンテキストの予算 | `search_context_size`、`max_tokens`、`max_tokens_per_page` | `search_context_size` の preset を使うとコンテキストが自動的に管理されます。コストやレイテンシをより厳密に制御したい場合は、明示的なトークン上限を指定してください。 |
| ツール呼び出しの課金  | `web_search` の呼び出し                                       | 各検索の呼び出しは、モデルのトークン使用量とは別に、ツール呼び出しの使用量および料金に計上されます。                                                |
