<div id="overview">
  ## 概要
</div>

preset は、特定のユースケース向けに最適化された事前構成済みのセットアップです。各 preset には、model、検索設定、推論ステップ、system prompt、利用可能なツールがまとめられています。

<Info>
  Agent API の preset は、ティアベースの名称になりました: fast-search → fast、pro-search → low、deep-research → medium、advanced-deep-research → high、ultra → xhigh。
</Info>

preset には次の2通りの使い方があります。

* **動的 preset (推奨)&#x20;**&#x20;— preset を名前で呼び出す (例: `preset="low"`) と、Perplexity が最適化した最新の構成が適用されます。評価で改善が確認され次第、Perplexity が基盤となる構成を更新するため、コードを変更しなくてもアプリケーションはその改善を自動的に取り込みます。
* **固定した preset／構成** — preset の現在の値 (model、ツール、system prompt、パラメータ) をリクエストにコピーし、`preset` パラメータを省略します。これにより、その preset が現時点で使用している構成をそのまま固定できます。今後の preset の更新の影響をアプリケーションが受けないようにしたい場合や、基盤の model とツール構成を厳密に固定したい場合に利用してください。

両方を併用することもできます。ほとんどの環境では動的 preset を呼び出し、安定性が求められる箇所では固定した構成を使う、といった使い分けが可能です。

<Note>
  preset は Perplexity が管理します。
  独自の構成を保存してバージョン管理したい場合 — たとえば preset の[現在の値](#current-preset-values)を出発点にする場合 — は、preset の組織所有版に相当する[profile](/ja/docs/agent-api/profiles)を使用してください。
  1つのリクエストで `preset` と `profile` の両方を指定することはできません。
</Note>

動的 preset は、共有されるプロンプトのプレフィックス (system prompt とツール定義) に対して安定した `prompt_cache_key` を自動的に使用します。これにより、同じ preset を使用する独立したリクエスト間でプロンプトキャッシュが再利用されやすくなります。このキーを自分で設定する必要はありません。リクエストレベルで `prompt_cache_key` を明示的に指定した場合は、preset のデフォルトより優先されます。

<Info>
  preset は、そのユースケースに最適化された妥当なデフォルト値を提供します。追加のパラメータを渡せば、任意のパラメータ (`model`、`max_steps`、`tools` など) を上書きできます。コード例については[preset のカスタマイズ](#customizing-presets)を参照してください。
</Info>

<Note>
  **明示的なバージョン管理はありません。** preset は特定のバージョンに固定されていません。preset を名前で呼び出すと、常に Perplexity が推奨する最新の構成に解決されます。大幅に優れた構成をリリースする際は、改善された preset として提供されますが、名前は変わりません。特定の構成に固定する必要がある場合は、[現在の preset の値](#current-preset-values)をインラインでコピーして、固定した構成を作成してください。
</Note>

<div id="what-changes-when-a-preset-is-updated">
  ### presetが更新されたときに変わること
</div>

Perplexityがpresetを更新する際は、変更を同じ想定プロファイルの範囲内に収めることを目指しています。これにより、アプリケーション側では予期せぬ影響を受けることなく品質の向上が得られます。

* **コストプロファイル** — presetの更新は同じコスト帯を維持することを目標とします。基盤となるmodelが変わることはありますが、リクエストあたりのコストが既存の水準に近くなるよう調整されます。
* **レイテンシプロファイル** — presetの更新は同じレイテンシ帯を維持することを目標とします。ステップ数、検索設定、ツール予算も現在の値に近い水準で維持されます。
* **品質** — presetの更新が最適化の対象とするのがこの観点です。評価で有意な改善が確認された場合に、新しい構成がリリースされます。

これらの更新に追従せず、特定の構成に固定したい場合は、[現在のpreset値](#current-preset-values)をインラインでコピーして、固定した構成を作成してください。

<div id="choosing-a-preset">
  ## presetの選択
</div>

各presetは、リサーチの深さ、ソースの網羅性、レイテンシのバランスが異なります。以下の表を参考に、クエリに合ったものを選んでください。

| Preset            | 得意なこと                                                          | 使いどころ                                                                                                             |
| ----------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **fast**          | 単一の事実の確認、用語の定義、インライン引用付きの簡潔な要約。                                | 答えが1つの事実または短い要約で済み、レイテンシが最優先で、多段階のリサーチが不要な場合。                                                                     |
| **low**           | 日常的な調査、最新情報とインライン引用を伴う軽めの多段階検索。                                | クエリに最新情報が必要で、軽めのリサーチとツール利用を要する場合。                                                                                 |
| **medium**        | 多段階のブラウジングと多数のソースにわたる幅広い集約。ソースに基づく主張にはインライン引用が付きます。            | 複数回の検索と推論を重ね、多数のソースにまたがる根拠をつなぎ合わせる必要がある場合。                                                                        |
| **high**          | 専門家レベルの推論と網羅的なソースカバレッジ。ソースに基づく主張にはインライン引用が付きます。                | 最も広いカバレッジと最も長い推論が必要な場合 — レイテンシよりも網羅性が重視される、機関レベルの分析。                                                              |
| **xhigh**         | オープンエンドなエージェント的作業: sandboxでのコード実行、長いツール利用ループの維持、多数のソースからの一括収集。 | タスクが単一の質問ではなくオープンエンドな場合 — コードを実行したり、多数回のツール利用を統括したり、段階的に結果を積み上げたりするケース。最も高性能なpresetであり、速度よりも処理能力が重要な場面に最適です。      |
| **wide-research** | 幅広い探索と項目ごとのリサーチによる、大規模で根拠に裏付けられたコレクションの構築。                     | 条件に合う項目を多数特定し、各結果をソースで裏付け、後続処理向けに構造化された出力を生成する必要がある場合。[Wide Researchガイド](/ja/docs/agent-api/wide-research)を参照してください。 |

<Info>
  各presetの現在の設定内容 — model、ツール、パラメータ、system prompt — の全体は、以下の[現在のpreset値](#current-preset-values)セクションに記載しています。
</Info>

<div id="using-a-preset">
  ## preset の使用
</div>

`preset` パラメータに名前を指定して preset を呼び出します。基盤となる設定は Perplexity が管理するため、コードを変更することなく今後の改善を自動的に取り込めます。

<CodeGroup>
  ```python Python theme={null}
  from perplexity import Perplexity

  client = Perplexity()

  response = client.responses.create(
      preset="low",
      input="Summarize the core findings of the original 'Attention Is All You Need' transformer paper and explain why it changed NLP.",
  )

  print(response.output_text)
  ```

  ```typescript Typescript theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  const response = await client.responses.create({
      preset: "low",
      input: "Summarize the core findings of the original 'Attention Is All You Need' transformer paper and explain why it changed NLP.",
  });

  console.log(response.output_text);
  ```

  ```bash cURL theme={null}
  curl https://api.perplexity.ai/v1/agent \
    -H "Authorization: Bearer $PERPLEXITY_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "preset": "low",
      "input": "Summarize the core findings of the Attention Is All You Need transformer paper and explain why it changed NLP."
    }'
  ```
</CodeGroup>

`preset="low"` の部分は、[上記の表](#choosing-a-preset)にある任意の preset 名に置き換えてください。preset のデフォルト値を上書きする方法については、[preset のカスタマイズ](#customizing-presets)を参照してください。

<div id="customizing-presets">
  ## presetのカスタマイズ
</div>

presetは適切なデフォルト値を提供します。presetと一緒に渡したフィールドは、そのデフォルト値を上書きします。設定しなかった項目には、presetのデフォルト値がそのまま適用されます。

例外は `tools` のみで、セット全体が置き換わるのではなく、ツール単位でマージされます。特定のツールを1つ指定した場合、上書きされるのはそのツールのオプションだけで、presetの他のツールは有効なまま残ります。

<Note>
  preset適用時に検索の深さを調整するには、`web_search` に `max_tokens` と `max_tokens_per_page` を設定します。[検索の設定](/ja/docs/agent-api/tools/web-search#configuring-search)を参照してください。
</Note>

<Tabs>
  <Tab title="Python SDK">
    ```python theme={null}
    from perplexity import Perplexity

    client = Perplexity()

    # preset の他の設定はそのまま使い、model だけを上書きする
    response = client.responses.create(
        preset="low",
        model="anthropic/claude-sonnet-4-6",  # preset が使用する model を上書き
        max_output_tokens=16384,
        input="Summarize the core findings of the original 'Attention Is All You Need' transformer paper and explain why it changed NLP.",
    )

    # より深く推論させるために max_steps を上書きする
    response = client.responses.create(
        preset="low",
        input="What is serverless cold start latency, what causes it, and what are the standard mitigations (warm pools, provisioned concurrency)?",
        max_steps=8,  # preset のステップ数の上限を上書き
    )

    # 推論の深さ（reasoning effort）を上書きする
    response = client.responses.create(
        preset="low",
        input="Compare the trade-offs between optimistic and pessimistic concurrency control in distributed databases.",
        reasoning={"effort": "high"},  # minimal | low | medium | high | xhigh | max
    )

    # preset の他のデフォルト値は維持しつつ、web_search を特定のドメインに限定する
    response = client.responses.create(
        preset="low",
        input="Explain the FDA's accelerated approval pathway under 21 CFR 314 Subpart H: eligibility criteria, surrogate endpoints, and confirmatory trial requirements.",
        tools=[{
            "type": "web_search",
            "filters": {
                "search_domain_filter": ["clinicaltrials.gov", "fda.gov"],  # 特定のドメインに限定
            },
        }],
    )

    # 使用量を厳密に制御したい場合は、token の上限を明示的に指定する
    response = client.responses.create(
        preset="low",
        input="Explain the FDA's accelerated approval pathway under 21 CFR 314 Subpart H: eligibility criteria, surrogate endpoints, and confirmatory trial requirements.",
        tools=[{
            "type": "web_search",
            "max_tokens": 6000,
            "max_tokens_per_page": 1200,
            "filters": {
                "search_domain_filter": ["clinicaltrials.gov", "fda.gov"],
            },
        }],
    )
    ```
  </Tab>

<div id="current-preset-values">
  ## 現在の preset の値
</div>

現在の preset の値とは、各 preset の背後にある具体的な model、システムプロンプト、ツール、パラメータを、公開 API のフィールドとして表したものです。これらの値をリクエストにコピーし、`preset` パラメータを省略すれば、固定構成 (現時点の preset の挙動を再現するピン留めされた設定) を作成できます。

以下の各 preset には、それ単体で完結する現在の値をすべて記載しています。ブロックを 1 つコピーするだけで、その preset の挙動を固定できます。

<Note>
  固定構成はピン留めされているため、今後の preset の改善は **反映されません**。自動的に更新を取り込みたい場合は、preset を名前で呼び出してください ([動的な preset](#using-a-preset)) 。
</Note>

<Note>
  cURL タブには、SDK タブよりも完全な構成が表示される場合があります。一部のパラメータは SDK でまだ公開されていないためです。
</Note>

以下の固定例では、リクエストを送信する前に現在の UTC 日付をローカルで計算しています。API が `{{current_date}}` を置換するのは preset のデフォルトの指示内のみで、リクエストで指定した `instructions` 内のプレースホルダーはそのまま送信されます。

<AccordionGroup>
  <Accordion title="fast — 現在のプリセット値">
    レイテンシを最小限に抑えた事実確認向けの高速検索。検索に基づく記述にはインライン引用が付きます。

    * **モデル:** `openai/gpt-5.6-luna`
    * **プロンプトキャッシュキー:** `fast`
    * **最大ステップ数:** 1
    * **推論強度:** `minimal`
    * **サービスティア:** `priority`
    * **最大出力トークン数:** 8192
    * **ツール:** `web_search`
    * **検索結果:** `max_results: 10` (cURLリクエスト)
    * **システムプロンプト:** 以下にインラインで記載

    <CodeGroup>
      ```python Python theme={null}
      from perplexity import Perplexity

      client = Perplexity()

      response = client.responses.create(
          model="openai/gpt-5.6-luna",
          prompt_cache_key="fast",
          input="Explain the 2023 Nobel Prize in Physics: who won, what attosecond physics is, and why their work matters for studying electron dynamics.",
          max_steps=1,
          max_output_tokens=8192,
          reasoning={"effort": "minimal"},
          instructions=r"""
      ## Role
      <role>
      You are Perplexity, a helpful search assistant built by Perplexity AI. Your task is to deliver accurate, well-cited answers by leveraging web search results. You prioritize speed and precision, providing direct answers that respect the user's time while maintaining factual accuracy.

      Given a user's query, generate an expert, useful, and contextually relevant response. Answer only the current query using its provided search results and relevant conversation history. Do not repeat information from previous answers.
      </role>

      ## Tools Workflow
      <tools_workflow>
      You must call the web search tool before answering. Do not rely on internal knowledge when search results can provide current, verifiable information.

      - Decompose complex queries into discrete, parallel search calls for accuracy
      - Use short, keyword-based queries (2-5 words optimal, 8 words maximum)
      - Do not generate redundant or overlapping queries
      - Match the language of the user's query
      - If search results are empty or unhelpful, answer using existing knowledge and state this limitation

      <tool_call_limit>Make at most one tool call before concluding.</tool_call_limit>
      </tools_workflow>

      ## Citation Instructions
      <citations>
      Your response must include citations. Add a citation to every sentence that includes information derived from search results.

      <formatting>
      - Use brackets with the source index immediately after the relevant statement: [1], [2], etc.
      - Do not leave a space between the last word and the citation
      - When multiple sources support a claim, use separate brackets: [1][2][3]
      - Cite up to three relevant sources per sentence, choosing the most pertinent results
      - Never use formats with spaces, commas, or dashes inside brackets
      - Citations must appear inline, never in a separate References section
      </formatting>

      <examples>
      Correct: "The Eiffel Tower is located in Paris[1][2]."
      Incorrect: "The Eiffel Tower is located in Paris [1, 2]."
      Incorrect: "The Eiffel Tower is located in Paris[1-2]."
      </examples>

      If you did not perform a search, do not include citations.
      </citations>

      ## Response Guidelines
      <response_guidelines>

      <structure>
      - Begin with a direct 1-2 sentence answer to the core question
      - Never start with a header or meta-commentary about your process
      - Use Level 2 headers (##) for sections only when organizing substantial content
      - Use bolded text (**text**) sparingly for emphasis on key terms
      - Keep responses concise; users should not need to scroll extensively
      </structure>

      <formatting>
      - Lists: Use flat lists only (no nesting). Numbers for sequential items, bullets (-) otherwise. One item per line with no indentation.
      - Tables: Use markdown tables for comparisons. Ensure headers are properly defined. Include citations within cells directly after relevant data.
      - Code: Use markdown code blocks with language identifiers for syntax highlighting.
      - Math: Use LaTeX with \( \) for inline and \[ \] for block formulas. Never use $ or unicode for math.
      - Quotes: Use markdown blockquotes for relevant supporting quotes.
      </formatting>

      <tone>
      - Write with precision and clarity using plain language
      - Use active voice and vary sentence structure naturally
      - Avoid hedging phrases ("It is important to...", "It is subjective...")
      - Do not use first-person pronouns or self-referential phrases
      - Ensure smooth transitions between sentences
      </tone>
      ```
