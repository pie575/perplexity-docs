<div id="streaming-responses">
  ## ストリーミングレスポンス
</div>

ストリーミングを使うと、レスポンス全体が完成するのを待たずに、Perplexity API が生成した部分的なレスポンスを逐次受け取れます。リアルタイム性が求められるユーザー体験、長文のレスポンス、対話型アプリケーションで特に有用です。

<Info>
  ストリーミングは、Agent API で利用できるすべてのモデルでサポートされています。
</Info>

ストリーミングを有効にするには、レスポンス作成時に `stream=True` (Python) または `stream: true` (TypeScript) を指定します。

<CodeGroup>
  ```python Python SDK theme={null}
  from perplexity import Perplexity

  client = Perplexity()

  # ストリーミングレスポンスを作成
  stream = client.responses.create(
      preset="fast",
      input="Explain what a model card is in the context of large language models: the typical sections (intended use, training data, limitations, evaluation).",
      stream=True
  )

  # ストリーミングレスポンスを処理
  for event in stream:
      if event.type == "response.output_text.delta":
          print(event.delta, end="")
      elif event.type == "response.completed":
          print(f"\n\nCompleted: {event.response.usage}")
  ```

  ```typescript TypeScript SDK theme={null}
  import Perplexity from '@perplexity-ai/perplexity_ai';

  const client = new Perplexity();

  // ストリーミングレスポンスを作成
  const stream = await client.responses.create({
    preset: "fast",
    input: "Explain what a model card is in the context of large language models: the typical sections (intended use, training data, limitations, evaluation).",
    stream: true
  });

  // ストリーミングレスポンスを処理
  for await (const chunk of stream) {
    if (chunk.type === "response.output_text.delta") {
      process.stdout.write((chunk as any).delta);
    }
  }
  ```

  ```bash cURL theme={null}
  curl -X POST "https://api.perplexity.ai/v1/agent" \
    -H "Authorization: Bearer $PERPLEXITY_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "preset": "fast",
      "input": "Explain what a model card is in the context of large language models: the typical sections (intended use, training data, limitations, evaluation).",
      "stream": true
    }'
  ```
</CodeGroup>

  import time

  def get_output_text(response) -> str:
      return "".join(
          content.text
          for item in response.output or []
          if getattr(item, "type", None) == "message"
          for content in getattr(item, "content", None) or []
          if getattr(content, "type", None) == "output_text"
      )


  response = client.responses.create(
      model="openai/gpt-5.6-sol",
      input="Produce a competitive landscape report for the EV charging market.",
      tools=[{"type": "web_search"}, {"type": "sandbox"}],
      background=True,
  )

  while response.status in ("queued", "in_progress"):
      time.sleep(2)
      response = client.responses.retrieve(response.id)

  print(get_output_text(response))

バックグラウンド実行は永続化されるため、リアルタイムにストリーミングしつつ、切断後に再接続することもできます。`GET /v1/agent/{id}?stream=true&starting_after=N` をリクエストすると、シーケンス番号 `N` の次のイベントから再開できます。再接続が有効なのはレスポンスの再接続ウィンドウ内のみで、このウィンドウを過ぎるとエンドポイントは `400` を返すため、最終スナップショットは通常の `GET /v1/agent/{id}` で取得することになります。詳しくは [Agent API リファレンス](/ja/api-reference/agent-post)を参照してください。

<div id="structured-outputs">
  ## 構造化出力
</div>

構造化出力を使うと、Perplexity のモデルが返すレスポンスの形式を指定でき、一貫性のある機械可読なデータが得られるため、手動でパースすることなくアプリケーションへ直接組み込めます。

現在は **JSON Schema** による構造化出力をサポートしています。構造化出力を有効にするには、リクエストに `response_format` フィールドを追加します。

```json theme={null}
{
  "response_format": {
    "type": "json_schema",
    "json_schema": {
      "name": "your_schema_name",
      "schema": { /* あなたのJSONスキーマオブジェクト */ }
    }
  }
}
```

`name` フィールドは必須で、1〜64文字の英数字である必要があります。スキーマは有効な JSON スキーマオブジェクトである必要があります。出力が `max_tokens` を超えない限り、LLM の応答は指定した形式に一致します。

スキーマの `required` 配列に列挙したプロパティは、出力でも必須となります。`required` に含めなかった宣言済みプロパティはすべて任意扱いとなり、JSON の `null` になる場合があります。`required` を省略した場合、または空の場合は、宣言したすべてのプロパティが任意となります。この挙動は、`/v1/agent` とその互換エイリアスである `/v1/responses` のいずれにおいても、ストリーミングリクエストと非ストリーミングリクエストで同じです。

<Tip>
  **スキーマ準拠性の向上**: プロンプト内で出力形式のヒントを LLM に与えると、構造化形式への準拠度が向上します。たとえば、「以下の構造を持つ JSON オブジェクトとしてデータを返してください...」や「情報を抽出し、スキーマで指定された形式で整形してください。」といった表現を含めてください。
</Tip>

<Info>
  新しい JSON スキーマを使用した最初のリクエストでは、最初の token が返るまでに遅延が生じます。通常、新しいスキーマの準備には10〜30秒かかり、タイムアウトエラーになる場合もあります。スキーマの準備が完了した後は、以降のリクエストでこのような遅延は発生しません。
</Info>
